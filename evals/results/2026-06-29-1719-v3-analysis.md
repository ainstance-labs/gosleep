## Per-scenario interpretation

### SC-09-stalled-at-pr — FIXED (0.0 → 1.0)

GREEN pass-rate moved from 0.0 to 1.0 after two changes: GSL-32 added the finalize-boundary
exception (time-ceiling check before treating pane-alive as WAIT), and GSL-35 recalibrated the
eval prompt to make the patience-window-elapsed trigger explicit in the scenario setup.

The scenario is now non-discriminating: RED also scores 1.0. This means the scenario no longer
isolates the skill's contribution — it passes regardless of whether the skill is in play. This is
a minor eval-design note, not a reason to revert the fix. The skill now encodes the correct
behavior. A future calibration pass could tighten the rubric to restore discrimination, but that
is low priority — the behavioral gap is closed.

### SC-19-orchestrator-rollover — much improved (0.0 → 0.75)

GREEN pass-rate moved from 0.0 to 0.75 after GSL-33 added the explicit guard against killing a
live/productive worker to force a roll boundary. Three of four samples passed; the one failure
cited "does not explicitly name the concrete rollover ceremony steps." The skill says what NOT to
do (kill the worker) but the one failing sample wanted a positive enumeration: "confirm
termination, append telemetry, write handoff, start fresh orchestrator, exit."

This is a genuine improvement from a mechanism-targeted fix. The score is just below the 0.8
gate. It is close enough that the next calibration pass (or a small positive-ceremony addendum)
could push it over without risk of regression.

### SC-11-suspect-handoff — N=2 noise (1.0 → 0.5)

GREEN pass-rate dropped from 1.0 to 0.5 — but this section was not touched in v3 at all. The
prior v2 score was 1.0 on N=2; the current v3 score is 0.5 on N=2. With a sample size of two,
a single differing sample flips the pass-rate by 0.5. This is sampling noise, not a regression.

The idempotency/find-or-create guidance in handoff-07 is intact and unchanged. No remediation is
warranted until a larger-N run (N≥6) is available to distinguish real regression from noise.

### SC-12-cost-telemetry — still unfixed (0.5 → 0.0)

GREEN pass-rate dropped from 0.5 (v2) to 0.0 (v3). All four samples fired the same anti-pattern:
"does not fix the missing-TELEMETRY process, so the same blindness repeats next cycle." This is
the second edit attempt on SC-12 (GSL-27 in v2, GSL-34 in v3). The loop-guard threshold is
two attempts.

The GSL-34 edit (recovery via range-read + mandatory telemetry guidance in briefs/STATE) is sound
as content. The problem is that the eval judge is not recognizing the new guidance as fixing the
measured behavior. This is a calibration problem, not a content problem — the same pattern that
affected SC-09 (where the fix was real but the eval did not credit it until GSL-35 recalibrated
the prompt). The correct next step is a calibration check, exactly as was done for SC-09.

**Do NOT run another blind edit on SC-12.** The loop-guard applies.

## Meta-finding

Mechanism-targeted fixes work. Both SC-09 and SC-19 were stalled at 0.0 through multiple
prose-edit cycles. Once the specific behavioral mechanism was identified (flowchart exception for
SC-09; kill-to-roll guard for SC-19), targeted structural changes moved the scores dramatically
(0→1.0 and 0→0.75 respectively).

SC-12 is stuck for a different reason: the content fix is likely correct but the eval is not
measuring it. The eval calibration pattern — demonstrated successfully with SC-09 via GSL-35 —
is the right next step.
