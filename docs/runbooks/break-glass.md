# Runbook — break-glass: полный контроль над флотом с телефона (Tailscale + mosh + tmux)

**Что это.** Последняя линия. Remote Control умирает примерно через 10 минут после того, как
телефон ушёл в офлайн; ntfy односторонний и ответить в него нельзя. Этот путь — единственный,
который даёт **полный** контроль: attach к живой панели, чтение вывода, kill и restart любого
воркера. Он же — единственный, которым никто не пользуется до той ночи, когда он понадобился.

Задача **GSL-107** (требование R6.4, приёмка **F6-S4**).

## 1. Сначала — preflight

```bash
tools/breakglass/bg-preflight.sh          # человекочитаемый вердикт
tools/breakglass/bg-preflight.sh --json   # то же одним JSON-объектом
```

Коды выхода: **0** — цепь цела, **1** — degraded (звено, которое должен поправить человек),
**2** — Tailscale отсутствует, чинить нечего, цепь надо строить.

Скрипт **ничего не устанавливает, не поднимает VPN и не включает sshd**. Установка системного
VPN и открытие SSH-демона на машине владельца — решения владельца, принятые на трезвую голову;
скрипт, который делал бы это сам, был бы не помощником, а инцидентом.

**Состояние на 2026-07-20:** `unavailable`. Дословно:

```
MISSING   tailscale CLI not found — no tailnet, so no path to this machine from a phone
DEGRADED  no SSH transport could be CONFIRMED (Tailscale SSH unknown, Remote Login off) — mosh may have nothing to bootstrap over
DEGRADED  mosh-server not installed — plain `ssh` still works over the tailnet, but every network change drops the session
OK        tmux server up with 9 session(s) — there is a live target for `tmux attach`

VERDICT: unavailable  (ok=1 degraded=2 missing=1)
```

Из пяти звеньев цепи готово **одно** — то, к которому подключаются. Всё остальное надо ставить.

## 2. Tailscale ⏳

### 2.1 Почему именно он

Цель — доступ к машине **без единого входящего порта на роутере**. Tailscale строит
E2E-шифрованную WireGuard-сеть, в которой оба устройства инициируют **исходящие** соединения к
координатору и дальше говорят напрямую. Пробрасывать порты на роутере не нужно; при симметричном
NAT трафик пойдёт через DERP-релей — медленнее, но всё ещё без проброса.

Отвергнуто (PRD): web-tmux обёртки (VibeTunnel, ttyd) — они перекладывают auth и TLS на нас.

### 2.2 На маке

```bash
brew install --cask tailscale     # либо Mac App Store, либо standalone-пакет с tailscale.com
tailscale up
```

**Гоча App Store-сборки.** В ней CLI лежит **внутри бандла**, а не на `PATH`:

```bash
/Applications/Tailscale.app/Contents/MacOS/Tailscale status
# удобнее один раз:
sudo ln -s /Applications/Tailscale.app/Contents/MacOS/Tailscale /usr/local/bin/tailscale
```

`bg-preflight.sh` ищет оба варианта и, найдя бандловый, скажет об этом отдельной строкой.

### 2.3 На телефоне

Приложение Tailscale из App Store, вход **тем же аккаунтом** — иначе устройства окажутся в
разных tailnet'ах и не увидят друг друга. После входа мак виден в списке машин.

### 2.4 Проверка «без входящих портов»

```bash
tailscale status                    # телефон должен быть в списке peer'ов
tailscale ping <имя-телефона>       # покажет direct или via DERP — оба годятся
tailscale netcheck                  # тип NAT; проброс НЕ требуется ни при каком
lsof -nP -iTCP -sTCP:LISTEN         # что реально слушает на машине (см. §3.2)
```

Требование выполнено, если на роутере **нет** ни одного проброшенного порта — и при этом
`tailscale status` видит телефон.

## 3. SSH-транспорт: звено, о котором забывают

**mosh не самостоятельный транспорт.** Он запускает `mosh-server` на той стороне **через SSH**,
читает из его вывода ключ и UDP-порт, и только потом переходит на собственный UDP-канал. Без
SSH-терминатора здоровый tailnet ведёт **в никуда**: `bg-preflight.sh` проверяет это отдельно и
не выдаёт `ready`, даже когда Tailscale зелёный, а mosh установлен.

Терминаторов два, и достаточно **одного**.

### 3.1 Путь A — Tailscale SSH (рекомендуемый)

```bash
tailscale up --ssh
```

SSH терминирует сам `tailscaled` **внутри** tailnet. На машине **не открывается ни один порт**:
единственный путь, выполняющий «без входящих портов» и по букве, и по духу. Доступ отзывается из
админки tailnet, а не перевыпуском ключей.

⏳ **Не проверено здесь:** связка `mosh` поверх Tailscale SSH. Механизм должен работать (mosh
поднимает `mosh-server` через любой SSH), но живого подтверждения на этой машине нет. Если mosh
поверх пути A не пойдёт — путь B остаётся рабочим запасным.

### 3.2 Путь B — системный Remote Login (запасной, с ценой)

*System Settings → General → Sharing → Remote Login.*

**Цена, которую надо назвать вслух.** Включённый Remote Login открывает `:22` на **всех**
интерфейсах машины — включая Wi-Fi в кафе и любую другую недоверенную сеть. Приёмка F6-S4 ещё
выполняется буквой (роутер не проброшен), но «машина без открытых портов» перестаёт быть правдой.
`bg-preflight.sh` в этом случае намеренно ставит `degraded` и печатает предупреждение — состояние
рабочее, но требующее внимания человека.

Ограничить демон одним tailscale-интерфейсом (`/etc/ssh/sshd_config`, нужен sudo и рестарт):

```
ListenAddress 100.x.y.z        # tailscale-адрес машины из `tailscale status`
```

**На 2026-07-20 Remote Login выключен**, `:22` закрыт (проверено `nc`). Это не недосмотр, а
хорошее состояние по умолчанию — но означает, что прямо сейчас пути B тоже нет.

> **Развилка зафиксирована как решение** — `q-2026-07-20-004` (DECISION, GSL-107). Дефолт: путь A
> основной, путь B запасной с предупреждением. Если владелец решит иначе — правится этот раздел.

## 4. mosh и tmux ✅

### 4.1 Зачем mosh, а не голый ssh

```bash
brew install mosh                       # на маке; на телефоне — клиент с поддержкой mosh
mosh <tailscale-имя-мака> -- tmux attach -t 12 -r -f ignore-size
```

SSH-сессия умирает при каждой смене сети: Wi-Fi → LTE, выход из зоны, засыпание телефона. Ночью
это происходит постоянно. mosh переживает смену IP и сна: сессия продолжается там, где была.
Без mosh путь работает, но каждый переход по сети означает заново открывать и заново
искать нужную панель — с телефона это дороже, чем звучит.

Клиент на телефоне — **Blink Shell** (в PRD назван он) или любой другой с поддержкой mosh.
`bg-preflight.sh` эту часть проверить не может и честно это пишет: клиент на телефоне
верифицирует только владелец.

### 4.2 ⚠️ Attach с телефона искажает флот на десктопе — если не сказать иначе

Проверено на `tmux 3.6a` этой машины:

```
$ tmux show-options -g window-size
window-size latest
```

`latest` означает: **размер окна задаёт последний активный клиент**. Приаттачившись с телефона,
вы становитесь этим клиентом — и tmux пережмёт окна под экран телефона **для всех**, включая
десктопные панели. Утром флот встречает владельца покорёженной раскладкой.

**Поэтому телефонный attach всегда такой:**

```bash
tmux attach -t 12 -r -f ignore-size
```

| Флаг | Что делает | Почему на телефоне |
|---|---|---|
| `-r` | read-only attach | Экранная клавиатура и промах пальцем не наберут ничего в панель живого воркера |
| `-f ignore-size` | «the client does not affect the size of other clients» (man 3.6a) | Десктопная раскладка переживает ночной attach |

Оба флага приняты `tmux 3.6a` (проверено; контроль — заведомо неверный `-Z` даёт `unknown flag`).

Когда нужно **действительно вмешаться**, `-r` снимается осознанно — отдельным attach без него,
а не «на всякий случай заранее».

### 4.3 Найти нужную панель

```bash
tmux list-sessions
tmux list-panes -a -F '#{session_name}:#{window_index}.#{pane_index}  id=#{pane_id}  #{pane_current_command}'
```

Живой пример с этой машины:

```
12:0.0  id=%348  2.1.215
12:0.1  id=%423  2.1.215
12:0.2  id=%425  2.1.215
12:0.3  id=%424  2.1.215
```

Сессия оркестратора — та, где несколько панелей с `claude`-процессом.

### 4.4 ⚠️⚠️ Инвариант kill-pane — только по явному `%id`

**HARD-урок 2026-07-07: `tmux kill-pane -a` однажды убил живой флот.** Ниже — механизм,
воспроизведённый экспериментально 2026-07-20 в изолированной тестовой сессии.

**Опасность №1 — `-a` убивает соседей.** Man `tmux 3.6a` дословно: *«The -a option kills all but
the pane given with -t»*. Проверено: `kill-pane -a -t %427` убил `%429` и `%430` — **все панели
того же окна**, кроме указанной. Панели соседнего окна уцелели, то есть радиус — **окно**.

И вот почему это смертельно именно здесь: **флот gosleep живёт панелями в одном окне** (см.
`12:0.0`…`12:0.3` выше). Для этого проекта `kill-pane -a` практически означает «убить всех
воркеров, кроме себя». А **без** `-t` «указанная панель» — это *текущая*, значение которой с
телефона угадать невозможно.

**Опасность №2 — позиционные адреса перенумеровываются.** Тот же эксперимент:

```
ДО                              ПОСЛЕ смерти %428
positional=…:0.0  stable=%427   positional=…:0.0  stable=%427
positional=…:0.1  stable=%428   positional=…:0.1  stable=%429   ← был 0.2
positional=…:0.2  stable=%429   positional=…:0.2  stable=%430   ← был 0.3
positional=…:0.3  stable=%430
```

`%429` **сменил** позиционный адрес с `0.2` на `0.1`, не сменив `%id`. С телефона между «прочитал
список» и «набрал команду» проходят минуты, за которые воркер вполне может закончиться сам.
Набранный по памяти `kill-pane -t 12:0.2` убьёт **не ту панель, которую вы читали**.

**Правило, следующее из обоих фактов:**

```bash
tmux kill-pane -t %425          # ✅ явный стабильный id, полученный ПРЯМО СЕЙЧАС
tmux kill-pane -t 12:0.2        # ❌ позиционный адрес — мог сдвинуться
tmux kill-pane -a               # ⛔ НИКОГДА. Убьёт всех соседей по окну = весь флот
```

Перед каждым kill — перечитать `list-panes` и взять `%id` из свежего вывода.

### 4.5 Restart воркера

Панель — это процесс. Убили — перезапускать через оркестратора (он знает брифы и модели), а не
руками с телефона. Если оркестратор мёртв, честнее дождаться утра, чем поднимать воркера вслепую
из кровати.

## 5. Порядок в аварию

1. `tools/breakglass/bg-preflight.sh` — если он давно не `ready`, аварии здесь и закончится.
2. Tailscale на телефоне — мак в списке машин.
3. `mosh <мак> -- tmux attach -t <сессия> -r -f ignore-size` — read-only, размеры целы.
4. Прочитать. Понять, **что** сломалось.
5. Только если нужно вмешаться: attach без `-r`, `kill-pane -t %id` со свежим id.
6. Detach: `Ctrl-b d`.

## 6. Деинсталляция и отзыв устройства ⏳

**Отозвать телефон** (потеря/продажа) — из админки tailnet, `login.tailscale.com` → Machines →
устройство → *Remove* либо *Disable*. Отзыв действует со стороны координатора: доступ пропадает,
даже если на самом телефоне ничего не сделано.

**На маке:**

```bash
tailscale logout                  # выйти из tailnet, оставив софт
brew uninstall --cask tailscale   # либо удалить .app
```

Плюс — вернуть `:22`, если включали путь B: выключить Remote Login в Sharing.

**Гигиена:** ключи устройств в Tailscale по умолчанию истекают. Мак, который «просто перестал
отвечать» через несколько месяцев, — скорее всего истёкший ключ, а не поломка. Если эта машина
должна быть доступна всегда — отключить key expiry для неё в админке, осознанно.

## 7. Честное ограничение: это аварийный путь, а не повседневный

Терминал на телефоне плох для чтения. Панель на 80 колонок на экране в 390 CSS-пикселей — это
переносы, промахи пальцем и потерянный контекст. Читать статус флота с телефона нужно
**дашбордом** (`docs/runbooks/phone-dashboard.md`), а разговаривать с оркестратором — через
Remote Control (`docs/runbooks/remote-control.md`). Break-glass берут тогда, когда оба
предыдущих пути мертвы и нужен именно **полный** контроль.

**Первый прогон нельзя делать в аварию.** Путь состоит из пяти звеньев, четыре из которых на этой
машине сейчас отсутствуют, а разделы §2, §3 и §6 ещё не подтверждены живым прогоном. Ставить
Tailscale, поднимать транспорт и впервые пробовать attach следует **днём, на здоровую голову**,
и после этого `bg-preflight.sh` должен показывать `ready` — иначе в 4 утра выяснится, что
инструкция была планом, а не проверенным путём.
