# Runbook — мотор регулярности (дебаунс + тик) (операции для владельца)

**Что это.** Два механических (без LLM) исполнителя всего, что система обязана делать регулярно:
пересобирать лабораторию, применять просроченные дефолты DECISION, опрашивать трекер, проверять
вооружённость. До эпика GSL-176 у этих обязанностей исполнителя не было — их вспоминал (или
забывал) живой агент. Теперь:

| Слой | Кто | Когда работает | Что делает |
|---|---|---|---|
| Дебаунс | `tools/lab/chronicler-debounce.sh` через PostToolUse-хук | пока жива хоть одна агентская сессия | через 90 c тишины после записи в `docs/lab/` — один прогон летописца |
| Тик | `tools/lab/tick.sh` на внешнем носителе (launchd / Desktop-задача / вручную) | всегда, пока машина не спит | poll-fill → apply-due → летописец (если несвежо) → armed-check → строка в леджер |

Эпик GSL-176, аудит 2026-07-24 (эпик 3 плана улучшений, находки 1, 7, 11, 12, 49, 53, 57, 89).

**Компоненты:**

| Файл | Что делает |
|---|---|
| `tools/lab/chronicler-debounce.sh` | движок дебаунса: матч по tool_input, waiter под локом, прогон летописца |
| `tools/hooks/chronicler-debounce-hook.sh` | fail-open шим — единственное, на что указывает settings.json (всегда exit 0) |
| `tools/lab/tick.sh` | сам тик: идемпотентный, 0 LLM, одна строка леджера на запуск |
| `tools/lab/gate.sh` | штатный гейт смены одной командой (smoke+hooks-verify+tsc+летописец С опросом) |
| `tools/lab/preflight/` | plist-шаблон launchd + arm/disarm скрипты ВЛАДЕЛЬЦА для preflight-ночи |
| `tools/lab/tick-preflight-report.sh` | утренняя таблица «носитель — тикал ли ночью — что после пробуждения» |

**Леджер (единый для обоих слоёв):** `docs/lab/supervision/tick-ledger.jsonl` — трекаемый,
append-only. Строки `{"mode":"debounce",...}` — прогоны дебаунса; `{"mode":"tick","carrier":...}`
— тики с указанием носителя. `result` у тика: `ok` / `idle` (работы не было — и это видно) /
`skipped-lock-held` / `error:<шаг>`.

---

## Что тикает и с какой частотой

- **Дебаунс:** trailing-edge 90 c тишины (`GOSLEEP_DEBOUNCE_QUIET`), потолок 600 c при
  непрерывных записях (`GOSLEEP_DEBOUNCE_MAX_WAIT`). Срабатывает на запись в `docs/lab/` или
  вызов lab-писателей (`lab-emit`/`lab-log`/`lab-write`); упоминание пути в ВЫВОДЕ команды —
  не триггер.
- **Тик:** интервал задаёт носитель (plist — 300 c). Порог свежести `GOSLEEP_TICK_FRESH=240` —
  сознательно меньше интервала: тихой ночью каждый тик пересобирает, и `generated_at` не стареет
  дальше одного интервала (критерий приёмки эпика). Днём при живом дебаунсе тик почти всегда
  `idle` — ноль сети, ноль пересборок, ноль токенов.
- **Порядок шагов тика:** сначала poll-fill (внешняя правда), потом apply-due (просроченные
  дефолты), потом летописец — иначе дашборд показывал бы применённое решение открытым. Летописец
  внутри тика идёт с `--no-poll` по композиции (шаг 1 уже опросил) — это НЕ оффлайн-режим.

## Как проверить, что мотор вооружён

```bash
# 1. Дебаунс подключён в settings.json (должно быть ровно 2):
jq '[.hooks.PostToolUse[].hooks[].command] | map(select(test("chronicler-debounce"))) | length' .claude/settings.json

# 2. Дебаунс живой (строки mode=debounce за последний час):
tail -20 docs/lab/supervision/tick-ledger.jsonl | jq -r 'select(.mode=="debounce") | .ts'

# 3. Носитель тика тикает (строки mode=tick, штамп carrier):
bash tools/lab/tick-preflight-report.sh --hours 6

# 4. launchd-носитель установлен (выполняет ВЛАДЕЛЕЦ):
launchctl list | grep com.gosleep.tick    # есть строка = вооружён

# 5. Полная самопроверка контракта (545 проверок на момент эпика, среди них дебаунс и тик):
bash tools/lab/gate.sh
```

`armed-check` (механический вердикт вооружённости всего контура) строит GSL-211 в эпике сторожа;
до его появления тик честно пишет `"armed_check":"absent"` — это не ошибка, это правда.

## Как выключить

```bash
# Дебаунс, мягко (текущая сессия и все будущие, пока переменная в окружении):
export GOSLEEP_DEBOUNCE_DISABLE=1

# Дебаунс, жёстко: убрать обе записи chronicler-debounce-hook.sh из .claude/settings.json
# (файл перечитывается на лету; проверить jq-командой из пункта 1 — должно стать 0).

# Тик на launchd (ВЛАДЕЛЕЦ):
bash tools/lab/preflight/preflight-disarm.sh

# Тик на Desktop-задаче: удалить/поставить на паузу задачу в самом приложении Claude Desktop.
```

Выключение мотора не ломает ничего: поверхности просто стареют и ЧЕСТНО говорят об этом
(staleness — продукт, F4-S3). Обратное вооружение — `preflight-arm.sh` (владелец) и возврат
записей в settings.json.

## Preflight-ночь (развилка владельца, вопрос 5)

Решения d-2026-07-28-003/005: преflight ОБОИХ носителей на одной реальной ночи; дату называет
владелец; основным станет тот, который фактически тикал; launchd остаётся страховкой.

```bash
# Вечером (одно действие владельца):
bash tools/lab/preflight/preflight-arm.sh
#   + создать Desktop-задачу по инструкции, которую скрипт напечатает
#   + обычный ночной caffeinate (arm сознательно не трогает питание)

# Утром:
bash tools/lab/tick-preflight-report.sh
```

Ограничение платформы (из аудита): launchd `StartInterval` не тикает во сне машины; Desktop-задача
требует запущенного приложения, и каждая её сработка — маленькая агентская сессия (токены на
обёртку). Ни один носитель не переживает выключение машины.

## Диагностика

| Симптом | Куда смотреть |
|---|---|
| дашборд стареет при живой сессии | `.artifacts/lab/chronicler-debounce.err`; `jq` из пункта 1; `GOSLEEP_DEBOUNCE_DISABLE` в окружении? |
| дашборд стареет ночью | `tick-preflight-report.sh --hours 12`: тикал ли носитель; `launchctl list`; `.artifacts/lab/launchd-tick.err` |
| просроченная DECISION не применена | `bash tools/lab/lab-emit.sh apply-due --dry-run` (что видит исполнитель); строки `applied` в леджере |
| тик всегда idle | это норма при живом дебаунсе; `--force` для принудительного полного прохода |
| два тика одновременно | не бывает: mkdir-лок, второй пишет `skipped-lock-held`; лок старше 30 мин крадётся |

## Границы (что мотор сознательно НЕ делает)

- Не запускает агентских сессий и не тратит токенов (C1: 0 LLM на всём пути тика и дебаунса).
- Не трогает launchctl/caffeinate/pmset сам — установка носителей только руками владельца.
- Не будит, если работы нет (idle-гейт, находка 89) — и оставляет след, что не будил.
- Не заменяет сторожа (GSL-178): тик — исполнитель регулярного, не супервизор живых агентов.
