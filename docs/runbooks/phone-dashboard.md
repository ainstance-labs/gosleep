# Runbook — читать дашборд с телефона

> Закрывает **F5-S4c**, который Фаза 5 честно записала как **опровергнутый**.
> Задача **GSL-108**, цикл 66. Всё ниже измерено 2026-07-20 против `ainstance-labs/gosleep`
> (приватный репо, аутентифицированно), а не выведено из документации.

## 1. Что открывать

**Одна ссылка, в закладки:**

```
https://github.com/ainstance-labs/gosleep/tree/main/docs/lab/mobile
```

Это **папка**, а не файл. GitHub сам рендерит `README.md` открытой папки — утренний экран
оказывается на телефоне сразу, без поиска файла по имени.

Пока Фаза 6 не смёржена, тот же путь на ветке:
`…/tree/GSL-102-mobile/docs/lab/mobile`.

Работает и мобильное приложение GitHub, и мобильный Safari/Chrome с залогиненным аккаунтом.
Приватность репозитория ничего не меняет — рендер происходит **после** проверки доступа.

## 2. Почему это работает, а HTML — нет

Фаза 5 измерила верно: `raw.githubusercontent.com` отдаёт `text/plain` + `nosniff`, Pages на
приватном репо — 404. Но **вывод** из этих измерений был шире самих измерений:
«GitHub — транспорт байтов, а не просмотрщик». Это неверно, и именно это на фазу закрыло решение.

Перемер (та же машина, тот же приватный репо):

| Что запрашиваем | Что GitHub возвращает |
|---|---|
| `.md` через Contents API (`Accept: html`) | `<article class="markdown-body">` — **отрендерено на сервере** |
| `.html` через тот же API | `<pre class="plain">&lt;!doctype html&gt;` — **экранировано**, показан исходник |
| `README.md` папки | тоже рендерится (`GET /readme/<dir>`) |
| папка **без** `README.md` | `404` — негативный контроль: 200 выше не является дефолтом |

`nosniff` никогда не управлял Markdown, потому что Markdown браузеру на интерпретацию **не отдают**:
GitHub рендерит его в HTML у себя на серверах и присылает результат. Препятствием был не приватный
репозиторий, а **расширение файла**.

Практическое следствие: **не ссылайтесь с телефона на `.html`** — откроется экранированный исходник.
Семь экранов `docs/lab/site/*.html` остаются десктопной поверхностью (`file://` из клона).

## 3. Что на странице

Проекция тех же семи экранов, собранная из того же `render_bundle.json`:
свежесть → **что ждёт вас** → флот → доставка → задачи → расходы и runway → активность → куда дальше.
Порядок не косметический: в 07:00 первый вопрос — «висит ли что-то на мне», и он идёт первым.

Страница **регенерируется, а не редактируется** (C8). Правка руками живёт до следующего прохода
летописца и всё это время является ложью с проставленным временем.

## 4. Свойство, ради которого стоило городить

Семь HTML-экранов требуют node. Эта страница — **нет**: её собирает Python из бандла, который Python
уже записал. Если node отвалится, дашборд замирает под красным баннером, **а телефонная страница
останется свежей** — и честно скажет, что HTML рядом с ней устарел.

То есть единственная поверхность, до которой вы дотягиваетесь из кровати, не исчезает именно в ту
ночь, когда ломается сборка. Это проверено в smoke: node срезается из `PATH`, HTML деградирует
(`ui.reason=no-node`), страница пишется и несёт время текущего прохода.

## 5. Что осталось на владельца (2 минуты)

Механика проверена машинно до последнего звена; **последнее звено — ваши глаза**:

1. Откройте ссылку из §1 с телефона.
2. Убедитесь, что видите отрендеренный текст, а не исходник и не 404.
3. Запишите результат **включая отрицательный** — как это сделала Фаза 5.

Если не отрендерится — это опровержение, и его надо зафиксировать фактом, а не переформулировать
критерий. Известные заранее причины отказа: не залогинен в GitHub на телефоне; нет доступа к
приватному репо у этого аккаунта; открыт файл, а не папка.

## 6. Что именно проверено руками, а что нет

| | |
|---|---|
| ✅ `.md` рендерится на приватном репо | измерено, Contents API, `markdown-body` |
| ✅ `.html` экранируется | измерено, тот же API, `<pre class="plain">` |
| ✅ README папки рендерится | измерено, + негативный контроль (папка без README → 404) |
| ✅ страница проходит настоящий рендерер GitHub | `POST /markdown` → `text/html`, 7 секций, таблица, ссылки |
| ✅ читается на ширине телефона | скриншот 390px по вернувшемуся от GitHub HTML |
| ✅ переживает отсутствие node | smoke, `PATH` без node |
| ⏳ **видно на реальном телефоне владельца** | **не проверено — §5** |

Строка `⏳` не должна превратиться в `✅` без прогона. Именно подгонка формулировки под критерий —
то, чего Фаза 5 не сделала, и поэтому её отчёту можно верить.
