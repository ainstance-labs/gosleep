## 1. Зачем эта спека и чем она отличается от предыдущей попытки

Дизайн-проход GSL-109 владельца **не устроил**: через полтора часа после его закрытия
UI повторно назван «полный AI-slop» (`docs/handoff/ORCHESTRATION-STATE.md`, запись 2026-07-20 ~16:50).
Важно понять, почему, иначе вторая попытка повторит первую.

**GSL-109 навёл порядок внутри существующего визуального языка**: свёл 18 ad-hoc размеров шрифта
к 7 ступеням, 12 ad-hoc отступов к шагу 4px, нормализовал неон тёмной темы, нашёл два настоящих
дефекта (каскад `.stale.stale` и `unknown`, красившийся чужим тоном). Это была *санация*, и как
санация она удалась — те находки в силе и здесь не отменяются.

Но язык остался прежним, а претензия была именно к нему. Что видно на скриншотах
`docs/dev_history/assets/GSL-109/after-*.jpeg` — то есть на состоянии, которое владелец и назвал
слопом:

| Признак | Как выглядит сейчас |
|---|---|
| Интерфейс говорит эссе | На главном экране, до всяких данных: «*Cannot say. No stopping clock is counting — but 1 of them could not be read (budget). That is a hole in the evidence, not a green light: "nothing is wrong" and "I cannot see whether anything is wrong" are different sentences.*» — пять строк прозы с курсивом |
| Самый громкий элемент — не данные | Блок runway: пурпурная заливка во всю ширину, пунктирная рамка, значение кеглем 40px |
| Цвет живёт в тексте значений | `clear` зелёным, `unknown` пурпурным курсивом — там, где должно быть нейтральное число |
| Рамка вокруг каждой мелочи | Шесть карточек-часов, у каждой своя рамка, внутри ещё подписи капсом |
| Навигация — таблетки | Семь pill-кнопок с рамками, активная инвертирована |
| Бейджи кричат в каждой строке | 200 строк timeline, в каждой цветная пилюля `hook:PostToolUse` — притом что это метаданные, а не статус |

**Отсюда три правила, которым подчинена вся остальная спека.**

1. **Инструмент, а не презентация.** Носитель смысла — плотная таблица и число. Хром (шапка,
   навигация, баннеры, футер) тише данных всегда, без исключений.
2. **Цвет получает только то, что несёт оценку.** Метаданные — нейтральные. Это правило само по
   себе убирает большую часть шума (раздел 7.2).
3. **Громкость пропорциональна тревоге.** Экран, которому нечего сообщить, молчит; заливку и
   утолщённую грань зарабатывает только `dead`/`incident`. Принцип унаследован от GSL-109 —
   он был верным, менялась только его реализация.

Основания не вкусовые: запреты на «толстые насыщенные блоки», «пунктирные линии как шум» и
«текст носит текстовые токены, а не цвет серии» — прямые пункты каталога анти-паттернов скилла
`dataviz` (`references/anti-patterns.md`, разделы «Marks & chrome» и «Color & encoding»).

### 1.1 Что нельзя трогать вообще

- **Схема `gosleep.lab.render/7`** — не меняется. Объявлена в `tools/lab/chronicler.py:2106`,
  `tools/lab/ui/src/types.ts:512`, `tools/lab/ui/src/render.tsx:26`, гейт `tools/lab/smoke.sh:428`.
  Редизайн — слой представления и только.
- **Видимые тексты.** Порядка 23 smoke-ассертов грепают прозу внутри `.html`, плюс ассерты на
  подписи (`smoke.sh:790/791` проверяют присутствие строки `cycles run (ledger running total)` и
  отсутствие `cycles ledgered`). **Новый видимый текст не добавляется, существующий не
  переписывается** — включая заголовки, подписи полей и прозу карточек. Перелицовка не имеет
  права разговаривать.
- **Данные, пороги, формулы.** Ни одно число не пересчитывается.

## 2. Как устроен технический слой (чтобы спека ложилась на него, а не мимо)

Факты проверены грепом по коду, не по документации.

- **Стилей-файла нет.** Весь CSS — один TypeScript-литерал: `export const CSS` в
  `tools/lab/ui/src/theme.ts` (строки 48–391). В файле **запрещены backticks** где угодно,
  включая комментарии (`theme.ts:10-13`).
- **Сборка не минифицирует.** `build.mjs` не выставляет `minify` ни на одном проходе; esbuild
  возвращает литерал байт в байт (в собранной странице `<style>` — 22 978 байт, 344 строки,
  комментарии на месте). Значит грепы по CSS (раздел 10.4) работают по тому, что написано в
  `theme.ts`, буквально.
- **Токены уже существуют** (`theme.ts:49-65`): поверхности `--bg --card --sunken`, чернила
  `--fg --dim --line --line-strong`, статусы `--ok --warn --dead --unk --accent` (+ `-soft`),
  типографика `--t-xs … --t-hero`, отступы `--s1 … --s7`, радиусы `--r1 … --r3`, шрифты
  `--mono --sans`.
  **Решение: имена токенов сохраняем, значения переопределяем.** Меньше диффа — меньше шансов
  задеть ассерт. Недостающие роли добавляются новыми именами (раздел 4.4).
- **Вебшрифты запрещены жёстко.** `smoke.sh:364` бракует любой `https?://(cdn|fonts|unpkg|cdnjs)`.
  Mona Sans (Mastra) и Circular (Supabase) недоступны — типографика строится на системном стеке
  (раздел 3.1). Ограничение принято как есть, обхода не ищем.
- **Брейкпоинт ровно один:** `@media (max-width:26rem)` (`theme.ts:383-390`) — это 416px, то есть
  390px под него попадает.
- **Тёмная тема живёт только на `prefers-color-scheme`** — переключателя нет.
  Практическое следствие уже случилось: в `docs/dev_history/assets/GSL-109/` лист
  `after-desktop-dark.jpeg` **вышел светлым** (а `after-390-dark.jpeg` — тёмным), то есть тёмную
  тему на десктопе никто не видел. Раздел 4.6 добавляет `:root[data-theme="dark"]`, чтобы её
  можно было форсировать при съёмке. Это чистый CSS, нового видимого текста и переключателя в
  интерфейсе не появляется.
- **Layout как такового нет:** `main{display:block}`, каждый экран — плоская вертикальная стопка.

## 3. Типографика

### 3.1 Стеки

Сохраняются существующие (`theme.ts:63-64`), менять нечего и не на что:

```
--mono: ui-monospace,SFMono-Regular,Menlo,Consolas,monospace
--sans: -apple-system,BlinkMacSystemFont,"Segoe UI",system-ui,sans-serif
```

**Моноширинный обязателен для:** любых чисел в таблицах, ключей (`GSL-110`, `#124`, `q-2026-07-20-004`),
sha, идентификаторов сессий и акторов (`ecab62c2`, `a6e197f577a9b8c59`), путей и glob'ов,
временных меток, имён моделей, JSON, shell-команд, значений бейджей.
**Пропорциональный — для** заголовков, прозы, подписей полей, тем задач и заголовков артефактов.

Правило разрешения спора: если значение можно сравнить с другим таким же по вертикали —
моноширинный.

### 3.2 Шкала

Имена ступеней существующие, значения новые. Правая колонка — что было в GSL-109.

| Токен | rem | px | Назначение | Было |
|---|---|---|---|---|
| `--t-xs` | 0.6875 | **11** | Заголовки колонок, микро-метки, подписи KPI, бейджи | 11 |
| `--t-sm` | 0.75 | **12** | Вторичные подписи, футер, `<small>`, провенанс | 13 |
| `--t-md` | 0.8125 | **13** | **База интерфейса и таблиц** | 15 |
| `--t-base` | 0.875 | **14** | Проза карточек, тело `<p>` | 16 |
| `--t-lg` | 1 | **16** | `h2` — заголовок секции | 20 |
| `--t-xl` | 1.25 | **20** | `h1` — имя экрана | 28 |
| `--t-hero` | 1.75 | **28** | Значения KPI, значение runway, `.wk-age` | 40 |

**Почему всё уехало вниз.** Верхняя ступень эталонов — 28px (Mastra `text-header-xl`), у Supabase
заголовок дашборда `text-2xl` = 24px. Сорокапиксельного кегля нет ни у одного из них. База 13px —
`text-ui-smd` Mastra, ступень, заведённая специально под плотный интерфейс.

`body` получает `--t-md`. Прозаические абзацы внутри карточек — `--t-base`.

### 3.3 Веса

**Максимальный вес во всей системе — 500. Значений 600 и 700 не существует.**

Это измеренное свойство обоих эталонов: у Supabase доказуемо — `strong { @apply font-medium }`,
жирного начертания нет как класса; в разобранных компонентах Mastra выше `font-medium` не
встречается. Иерархия строится размером и цветом, а не жиром.

| Роль | Вес |
|---|---|
| Основной текст, ячейки таблиц, проза | 400 |
| `h1`, `h2`, заголовки колонок `th`, значения KPI, бейджи, активный пункт навигации, `<b>` | 500 |

⚠️ `<b>` остаётся элементом `<b>` — `smoke.sh:2058` требует, чтобы `#sh-data-age` был именно `<b>`.
Меняется только его вес: `b{font-weight:500}`.

### 3.4 Интерлиньяж и трекинг

Интерлиньяж падает с ростом кегля (приём Mastra, у них задан процентами 160% → 129%):

| Ступень | line-height |
|---|---|
| `--t-xs`, `--t-sm` | 1.5 |
| `--t-md`, `--t-base` | 1.5 |
| `--t-lg` (h2) | 1.4 |
| `--t-xl` (h1) | 1.3 |
| `--t-hero` | 1.15 |

Трекинг: `0` везде, **кроме** заголовков колонок и микро-меток капсом — там `0.06em`
(без разрядки капс слипается). Оба эталона делают ровно это: Supabase `tracking-wider` на
`heading-meta`, Mastra `tracking-wide` на `th`.

### 3.5 Цифры

- В таблицах, KPI-значениях и любых колонках чисел: `font-variant-numeric: tabular-nums`.
- Крупное одиночное число (KPI, `--t-hero`) — **тоже** `tabular-nums`, вопреки общему совету
  `dataviz` про пропорциональные цифры на hero. Причина конкретная: `tickAges()` перерисовывает
  `.age`/`.wk-age` **раз в секунду** (`client.ts:134-154`), и пропорциональные цифры дают
  дёрганье ширины на каждом тике. Стабильность важнее плотности набора.

## 4. Палитра

### 4.1 Как она построена

Не подбором, а по формуле — способом эталонов (Supabase выводит всю тему из ~8 скаляров через
`calc()` в OKLCH; Mastra объявляет рампы в OKLCH). Здесь то же самое, но результат материализован
в hex, потому что страницы собираются в статику и impl-воркеру нужны значения, а не формулы,
которые можно истолковать по-своему.

Параметры: нейтраль — тон 264 с хромой **0.004** (почти ахроматична; у Mastra ровно 0, у
Supabase 0…0.005 — лёгкий холодный уклон нужен, чтобы нейтраль не спорила с тёплыми статусами).
Статусные — общая хрома **0.14** (константа `--expressive-chroma` Supabase), тон фиксирован,
светлота у каждого своя (раздел 4.3).

Ступени светлоты подобраны **не на глаз**: каждая прогнана через `contrast()` и поднята до
порога. Так, `muted` пришлось увести с L 0.58 на 0.52 (не проходил 4.5:1 на приподнятых
поверхностях), а `border-strong` — с 0.72 на 0.60 в light и с 0.46 на 0.56 в dark (не проходил
3:1 по WCAG 1.4.11).

### 4.2 Поверхности, чернила, границы

**Индекс поверхности означает роль, а не светлоту.** В светлой теме «выше» не может быть
светлее белого, поэтому приподнятые уровни там темнее. Так же поступает Mastra (их светлая шкала
намеренно немонотонна).

|---|---|---|---|---|
| Плоскость страницы | `--bg` | `#f5f7f9` | `#0d0e10` | `body` |
| Панель / карточка / таблица | `--card` | `#ffffff` | `#151618` | `.card`, `.kpi`, `.wk`, тело таблицы |
| Второй уровень | `--sunken` | `#f2f3f6` | `#1d1e20` | `th`, hover строки, `.filters`, code-блок |

### 4.3 Статусные роли

Тон один и тот же в обеих темах — меняется светлота. `fg` — цвет текста и значения,
`bg` — подложка бейджа, `border` — его граница.

| Роль | Light fg / bg / border | Dark fg / bg / border |
|---|---|---|
| `--ok` | `#007835` / `#e6fae9` / `#b1dfb9` | `#7cdd93` / `#1e2d21` / `#295233` |
| `--warn` | `#976500` / `#fff1df` / `#eccb9e` | `#ffc673` / `#322717` / `#5e4216` |
| `--dead` | `#902828` / `#ffefee` / `#fcc0ba` | `#f07f77` / `#372321` / `#683834` |
| `--info` | `#0068a5` / `#eaf5ff` / `#abd7fd` | `#71bfff` / `#1c2b37` / `#244b6b` |
| `--unk` | `#8e4d9d` / `#fceeff` / `#e6c3ee` | `#d58fe5` / `#302432` / `#583b5f` |
| `--neutral` *(новый)* | `#68696b` / `#f2f3f6` / `#cfd1d4` | `#97989b` / `#28292b` / `#46484a` |

Существующие `-soft` токены становятся колонкой `bg`; добавляется колонка `border`
(`--ok-border` и т.д.).

**`--info` намеренно совпадает с `--accent`** (один и тот же `#0068a5` / `#71bfff`). Это не
коллизия, а решение: синий в этом интерфейсе значит «информационное, не оценка» — и у ссылки, и
у информационного бейджа. Два разных синих рядом читались бы как разница, которой нет.

**`--unk` остаётся отдельной ролью вне оси green–amber–red.** Это завоёванное знание GSL-109:
«ничего не идёт к нулю» и «я не могу прочитать часы» — разные утверждения, и красить их одинаково
было дефектом. Не отменять.

### 4.5 Контраст — измеренные значения

Прогон: `contrast(a,b)` из `scripts/validate_palette.js` скилла `dataviz` (WCAG-формула).
Порог для текста — 4.5:1, для функциональных границ — 3:1 (WCAG 1.4.11).

**Все роли проходят в обеих темах. Ни одного FAIL.**

Текст на каждом уровне поверхности:

| | light: canvas / card / sunken / raised | dark: canvas / card / sunken / raised |
|---|---|---|
| `--fg` | 16.06 · 17.25 · 15.55 · 14.47 | 17.21 · 16.13 · 14.87 · 12.97 |

### 4.5.1 Что валидатор сказал про статусные цвета, и почему это не дефект

Категориальный прогон статусного набора даёт:

| Проверка | Light | Dark |
|---|---|---|
| Contrast vs surface | PASS (все ≥ 3:1) | PASS |
| **Normal-vision floor** | **PASS — 15.3** (порог 15) | **PASS — 15.4** |
| CVD separation | FAIL — ΔE 2.9 (protan) | FAIL — ΔE 3.7 (protan) |
| Lightness band | PASS | FAIL (L 0.72–0.86) |

**CVD-провал ожидаем и неустраним для светофорной семантики.** Гейт написан для палитры *серий*,
о чём валидатор сам пишет в scope-строке: «for a lone status/text color check WCAG text contrast».
Красный и зелёный при дейтеранопии сближаются по построению — это физика, а не свойство подбора.

Утверждение проверено контролем, а не заявлено: **референсная статусная палитра самого скилла**
(`references/palette.md`) на том же гейте даёт CVD ΔE **4.1**, normal-vision **13.6** — и вдобавок
проваливает контраст (`#fab219` = 1.79:1, `#ec835a` = 2.57:1). Наша проходит контраст с запасом
(минимум 4.52:1) и **проходит normal-vision floor**, который у референсной провален.

Normal-vision floor — единственный hard gate из перечисленных — закрыт намеренным приёмом:
**светлоты статусов разведены** (light 0.44…0.545, dark 0.72…0.86). При равной светлоте статусы
различались бы только тоном, и замер это показал: до разведения ΔE был 1.3, после — 2.9, а
normal-vision поднялся с 10.8 до 15.3. Даже там, где тон потерян, остаётся разница яркости.

FAIL по Lightness band в тёмной теме — тоже by design: полоса 0.48–0.67 рассчитана для *заливок*
на тёмном фоне, а у нас это **текст**, которому нужен контраст 4.5:1, поэтому он светлее полосы.

**Обязательное следствие (не рекомендация):** цвет статуса **никогда не единственный носитель
смысла**. Рядом всегда слово из данных — `FRESH`/`STALE`/`DEAD`, `unknown`, `Done`, `warn`,
`ended`. Это уже выполняется данными; перелицовка не имеет права это сломать, скрыв текст или
заменив его на цветную точку.

### 4.6 Переключение темы

К медиазапросу добавляется атрибутный scope — приём из `references/palette.md` скилла:

```css
@media (prefers-color-scheme:dark){:root:not([data-theme="light"]){ ... }}
:root[data-theme="dark"]{ ... }
```

Зачем: тёмную тему сейчас невозможно снять скриншотом, не меняя настройку ОС, и один из четырёх
листов приёмки GSL-109 из-за этого вышел светлым. С атрибутом достаточно выставить
`document.documentElement.dataset.theme='dark'`.

**Переключателя в интерфейсе не появляется** — новых видимых элементов и текста не добавляем
(раздел 1.1). Атрибут ставится извне, инструментом съёмки.

## 5. Spacing

База **4px**. Существующая шкала `--s1…--s7` = 4/8/12/16/24/32/48px — **уже правильная,
значения не меняются**. Меняется дисциплина применения: любое расстояние берётся из шкалы,
промежуточных значений нет.

| Что | Значение | Токен |
|---|---|---|
| Между секциями (`h2` и предыдущий блок) | 32 | `--s6` |
| Между `h2` и его содержимым | 12 | `--s3` |
| Внутренние поля карточки `.card`, `.kpi`, `.wk` | 12 по вертикали, 16 по горизонтали | `--s3` / `--s4` |
| Между карточками в `.grid` | 8 | `--s2` |
| Ячейка таблицы `td` | 6 по вертикали, 10 по горизонтали | см. 6.2 |
| Ячейка заголовка `th` | 4 по вертикали, 10 по горизонтали | см. 6.2 |
| Между бейджем и соседним текстом | 4 | `--s1` |
| Внутри бейджа | 1 по вертикали, 6 по горизонтали | см. 7.1 |
| Поля страницы, desktop | 24 | `--s5` |
| Поля страницы, ≤ 416px | 12 | `--s3` |
| Между пунктами навигации | 4 | `--s1` |

Ширина колонки контента: `max-width:64rem` (существующее значение, не меняется), `margin-inline:auto`.

**Радиусы.** `--r1` 4px (бейдж-прямоугольник, ячейка code), `--r2` 6px (карточка, кнопка,
пункт навигации — совпадает с `--radius-panel` Supabase), `--r3` 8px (крупный блок runway),
`--r-pill` 999px (бейдж-пилюля). Значение `--r2` уточняется с 8px до 6px, `--r3` с 12px до 8px:
у эталонов панель — 6px (Supabase) и 6–10px (Mastra), 12px читается мягко для инструмента.

**Границы.** Толщина везде `1px`. Двухпиксельная рамка допускается **только** на блоке в
состоянии `dead` (раздел 8.1). Тени не используются нигде — ни у Supabase, ни у Mastra в
дашбордных поверхностях их нет; разделение делают граница и уровень поверхности.

## 6. Таблицы

Таблица — главный носитель этого интерфейса: 13 таблиц, 589 строк данных на семи экранах.
Всё остальное обслуживает её.

### 6.1 Зебра или hover — выбрано hover

**Зебры нет. Строки различаются только по hover.** Обоснование измеренное, а не вкусовое: ни у
Supabase, ни у Mastra зебры нет ни в одном табличном компоненте — обе системы разделяют строки
границей-волоском и подсвечивают только наведение и выделение (`table.tsx`: `hover:bg-surface-200`;
Mastra: `hover:bg-surface3`).

Дополнительная причина, специфичная для нас: в timeline у строк уже есть **семантическая**
подсветка фона по severity (`tr.sev-incident` получает тонированный фон и врезанную левую грань).
Зебра конфликтовала бы с ней — читатель не смог бы отличить «чётная строка» от «инцидент».

```
tbody tr{border-bottom:1px solid var(--line-subtle)}
tbody tr:last-child{border-bottom:0}
tbody tr:hover{background:var(--sunken)}
```

### 6.2 Плотность

| Элемент | Значение |
|---|---|
| Кегль `td` | `--t-md` (13px) |
| Кегль `th` | `--t-xs` (11px) |
| Поля `td` | `6px 10px` → высота строки ≈ **32px** |
| Поля `th` | `4px 10px` → высота ≈ **28px** |
| Граница под `th` | `1px solid var(--line)` |
| Фон `th` | `var(--sunken)` |
| Выравнивание по вертикали | `top` (длинные значения переносятся — раздел 6.4) |

Высота строки 32px — плотнее эталонов (Supabase ≈ 48px, Mastra 40–56px) и соответствует их же
плотному дата-гриду (`--datatable-rowheight: 28px` у Supabase). Причина: у нас 200 строк на экран,
а не 20; при 48px timeline превращается в бесконечную прокрутку. Заголовок 28px совпадает с
`--height-table-header` Mastra.

### 6.3 Заголовки колонок

Приём общий у обоих эталонов: мелкий верхний регистр приглушённым цветом.

```
th{font:500 var(--t-xs)/1.5 var(--sans);text-transform:uppercase;letter-spacing:.06em;
   color:var(--muted);text-align:left;background:var(--sunken)}
```

Регистр меняется **только CSS-свойством** `text-transform`. Текст в DOM остаётся как есть —
это условие выживания текстовых ассертов.

### 6.4 Числа и длинные значения

**Числа** — вправо, с табличными цифрами:

```
td.num,th.num{text-align:right;font-variant-numeric:tabular-nums;font-family:var(--mono)}
```

Правило применения: колонка выравнивается вправо, если её значения — количества, которые
сравнивают по величине. В данных это `n`, `events`, `files`, `cycles`, `out`, `in`, `cache read`,
`cache write`, `running total`, `tokens`. Самое широкое значение — `461,861,060` (9 цифр плюс
разделители), под него колонка и должна быть рассчитана.

Ключи и идентификаторы (`GSL-110`, `#124`, sha, `q-2026-07-20-004`) — моноширинные, но
**влево**: их не сравнивают по величине, а ищут глазами по началу строки.

**Длинные значения — перенос, не обрезка.** Решение обязательное, и оно не вкусовое:

1. Урок цикла 61, записанный в GSL-109: «mono-карточка молча резала JSON — обрезка без
   индикации» был квалифицирован как дефект.
2. Правило `overflow-wrap:anywhere` — часть контракта, его грепает `smoke.sh:2237`.
3. Дашборд, чья заявленная задача — не врать о данных, не имеет права молча прятать их хвост.

```
.mono:not(table):not(.wrap *){overflow-wrap:anywhere}
td{overflow-wrap:anywhere}
```

Реальная нагрузка, под которую это рассчитано: 892 символа моноширинного списка имён одной
строкой (fleet), 455 символов вопроса в ячейке пятиколоночной таблицы (questions), 168 символов
решения рядом со 144 символами моноширинного правила (library).

⚠️ **Многоточие как индикатор обрезки не добавляется** — это был бы новый видимый текст.
Уже пре-обрезанные значения (пути, урезанные генератором на ~90 символах) остаются как есть:
чинить их — задача данных, не представления.

Горизонтальная прокрутка широких таблиц сохраняется на существующей обёртке
`.wrap{overflow-x:auto}`.

### 6.5 Что делать с колонками, где почти всё пусто

В `tasks` колонка `summary` пуста в 101 строке из 110, в `cost` колонка `cache write` — в 30 из 40.
Колонки **не убираются** (это изменило бы порядок ячеек, а он проверяется — раздел 10.3).
Пустое значение остаётся тем, чем оно отрисовано генератором. Единственное правило: заполнитель
отсутствия красится `--muted`, а не `--fg`, чтобы пустота не выглядела данными.

## 7. Статусные бейджи

### 7.1 Форма

Одна форма на все бейджи:

```
.tag{display:inline-flex;align-items:center;gap:var(--s1);
     padding:1px 6px;border-radius:var(--r-pill);border:1px solid;
     font:500 var(--t-xs)/1.45 var(--mono);white-space:nowrap}
```

- **Заливка полупрозрачная, текст цветной, граница цветная** — устойчивый паттерн обоих эталонов;
  плотной заливки нет ни в одном их статусном варианте. У нас это выражено готовыми токенами:
  `background:var(--X-soft); color:var(--X); border-color:var(--X-border)`.
- **Моноширинный, без `text-transform`.** Mastra делает бейдж моноширинным; капса не ставим
  намеренно — содержимое бейджей здесь это идентификаторы из данных
  (`hook:PostToolUse`, `merge-commit`, `claude-opus-4-8`), и капс их только ухудшит. Значения,
  которые уже пришли капсом (`DECISION`, `MERGED`), капсом и останутся — потому что так в данных.
- Высота получается ≈ 18px. Бейдж — метка, а не кнопка.

### 7.2 Кто получает цвет, а кто нет

**Правило: цвет получает только то, что несёт оценку.** Всё остальное — `--neutral`.
Прямое следствие анти-паттерна `dataviz`: «status color used for a non-status series» —
статусный цвет, надетый на не-статус, обесценивает сам канал.

Сейчас правило нарушено массово: 12 разных провенанс-бейджей (`hook:PostToolUse`, `emit`,
`poll-fill`…) окрашены и повторяются в каждой из 200 строк timeline. Это метаданные — откуда
пришло событие, — а не суждение о нём.

**Нейтральные (`--neutral`)** — метаданные, идентификаторы, категории:

| Семейство | Значения |
|---|---|
| Провенанс / `src` | `hook:PostToolUse`, `hook:Stop`, `hook:SessionStart`, `hook:SessionEnd`, `hook:TeammateIdle`, `hook:SubagentStart`, `hook:SubagentStop`, `hook:Notification`, `hook:TaskCreated`, `hook:TaskCompleted`, `emit`, `poll-fill` |
| Вид артефакта | `Handoffs`, `Dev history`, `Reviews`, `Incidents / RCA`, `Reports`, `Research`, `Morning digests`, `PRD` |
| Модель | `claude-opus-4-8`, `claude-fable-5` |
| Членство эпика | `merge-commit`, `branch`, `merged-unwitnessed`, `no-trunk` |
| Тип вопроса | `DECISION`, `CLARIFY`, `FYI` |
| Состояние PR | `MERGED`, `pr-open`, `pr-closed` |
| Статус вопроса | `auto-resolved`, `answered`, `answered-by-default`, `noted`, `open` |

**Цветные** — только оценка:

| Значение | Роль | Где |
|---|---|---|
| `fresh` · `clear` · `active` · `Done` · `ok` | `--ok` | баннер, часы, воркеры, задачи, метры |
| `stale` · `warn` · `silent` · `gaps` · `To Do` | `--warn` | баннер, severity, воркеры, метры, задачи |
| `dead` · `incident` · `BLOCKER` · `exhausted` | `--dead` | баннер, severity, вопросы, часы |
| `unknown` · `empty` · пустое показание | `--unk` | везде, где показания нет |
| `info` · `In Progress` | `--info` | severity, статус задачи |

⚠️ **`info` при этом отрисовывается нейтрально в колонке `sev` timeline.** Значение `info` стоит
в 181 строке из 200 — красить его значит красить весь экран. Дефолт не подсвечивают; цвет
зарабатывают `warn` и `incident`. Роль `--info` остаётся в палитре для случаев, где
информационный бейдж стоит одиночно.

### 7.3 Единый вид отсутствия

Сейчас «нет данных» отрисовано двумя разными способами: `.unknown` (пурпурный курсив с пунктирным
подчёркиванием и тултипом) и голое `—` в таблицах cost. Читатель видит два разных явления там,
где явление одно.

**Приводится к одному виду:** `--unk` как цвет, обычное начертание (курсив убирается), пунктирное
подчёркивание сохраняется как второй канал, тултип сохраняется.

```
.unknown{color:var(--unk);font-style:normal;text-decoration:underline dotted;
         text-underline-offset:2px;cursor:help}
```

Символ `—` в таблицах cost **остаётся символом** (это текст из данных, менять его нельзя) и
получает цвет `--muted`.

### 7.4 Мёртвые классы

В разметке есть классы без единого CSS-правила: `tag ok`, `tag warn`, `tag dead`, `tag dim`,
`tag unknown` (`selfhealth.tsx:78`), голые `ok`/`warn`/`dead` (`selfhealth.tsx:133,181,183`,
`runway.tsx:76`), `tag pr-unknown` (`tasks.tsx:37`). Сейчас к ним применяется только базовый
`.tag`.

**Их нужно оживить, а не удалить** — разметка уже передаёт смысл, просто он не покрашен.
Правила пишутся по таблице раздела 7.2. Удаление классов из разметки запрещено (раздел 10).

## 8. Компоненты, которые задают лицо экрана

### 8.1 Блок runway (index) — главный источник претензии

Сейчас: пурпурная заливка во всю ширину, пунктирная рамка, значение кеглем 40px, под ним пять
строк прозы. Это ровно два анти-паттерна `dataviz` сразу — «толстые насыщенные блоки» и
«пунктир как шум».

Становится:

```
.runway{background:var(--card);border:1px solid var(--line);border-radius:var(--r3);
        padding:var(--s4);border-left:2px solid var(--line)}
.runway-label{font:500 var(--t-xs)/1.5 var(--sans);text-transform:uppercase;
              letter-spacing:.06em;color:var(--muted)}
.runway-big{font:500 var(--t-hero)/1.15 var(--mono);font-variant-numeric:tabular-nums}
.runway-say,.runway-next{font:400 var(--t-base)/1.5 var(--sans);color:var(--dim);max-width:68ch}
```

- Заливки нет. Пунктира нет. Радиус 8px, граница-волосок.
- Цвет несут **значение** (`.runway-big` красится в `--ok`/`--warn`/`--dead`/`--unk` по грейду)
  и **бейдж** рядом. Не подложка.
- **Громкость по мере тревоги** — левая грань:
  `ok` → `var(--line)` (то есть незаметна),
  `warn` → 2px `var(--warn)`,
  `dead` → 2px `var(--dead)` плюс подложка `var(--dead-soft)`,
  `unk` → 2px `var(--unk)`.
  Заливку зарабатывает только `dead`.
- Проза (`.runway-say`) уходит на `--t-base`, цвет `--dim`, ширина строки ограничена 68ch.
  **Текст не меняется** — он просто перестаёт кричать.

### 8.2 Проза вообще

На этих экранах много объяснительного текста, и удалить его нельзя (раздел 1.1). Значит его нужно
подчинить:

```
p,.card p,.blind{font:400 var(--t-base)/1.5 var(--sans);color:var(--dim);max-width:68ch}
```

- Курсив как средство акцента **не используется** нигде: он есть в исходных текстах как часть
  цитат — там и остаётся, но CSS его не добавляет.
- Жирного внутри прозы нет (максимум 500 и только на `<b>`, который несёт данные).
- `.blind` («что этот экран не видит») и `.stale-note` — это оговорки, а не тревога: цвет `--dim`,
  фон `--sunken`, граница-волосок. Янтарь `--warn` в них не используется, кроме случая, когда
  оговорка сообщает о настоящем ухудшении.

### 8.3 Карточки часов и KPI

Шесть карточек-часов и четыре KPI-плитки сейчас каждая в своей рамке, с разноцветными значениями
и подписями капсом.

```
.kpi,.clock{background:var(--card);border:1px solid var(--line);border-radius:var(--r2);
            padding:var(--s3) var(--s4)}
.kpi b,.clock-val{display:block;font:500 var(--t-hero)/1.15 var(--mono);
                  font-variant-numeric:tabular-nums;color:var(--fg)}
.kpi span,.clock-axis{font:400 var(--t-xs)/1.5 var(--sans);text-transform:uppercase;
                      letter-spacing:.06em;color:var(--muted)}
```

## 9. Навигация

### 9.1 Структура — не меняется

Остаётся `<header class="masthead">` → `<h1>` → `<nav>` с семью ссылками
`href="<screen>.html"` в существующем порядке: Overview · Timeline · Tasks · Questions · Fleet ·
Cost · Library. Проверяется 49 грепами (`smoke.sh:513-520`), править нельзя.

Сайдбар эталонов **не переносится**: он потребовал бы сменить структуру шапки, а `nav` с
`flex-wrap` — часть контракта (раздел 10.4) и инвариант GSL-100 про 390px. Берётся приём, а не
форма: у обоих эталонов активный пункт отмечен **плотностью подложки, а не цветом**
(у Mastra это измеримо: hover 7% → active 11%).

### 9.2 Оформление

```
nav{display:flex;flex-wrap:wrap;gap:var(--s1) var(--s1);margin:0}
nav a{padding:var(--s1) var(--s2);border-radius:var(--r2);border:0;
      font:400 var(--t-md)/1.5 var(--sans);color:var(--dim);text-decoration:none}
nav a:hover{background:var(--sunken);color:var(--fg)}
nav a[aria-current="page"]{background:var(--raised);color:var(--fg);font-weight:500}
```

- Рамок у пунктов нет — «таблетки» уходят.
- Активный пункт: подложка `--raised` плюс вес 500 плюс основной цвет текста. **Не акцентный
  цвет** — синий здесь значит «ссылка», и активный пункт не должен выглядеть как самая важная
  ссылка на странице.
- `h1` — `--t-xl` (20px), вес 500, цвет `--fg`. Шапка отделяется от содержимого границей-волоском
  снизу, а не отступом в 32px.

⚠️ Строка `nav{display:flex;flex-wrap:wrap;...}` обязана остаться **одной строкой**, с `nav{`
без пробела перед скобкой и `flex-wrap:wrap` без пробела после двоеточия. Причина — в разделе 10.4.

### 9.3 Поведение на 390px

Единственный брейкпоинт — `@media (max-width:26rem)` (416px).

| Что | Desktop | ≤ 416px |
|---|---|---|
| Поля страницы | `--s5` (24px) | `--s3` (12px) |
| `h1` | `--t-xl` (20px) | `--t-lg` (16px) |
| `.runway-big`, `.kpi b` | `--t-hero` (28px) | `--t-xl` (20px) |
| Навигация | одна строка | **переносится на две строки** через `flex-wrap` |
| `.grid` | `auto-fit`, от 180px | одна колонка |
| `td`/`th` поля | `6px 10px` / `4px 10px` | `6px 8px` / `4px 8px` |
| Широкие таблицы | по ширине | горизонтальная прокрутка внутри `.wrap` |

**Инвариант, который нельзя нарушить:** `scrollWidth == clientWidth == 390` на всех семи экранах,
все семь ссылок навигации достижимы. В цикле 59 рендерер печатал ссылки без пробелов между
`<a>`, и Cost с Library были физически недостижимы с телефона (`scrollWidth` 850 при экране 390).
Перенос навигации обеспечивается `flex-wrap:wrap` плюс `gap` — не пробелами в разметке.

### 10.4 Два правила CSS, которые грепаются

```bash
smoke.sh:2236  grep -qE 'nav\{[^}]*flex-wrap:wrap'
smoke.sh:2237  grep -qE 'overflow-wrap:anywhere'
```

Проверяются только на `index.html` (`$SHI`), с инвертированными позитивными контролями
(`2242-2248`: рукописная «до-фиксовая» таблица стилей обязана обоими детекторами **отбраковываться**).
Минификация не грозит — её нет ни на одном проходе сборки.

**Что ломает первый греп** (проверено на форме регулярного выражения):

| Изменение | Результат |
|---|---|
| Разбить правило на несколько строк | **FAIL** — grep построчный |
| `nav {` с пробелом | **FAIL** |
| `flex-wrap: wrap` с пробелом после двоеточия | **FAIL** |
| `nav,footer{…flex-wrap:wrap}` — список селекторов | **FAIL** (подстроки `nav{` нет) |
| `header nav{…}`, `.masthead nav{…}`, внутри `@media` | PASS |
| Добавить другие свойства в тот же блок | PASS |
| Заменить на `display:grid` или `flex-flow:row wrap` | **FAIL** — поведение то же, греп другой |

**Второй греп не проверяет селектор вообще** — он матчит строку где угодно в файле. Правило
`.mono:not(table):not(.wrap *){overflow-wrap:anywhere}` (`theme.ts:164`) обязано остаться с
`overflow-wrap:anywhere` без пробела после двоеточия. Замена на `word-break:break-all` или
`hyphens:auto` — **FAIL**, хотя поведение сопоставимо.

Если редизайну понадобится выразить любое из этих поведений иначе — `smoke.sh:2236-2237`
правится **в той же задаче**.

### 10.5 Ограничения со стороны клиентского JS

`client.ts` — вторая поверхность контракта, не менее жёсткая, чем smoke.

1. Клиентский бандл остаётся **первым `<script>` без атрибутов** на странице: три тестовых
   стенда (`1395`, `1576`, `1767`) матчат именно первый такой тег. Новый безатрибутный `<script>`
   выше по документу сломает все тесты клиентского поведения.
2. `#staleness` и `.filter-count` **теряют свой `className` целиком** при первом же
   срабатывании (`client.ts:59` и `201`). На них нельзя вешать классы оформления —
   стилизовать только по `id`, `[data-grade]` и типу элемента.
3. `.age`, `.wk-age`, `.countdown` **перерисовываются по `textContent`** — внутри не должно быть
   дочерней разметки, она будет стёрта на первом тике.
4. Строки фильтруемых таблиц скрываются через `r.hidden = true`, что работает только благодаря
   правилу `[hidden]{display:none!important}` (`theme.ts:278`) — **удалять его нельзя**:
   браузерное `[hidden]{display:none}` проигрывает любому `display`, заданному на `<tr>`.
5. Строки должны оставаться **потомками** элемента `filterScope` и сохранять `data-row="N"`.
6. Текст возраста склеивается как `«<значение> old»` (`ageText`), поэтому подпись рядом обязана
   оставаться именной группой: `smoke.sh:675-693` и `2116-2130` с позитивными контролями
   запрещают появление `… old ago` и `for Nm old`.
