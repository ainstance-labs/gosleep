# GSL-223 — JQL-выгрузка оркестратора и автоподхват её poll-fill'ом

## What was done

Ветка сверки с Jira наконец подключена к данным (находка 12, MAJOR: 152 из 161 задач без статуса,
трекер не опрашивался 11 дней). Теперь у poll-fill три источника Jira-ленты по порядку: явный
`--jira-json FILE`, acli/jira CLI (если появится), и **конвенционный дамп
`docs/lab/scratch/jira-poll.json`**, который оркестратор сохраняет на границе цикла — подхватывается
БЕЗ флагов, так что и сегодняшний проход хроникёра, и будущий тик GSL-176 получают Jira-ветку без
нового кода. Подхват громкий: отчёт несёт `jira_feed` с возрастом файла — «сверился с дампом
прошлого вторника» и «сверился с трекером» не выглядят одинаково.

Сделан и первый реальный прогон: выгружены все 249 задач GSL через Atlassian MCP (3 страницы
пагинации), poll-fill записал 338 событий `tracker.issue.updated` (bootstrap с `--prehistory` —
104 статуса старше пола лога), повторный прогон нашёл 0 пропусков (идемпотентность — приёмочный
критерий GSL-87 держится). Экран Tasks: **unknown 0 из 249** (было 94 процента). Метрика
автономности GSL-222 сразу ожила: **0.829** (13 asks / 76 shipped за 7 дней).

## Problems solved

- **Транспорт через границу MCP.** Лаборатория не держит Jira-ключей (C1), CLI нет; лента доступна
  только агентам с MCP. Файл-дамп в scratch/ (gitignored — транспорт, не история; историю пишут
  события) — единственный стык, не требующий ни ключей у механики, ни нового кода у будущего тика.
- **tools/lab/tick.sh не существует** (эпик GSL-176 ещё открыт) — задача называла его местом
  правки. Автоподхват в самом poll-fill решает это без зависимости: кто бы ни запускал сверку,
  ветка Jira включается сама.

## Problems remaining

- Привычка сохранять дамп на границе цикла — шаг чек-листа оркестратора, а чек-лист живёт в
  СУВЕРЕННОМ глобальном скилле. Готовый текст шага (плюс рекомендация гонять на границе цикла
  chronicler БЕЗ --no-poll — вторая половина находки 12) — в
  `docs/handoff/GSL-223-orchestrator-cycle-boundary-jira-dump.md`; применить его может только
  оркестратор/владелец.
- Свежесть дампа не форсируется: старый дамп используется с честным возрастом в отчёте. Порог
  свежести (например, «старше суток — degraded») сознательно не введён — сначала посмотреть на
  реальную каденцию границ цикла.

## Pitfalls & workarounds

- **Пагинация MCP:** searchJiraIssuesUsingJql режет по 100, `nextPageToken` длинный — обрезанный
  токен даёт «invalid or expired». Передавать целиком.
- **Пол лога (prehistory):** по умолчанию poll-fill отсекает факты старше первой строки лога —
  для первого прогона это 104 задачи. Однократный bootstrap `--prehistory` — штатный путь, флаг
  для этого и существует; зафиксировано в документе оркестратору.
- Приоритет источников: явный `--jira-json` всегда бьёт дамп (флаг — это решение); закреплено
  smoke-ассертом.

## What didn't make it

- Правка суверенного скилла (запрещено) — только документ-заготовка.
- Снятие --no-poll с коммит-гейтов воркеров: осознанно НЕТ — гейт под задачей не должен мутировать
  общий лог событий; рекомендация касается штатного прохода оркестратора на границе цикла.
