# GSL-199 — tools/lab/tick.sh: идемпотентный страховочный тик

## What was done

Появился сам мотор — `tools/lab/tick.sh`, один скрипт, который за один запуск делает всё, что
система обязана делать регулярно, и доказывает это ровно одной строкой леджера. Порядок шагов —
по зависимостям данных: `poll-fill` (сверка внешней правды: git/gh/Jira-дамп → таймлайн), `lab-emit
apply-due` (дефолты просроченных DECISION — исполнитель из GSL-200), летописец (пересборка
производных поверхностей — но ТОЛЬКО если дебаунс GSL-198 не держит их свежими: возраст бандла
больше `GOSLEEP_TICK_FRESH`, либо apply-due что-то применил, либо `--force`), `armed-check` (если
существует), и строка `{"mode":"tick",...}` в `docs/lab/supervision/tick-ledger.jsonl`.

Тик — страховка, не первый эшелон: в живой сессии свежесть держит дебаунс-хук, тик закрывает все
остальные часы — ночь без агентов, дедлайн решения в 03:00, пропущенное окно дебаунса. На нём
ноль LLM-вызовов: тик не тратит токенов и не открывает окно квоты, кто бы и как часто его ни
запускал.

## Problems solved

- **Двойной опрос.** Летописец сам гоняет poll-fill нулевым шагом — но тик уже сделал это шагом 1.
  Внутри тика летописец зовётся с `--no-poll` ПО КОМПОЗИЦИИ (в заголовке скрипта это объяснено
  словами): это не «оффлайн-режим», а «не опрашивать дважды за один тик». GSL-203 убирает флаг из
  самостоятельного гейта смены — там перед летописцем никакого шага 1 нет.
- **Свежесть против интервала.** Порог свежести по умолчанию 240 c — сознательно МЕНЬШЕ интервала
  носителя (300 c): тихой ночью каждый тик находит бандл возрастом ~интервал и пересобирает, так
  что `generated_at` не может состариться дальше одного интервала — это критерий приёмки эпика.
  Дневной тик при работающем дебаунсе наоборот почти всегда «skipped-fresh» — ноль лишней работы.
- **Герметичность тестов.** У тика флаг `--repo` (как у летописца и poll-fill): lab-каталог,
  бандл, леджер и лок следуют за целевым репо; smoke гоняет тики по фикстуре, не касаясь живой
  лаборатории. Явный env всё равно сильнее (smoke пиннит GOSLEEP_LAB_DIR из-за своего глобального
  сандбокса).
- **Один тик за раз.** mkdir-лок: второй тик при живом локе пишет `result="skipped-lock-held"` и
  выходит 0 (работу сделает бегущий); лок, молчащий больше 30 минут, — труп и крадётся.

## Problems remaining

- `armed-check` ещё не существует (его строит GSL-211 в эпике сторожа GSL-178) — тик честно пишет
  `"armed_check":"absent"` вместо театра вооружённости (R2 аудита). Когда скрипт появится, тик
  подхватит его без правок — проверка по `-x tools/lab/armed-check.sh`.
- Путь ошибки летописца/apply-due (exit 1 с леджер-строкой `error:<шаг>`) покрыт кодом, но не
  smoke-тестом: honest-заметка, форсировать падение летописца герметично дорого.

## Pitfalls & workarounds

- **ИНЦИДЕНТ-УРОК: тестовая запись утекла в живую очередь.** При ручном прогоне фикстуры один
  вызов `lab-emit question` ушёл БЕЗ `GOSLEEP_LAB_DIR` и создал `q-2026-07-28-005` в реальной
  очереди. Очередь append-only — запись не удалить; закрыта честно через `answer --by impl-176` с
  текстом «ошибочная тестовая запись». Правило на будущее: каждый герметичный вызов lab-emit
  начинается с `GOSLEEP_LAB_DIR=фикстура`, без исключений.
- **`exit N` в конце — только на настоящей ошибке.** Деградированные источники (gh оффлайн, нет
  Jira-фида) — это ДАННЫЕ отчёта poll-fill, не провал тика: фикстура без remote и без фида даёт
  poll_rc=0 и result=ok. Ненулевой выход зарезервирован для реальных поломок (apply-due упал,
  летописец упал, неизвестный флаг = exit 2).
- **Порядок «poll → apply-due → летописец» не случаен**: сначала таймлайн узнаёт внешнюю правду,
  потом закрываются просроченные решения, и только потом пересобираются поверхности — иначе
  дашборд одну итерацию показывал бы уже применённое решение открытым.
- **Грep-ловушка C1.** Первая версия заголовка тика содержала фразу «no claude -p» — и C1-проверка
  smoke (`grep 'claude -p'`) честно завалилась об КОММЕНТАРИЙ. Перефразировано без литерала;
  урок тот же, что у летописца с backtick'ами: проверяемый инвариант должен быть grep-чистым и в
  документации к себе.

## What didn't make it

- Ранний выход «не будить, если работы нет» — это следующая задача GSL-202, отдельным коммитом.
- Автоматический выбор носителя — развилка владельца (вопрос 5, d-2026-07-28-003): тик лишь
  штампует `--carrier` в леджер, чтобы утро после preflight-ночи могло разделить launchd и
  Desktop по строкам.
