# GSL-205 — Идентификатор снова ведёт куда-то, и не на одном экране, а на всех семи

## Что произошло

Ссылки наружу были ровно на одном экране. Доска задач печатала 796 ссылок, Questions — 7. При этом
все элементы очереди несли ключ Jira, а 114 из 200 строк таймлайна несли кликабельный идентификатор
простым текстом. То есть данные для ссылки были, а ссылки не было: доска умела превращать ключ в
URL, а остальные шесть экранов печатали ровно те же ключи мёртвым текстом.

Это ломает главное обещание лаборатории — «единое место, где всё можно проверить». Идентификатор,
который приходится выделять, копировать и искать руками, — это обещание, нарушенное один раз на
каждую строку.

## Что сделано

Одна функция, а не привычка. Экран больше не решает, как ключ становится ссылкой: он отдаёт свой
текст в `Ids` (и в `Sha` там, где значение точно коммит). Три следствия, и каждое — причина, по
которой это не семь локальных хелперов:

- **Один префикс.** Базы URL (`links.jira_base`, `links.gh_base`) собираются один раз в Python из
  тех же констант, что строят per-row `jira_url`/`gh_url` на доске. Две записи одного трекера — это
  отказ, при котором ссылка резолвится, но на чужом сайте.
- **Один отказ.** Нет базы на диске (старый бандл, не-GitHub remote) — текст печатается ровно так,
  как печатался. Старейшее правило этого дашборда: нет источника — нет утверждения.
- **Одна форма.** Каждая сгенерированная ссылка носит `data-idlink`, поэтому тест считает их
  поэкранно, а не верит, что семь файлов не забыли.

**Почему `#N` ведёт на `/issues/N`, а не на `/pull/N`.** Номера issue и PR на GitHub живут в общем
пространстве, и по номеру нельзя сказать, что это. Доска уже отказывается гадать (она не одалживает
эпику номер его issue под ссылку на PR — неправильная ссылка не выдала бы 404, она **зарезолвилась**
бы на настоящую чужую страницу, и это худший из доступных здесь отказов). `/issues/N` — единственная
форма, которая не ошибается никогда: GitHub сам редиректит её на PR, если N — это PR. Гадания
избегаем, выбрав URL, для которого гадать не нужно.

**Коммит-ссылка выдаётся только по имени поля.** `eventDetail` разбит на `eventDetailParts`, который
возвращает ещё и то, КАКОЕ поле выиграло. Ссылка на коммит выдаётся, только если поле — `sha`. Голая
семизначная шестнадцатеричная строка, ссылающаяся «по внешнему виду», рано или поздно указала бы на
коммит, которого нет.

## Ловушка, на которой сломался первый прогон

Ассерт GSL-97 «каждая ссылка Библиотеки открывается» собирал все `<a href>` внутри таблицы и требовал,
чтобы за каждой лежал файл. Ключ Jira внутри заголовка документа — тоже якорь, и файла за ним нет по
построению. Ассерт не выброшен и не ослаблен до «пропускаем абсолютные URL»: он исключает якоря по
метке, которую они все носят (`data-idlink`), и называет в комментарии, что именно пропускает.
Ссылки-идентификаторы проверяются отдельно, ассертами GSL-205.

Вторая ловушка — своя: комментарий внутри heredoc в `$( … )` содержал апостроф, и bash 3.2 на macOS
(который считает кавычки ВНУТРИ закавыченного heredoc) развалил присваивание в «unbound variable».
Урок в шапке `chronicler.sh` описан ровно про это; теперь про это же есть предупреждение и в
`smoke.sh`.

## Что не вошло

`links` добавлено **без** подъёма версии схемы (`gosleep.lab.render/7`). Поле аддитивное и
объявлено опциональным во view: старый бандл без него печатает идентификаторы текстом. Подъём
версии сломал бы равенство в `render.tsx` и ассерт в `smoke.sh` ради поля, которое ничего не ломает.

Доска и Cost не получили новых ссылок: на доске ключи уже были ссылками (`jira_url`), а в Cost
идентификаторов не печатается вовсе — имена воркеров в леджере их не несут. Считать это пробелом
было бы выдумыванием работы.
