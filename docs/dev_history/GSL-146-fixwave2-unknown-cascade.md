# GSL-146 — Каскад label-спанов больше не глотает span.unknown: значение-отсутствие вернуло себе --unk и размер значения

Задача эпика GSL-153 «Fix wave 2: verification run 02 findings» (GH #148).
Jira: GSL-146 · GH: #149 · находка 1 (MAJOR) аудита verifier-skeptic, run 02:
«unknown values render as 11px muted labels — .kpi span / .wk-f span cascade swallows
span.unknown (Fleet, Cost)».

---

## Часть 1 — человеческим языком

### Что сделано

Дефект был чисто каскадный. Компонент `Unknown` рендерит `span.unknown` там, где стоит
ЗНАЧЕНИЕ: внутри `.kpi b` (KPI-плитка) и рядом с label-спаном в поле воркер-карточки
(`.wk-f`). Généric-селекторы подписей `.kpi span` и `.wk-f span` (специфичность 0,1,1)
матчили и этот спан, перебивая `.unknown` (0,1,0): значение отрисовывалось как ПОДПИСЬ —
11px, капс, `--muted` вместо `--unk`. KPI-плитка с unknown читалась как карточка с двумя
подписями и без значения; маркер отсутствия терял тот самый пурпур, который вся система
резервирует за «не могу прочитать» (спека, разделы 7.3, 8.3, 8.4).

Фикс — исключить маркер из обоих label-селекторов: `.kpi span:not(.unknown)` и
`.wk-f span:not(.unknown)` (theme.ts). Ничего больше не менялось: `.unknown` теперь
выигрывает каскад сам, значение наследует кегль контекста значения (28px hero внутри
`.kpi b`, 13px в поле `.wk-f`), пунктирное подчёркивание и тултип — как были.

### Решённые проблемы

- Ошибка «а почему бы не поднять специфичность .unknown» отвергнута сознательно: правило
  `.kpi span` НЕ ДОЛЖНО касаться значения в принципе — это подпись-селектор; чинить надо
  зону действия селектора подписи, а не устраивать гонку специфичностей.

### Оставшиеся проблемы

- Нет. Оба несущих комментария в theme.ts объясняют, почему `:not(.unknown)` load-bearing.

### Подводные камни

- **theme.ts — один template literal.** Бэктики в CSS-комментарии разрывают строку шаблона:
  первая версия комментария с `` `.kpi span` `` уронила tsc тремя ошибками TS1005. В
  комментариях этого файла допустимы только кавычки.
- Смоук-греп читает СОБРАННУЮ страницу (fleet.html фикстуры $CR), а не исходник — то есть
  ровно те байты, которые читает браузер.

### Что не вошло

- Пересборка закоммиченных страниц `docs/lab/site/` — по норме волны она выполняется одним
  последним коммитом (GSL-150), чтобы производные артефакты индексировали все dev_history
  волны.

### Как проверено прогоном

- **Красный прогон** (сломанная версия = HEAD 10e63d7 до фикса): оба грепа по собранному
  `fleet.html` — FAIL kpi-not, FAIL wkf-not (правил-исключений нет в CSS).
- **Зелёный прогон** (после фикса + пересборка в worktree): PASS kpi-not, PASS wkf-not,
  PASS control-unknown-present; `npx tsc --noEmit` — 0 ошибок.
- **Computed styles (Chromium, light):** `.kpi b .unknown` → fontSize 28px, color
  rgb(142,77,157) = `--unk` #8e4d9d, text-transform none, display inline;
  `.wk-f .unknown` → 13px, rgb(142,77,157); подписи `.kpi span:not(.unknown)` /
  `.wk-f span:not(.unknown)` остались 11px, rgb(104,105,107) = `--muted`, uppercase.
  Ожидание тикета («28px hero / 13px, colour --unk») выполнено дословно.
