# GSL-212 — Источник истины о жизни — claude agents --json; поле session в heartbeat

Эпик GSL-178 (аудит 2026-07-24, эпик 5 «Супервизия»). Смена 74, исполнитель impl-178.

## What was done

Watchdog перестал судить о жизни оркестратора по tmux-скрейпингу и начал спрашивать саму
платформу: `claude agents --json` — штатный машинный список живых top-level сессий Claude Code
(`{pid,cwd,sessionId,name,status}`; тиммейты-сабагенты в списке не появляются, что и делает
сигнал чистым — проверено живьём на этой машине). Появился писатель пульса
`tools/lab/heartbeat.sh`: оркестратор больше не составляет JSON руками — писатель сам находит
свою сессию в ростере по `$CLAUDE_CODE_SESSION_ID` и вписывает в строку `session` (имя) и
`session_id` (UUID). Рассинхрон имени сессии стал невозможен по конструкции: оркестратор не
может опечататься в том, чего никогда не печатает. Вторым слоем этой же задачи в watchdog
въехал каркас режимов: `WD_MODE=observe` — дефолт, при котором всё дерево решений работает, но
каждое действие только записывается в леджер как `would_*` (would_nudge / would_kill /
would_rewake), ничего не отправляется, не убивается, не спавнится и не уведомляется; `armed` —
только явной строкой в watchdog.conf владельца. Каждый тик теперь оставляет одну строку `tick`
с решением и полным основанием (возраст пульса, платформа, корроборация tmux) — леджер
наблюдательного прогона читается сам по себе.

## Problems solved

- **F2 аудита (CRITICAL, раздвоение флота).** Старый watchdog с дефолтами искал tmux-сессию
  `gosleep`, не находил её и по своей же логике поднял бы ВТОРОГО оркестратора рядом с живым.
  Теперь: (а) личность сессии едет в самом пульсе и берётся из ростера; (б) новый гейт
  `session_mismatch` — если заявленная в пульсе сессия отсутствует в ростере, а в этом репо ещё
  есть живые сессии, watchdog отказывается от ЛЮБОГО действия и эскалирует (в observe —
  только в леджер); (в) re-wake возможен только когда ростер не видит ни одной сессии в репо.
  Смоук-кейс `roster-session-mismatch` воспроизводит F2 и подтверждает отказ.
- **Совместимость 75 легаси-сценариев смоука.** Дерево решений не переписывалось — наблюдение
  реализовано подавлением act-слоя, поэтому имена DECISION не изменились. Легаси-кейсы гоняются
  с `WD_MODE=armed --dry-run` (они проверяют вооружённое дерево), новые — с observe и
  фикстурами ростера. Итог 101/101.
- **Наследство симуляции не должно стрелять в бою.** Память между тиками (маркеры, счётчики,
  restarts.history) стала mode-scoped (`$WD_STATE_DIR/<mode>/`): наблюдательный прогон,
  «спаливший» would-бюджет рестартов, не съест бюджет вооружённого сторожа, и наоборот.

## Problems remaining

- Пороги по-прежнему дефолтные (900с/80%): первый же живой observe-тик на этой машине выдал
  `would_request_handoff` при ctx=98% — ровно F3 аудита; лечится GSL-217 этим же эпиком.
- Оркестратор ещё не перешёл на писатель — живой пульс без `session`; до перехода watchdog
  матчит по cwd_single (ровно одна сессия в репо), что на этой машине верно. Переход — строка
  в handoff/эррате для оркестратора.
- `claude agents --json` на прошлых версиях CLI не проверялся; при недоступности ростера
  watchdog честно пишет `platform_unknown` и не действует (fail safe).

## Pitfalls & workarounds

- **`counter_path` забыл про mode-scope** — 4 зомби-теста упали (счётчик писался в корень state,
  смоук сеял в `state/armed/`). Урок: перенося «память» в подкаталог, greppай ВСЕ пути к state
  (markers + counters + history + rate-limit marker), а не только тот, что чинишь.
- **`probe_pane_exists` теперь ищет по `-a` (всему серверу), не внутри настроенной сессии** —
  иначе гейт панели реимпортировал бы F2 (мис-конфиг имени сессии прятал бы живую панель).
  Pane id (%N) глобально уникален.
- **Пробы вынесены до щитов**: quiesced/rolling-тики тоже несут реальные platform-данные в
  строке `tick` — иначе наблюдательный леджер вслепую для самых интересных состояний.
- **В observe `would_rewake` НЕ пишет last-started маркер** — рестарта не было, значит
  startup-grace за него давать нельзя; re-wake-brief при этом собирается (это данные о том,
  ЧТО именно получил бы преемник).
- Тест-мода без фикстуры ростера зеркалит `WD_TEST_SESSION_ALIVE` (match=mirror) — это
  сознательный мост совместимости, а не дыра: все новые ветки тестируются фикстурами.
