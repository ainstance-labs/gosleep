# GSL-157 — Freshness при grade=dead носит .sh-m.dead: прочитанный вердикт больше не рендерится как «не могу прочитать»

Задача эпика GSL-161 «Fix wave 3: verification run 03 findings» (GH #159).
Jira: GSL-157 · GH: #161 · находка 2 (MAJOR) аудита verifier-skeptic, run 03:
«Freshness meter encodes grade=dead as the unknown state — dead and unknown rendered alike».

---

## Часть 1 — человеческим языком

### Что сделано

Тернарник Freshness проецировал грейд в состояние карточки без ветки для dead:
`fresh → ok, stale → gaps, всё остальное → unknown`. Грейд dead — ПРОЧИТАННЫЙ вердикт (возраст
данных известен, порог вычислен), но карточка отвечала на него магентой «не могу прочитать
показание», в двух блоках под красным DEAD-баннером: страница противоречила сама себе в сторону
смягчения вердикта — единственное направление, в котором этому экрану ошибаться нельзя.

Фикс двумя строками: в METER_CLASS добавлен вход `dead: "dead"`, в тернарник — ветка
`h.grade === "dead" ? "dead"`. Карточка при мёртвых данных берёт `.sh-m.dead` — красная грань +
заливка dead-soft, тот же язык, что у баннера. Фолбэк unknown сохранён для действительно
отсутствующего грейда.

### Решённые проблемы

- Рассмотрен и отвергнут вариант «прокинуть grade напрямую в METER_CLASS»: grade и state — разные
  словари (fresh/stale/dead против ok/gaps/debt/empty/unknown), тернарник-переводчик остаётся
  единственным местом, где они встречаются.

### Оставшиеся проблемы

- Нет. dead ≠ unknown теперь выдержан во всех трёх метрах self-health (Handoffs уже имел
  alarm-ветку dead, DevHistory dead-состояния не имеет по построению).

### Подводные камни

- Сериализация preact кладёт `class` до `id` — смоук-грепы держат обе подстроки вместе
  (`class="card sh-m dead" id="sh-freshness"`), что делает их точечными: другой метр в dead они
  не зацепят.
- **Ловушка полного прогона, поймана гейтом:** $CR dead-graded только при первой сборке — проверка
  очереди (lab-emit на :1045) пишет вопрос СЕЙЧАС и пересобирает её, к хвосту smoke грейд снова
  fresh, и первая версия грепа мерила fresh-страницу (sh-m ok). Волна 3 получила собственную
  dead-фикстуру (fw3-dead). Вторая ловушка там же: греп `class="stale dead"` вакуумно зелен на
  fresh-странице — строка живёт в JSON-острове вердиктов; свидетель контрола — status.json.

### Что не вошло

- Пересборка закоммиченных derived-страниц — последним коммитом волны (норма docs/lab/README.md).

## Часть 2 — техническая справка

### Файлы

- `tools/lab/ui/src/selfhealth.tsx` — METER_CLASS с входом dead + несущий комментарий
  (dead = прочитанный вердикт, unknown = отсутствие показания); dead-ветка тернарника Freshness

- `tools/lab/smoke.sh` — блок «GSL-157 (fix wave 3)»: греп `.sh-m.dead` на Freshness собранного

  (`class="stale dead"` — баннер как свидетель).

- **Красный прогон** (родительская версия selfhealth.tsx = HEAD 9601d43, dead-фикстура):
  греп dead-класса FAIL, guard RED (unknown при dead), контроль баннера PASS.
- **Зелёный прогон** (после фикса): PASS×3; `npx tsc --noEmit` — 0 ошибок.
- **Computed styles (Chromium):** light — карточка `card sh-m dead`, грань rgb(144,40,40) =
  `--dead` #902828, заливка rgb(255,239,238) = `--dead-soft` #ffefee, заголовок rgb(26,27,28) =

  rgb(55,35,33); баннер на той же странице `stale dead`.
