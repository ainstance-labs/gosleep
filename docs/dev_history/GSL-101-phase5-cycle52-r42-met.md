## Part 1 — Рассказ

### Что закрыто

**R4.2 — единственный критерий Фазы 4, остававшийся ⏳ PENDING.** Цикл 50 понизил его честно: ✅ стояло
на наблюдении из разового bootstrap-прогона, которого в репозитории нет. Теперь доказательство есть и
его можно проверить на конкретном sha — строка `seq 156` в `docs/lab/events/2026-07-13.jsonl`,
закоммиченная в `7b229c7`:

```json
{"ts":"2026-07-13T11:37:15Z","seq":156,"actor":"poll-fill","type":"vcs.pr.merged","src":"poll-fill",
 "data":{"pr":102,"occurred_at":"2026-07-13T11:37:15Z","source":"gh","reconciled":true}}
```

Это **единственная** `vcs.pr.merged` во всём логе. Конкурирующей хуковой записи нет — значит мёрж
PR #102 **не увидел ни один хук**, и в таймлайн он доехал **сверкой**. Механизм, ради которого писался
poll-fill, отработал на живом событии, а не на фикстуре и не в smoke.

### Оговорка, без которой это было бы подгонкой

Мёрж сделан **не из веба**, как предписывал handoff 27, а командой `gh api -X PUT`. `gh` — это и есть
CLI. Значит **буква** критерия («PR, смёрженный **вне CLI**, появляется в таймлайне») **не выполнена**.

Выполнено **свойство**, которое эта буква обозначала. Матчер `VERBS` в `lab-log.sh` знает ровно
`("gh pr merge", "vcs.pr.merged")` — про `gh api` там нет ничего, поэтому распознать такой мёрж хук
физически не мог. А poll-fill к *способу* мёржа безразличен: он спрашивает у `gh`, какие PR смёржены,
и дописывает те, которых нет в логе. Мёрж из веба прогнал бы **тот же самый код**.

**Находка, а не формальность:** «вне CLI» — **дырявый прокси** для «не увиденный ни одним хуком». Путь
через CLI тоже может остаться неувиденным — что и произошло. Критерий стоило формулировать по свойству,
которое он проверяет, а не по способу, которым это свойство обычно достигается.

Записано как находка. Переписывать формулировку задним числом под то, что получилось, — нельзя: это
ровно тот жанр, за который цикл 50 и понизил R4.2 до PENDING.

### Что чуть не сломалось по дороге

Правка выглядела как «перещёлкнуть один значок». Но вся таблица приёмки цитирует **счётчики по логу**, а
леджер-коммит GSL-91 лог **дополнил**. Сверил обе точки — поехало **всё**:

| Счётчик | `63b1c63` | `7b229c7` |
|---|---|---|
| `vcs.commit` | 11 hook + 3 poll-fill | **12 + 4** |
| Jira-переходы (hook) | 9 | **11** |
| `pane.started` / `pane.ended` | 7 / 7 | **9 / 9** |
| `src=hook:*` всего | 162 | **246** |
| `context.*` (компакция) | 0 | 0 |
| `vcs.pr.*` | opened 1, merged **0** | opened 1, merged **1** |

Перещёлкнуть только `merged: 0 → 1` означало бы оставить пять остальных цифр **тихо неверными** на новом
sha — то есть воспроизвести дефект M2/M4, который цикл 50 как раз и чинил. Поэтому jq-рецепт в документе
теперь даёт **две колонки** и прямо говорит, на каком sha какое число держится.

Компакция на обоих sha = **0**. **F4-S1 остаётся 3 из 4** — не подкручен под красивую картинку.
