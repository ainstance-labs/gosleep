# GSL-220 — Наблюдательный прогон супервизора: тикает, пишет леджер, ничего не убивает

Эпик GSL-178 (аудит 2026-07-24, эпик 5 «Супервизия»). Смена 74, исполнитель impl-178.

## What was done

Наблюдательный прогон (d-2026-07-28-001) перестал ждать launchctl-шага: его носителем стал мотор
тика. `tools/lab/tick.sh` получил шаг 4b — один watchdog-тик в ПРИНУДИТЕЛЬНОМ observe на каждом
проходе (degraded-never-fatal): леджер, который владелец читает перед вооружением, копится с
первого тика ЛЮБОГО носителя (launchd-плист тика, Desktop-задача, ручной запуск). Разделение
полномочий носителей — конструкцией: тик-носитель наблюдает всегда (WD_MODE=observe форсирован
в вызове, конфиг владельца его тут не переключает), действовать может только собственный plist
сторожа, который ставит владелец. Рунбук `docs/runbooks/watchdog.md` переписан под v0.6: шапка
(режимы, платформенный источник жизни), раздел 0 «Наблюдательный прогон» (как читается леджер
утром, критерий «прогон состоялся», что смотреть перед вооружением), раздел 1 стал «= вооружение»
(WD_MODE=armed — сам акт, плюс гигиена observe-памяти), таблица компонентов пополнена четырьмя
инструментами эпика. Прогон ЗАПУЩЕН живым тиком: первая боевая строка
`docs/handoff/.watchdog-ledger.jsonl` — decision=ok class=healthy mode=observe dry_run=0 на живом
флоте (cycle=150), архиватор GSL-225 скопировал её в трекаемый
`docs/lab/supervision/watchdog-ledger.jsonl`.

## Problems solved

- **Главный риск шага владельца снят**: аудит показал, что «шаг владельца» не делался неделями —
  теперь наблюдательное свидетельство копится без него, а его шаг сузился до самого вооружения.
- **Тик-носитель не может начать убивать**: observe форсирован в точке вызова, не в конфиге —
  даже вооружённый conf не превращает тик в исполнителя.

## Problems remaining

- «Леджер за трое суток» — критерий времени: механизм запущен, но трое суток должны пройти;
  читать — раздел 0 рунбука. Носитель тика (launchd/Desktop) всё ещё ждёт своего one-action
  включения владельцем (preflight GSL-201) — до тех пор строки копятся от ручных/дебаунс-тиков.
- Архив супервизии отстаёт на один проход летописца от живого леджера (порядок шагов тика:
  летописец раньше шага 4b) — следующий тик догоняет; для чтения истории это несущественно.

## Pitfalls & workarounds

- В вызове шага 4b обязателен WD_REPO_ROOT="$REPO": фикстурные тики (smoke) должны наблюдать
  СВОЙ репозиторий и писать СВОЙ леджер, не боевой (тот же урок, что в armed-check/GSL-211).
- Пятидневная пауза подписки посреди эпика: возобновившийся живой флот дал пульс cycle=150 —
  первая наблюдательная строка снята уже с «нового» мира, что только честнее.

## What didn't make it

- Отдельный плист для observe-watchdog — не нужен: мотор тика уже существует и уже
  предназначен «для каждого другого часа»; второй носитель добавил бы только рассинхрон.
  Вооружённый плист остаётся путём вооружения (рунбук, раздел 1).
