# GSL-219 — Зафиксировать версию CLI в STATE и в heartbeat

Эпик GSL-178 (аудит 2026-07-24, эпик 5 «Супервизия»). Смена 74, исполнитель impl-178.

## What was done

Версия Claude Code CLI перестала быть нигде не записанным фактом. Писатель пульса штампует поле
`cli` в каждую строку heartbeat — разрешая версию из `CLAUDE_CODE_EXECPATH` (харнесс сам
закрепляет там работающую версию: `.../versions/2.1.220`), с фолбэком на `claude --version` и
тестовым override `GOSLEEP_CLI_VERSION`. Watchdog помнит последнюю виденную версию (mode-scoped
`last-cli`) и превращает смену версии между строками пульса в событие `cli_version_changed`
(old→new) в леджере; версия также едет в каждой tick-строке. Для STATE подготовлена эррата
`docs/handoff/GSL-178-errata-orchestration-state.md` с точным текстом строки `cli=` (якорь —
сразу после заголовка TELEMETRY) и дисциплиной обновления на границе цикла — STATE суверенен,
вставляет оркестратор. Скилловая эррата GSL-178-errata-skill-heartbeat.md дополнена: `cli` в
примере формата и в списке полей.

## Problems solved

- **Живой пример аудита закрыт**: расхождение 2.1.219 (день аудита) → 2.1.220 (сегодня) прошло
  бы незамеченным; теперь первый же пульс новой версии даёт событие с old/new.
- **Ноль лишней цены**: чтение basename EXECPATH бесплатно; `claude --version` — только фолбэк.
- **Первая встреча ≠ смена**: событие требует предшественника (иначе каждый свежий state-dir
  порождал бы ложную «смену»).

## Problems remaining

- «Ломающее обновление в 03:00 не обработано» — обработка (стратегия отката/пиннинга) за
  пределами задачи: сделана ОБНАРУЖИМОСТЬ (событие + строка в STATE), реакция — решение
  владельца по данным наблюдательного прогона.
- Строка `cli=` появится в STATE только после применения эрраты оркестратором.

## Pitfalls & workarounds

- Память версии mode-scoped, как и вся память тиков — наблюдательный прогон не должен
  «съедать» первое событие вооружённого (и наоборот).
- В окружении Bash-тулов harness выставляет CLAUDE_CODE_EXECPATH — в смоуке дефолтная
  резолюция проверяется регэкспом на семвер, а не точным значением (тест переживёт обновление
  CLI).

## What didn't make it

- Автоматическое обновление строки `cli=` в STATE механикой — сознательно нет: STATE пишет
  только оркестратор (суверенитет); механическая половина живёт в heartbeat+леджере.
