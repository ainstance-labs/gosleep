# GSL-226 — Ветка рендера BLOCKER впервые исполнена на реальных данных

## What was done

Индикатор блокеров всю историю репозитория не исполнялся: open_blockers был 0 во всех сборках,
то есть код, рисующий BLOCKER, ни разу не работал на реальном наборе — «не испытан» в одежде
«рабочего» (находка 96). Теперь весь путь от записи до экрана пройден и закреплён пятью
smoke-ассертами на предписанной задачей механике: настоящий `lab-emit question --type BLOCKER` в
КОПИИ данных (одноразовая лаборатория фикстуры RWB — та же, что гоняет runway), настоящий
хроникёр, настоящий рендерер. Проверено на отрендеренных страницах: Questions берёт ветку
«Blocking you (1)» (текст пустой ветки отсутствует), карточка несёт семантический класс
`tag BLOCKER` и фразу «No default, and there never will be», на странице живёт само цветовое
правило `.tag.BLOCKER -> dead` (красный «стоп», не серый FYI — защита GSL-116), Overview кладёт
блокер в блок «Waiting for you (1)» с тем же тегом, утренний дайджест печатает его первым с
маркером «!». Живая очередь не тронута.

## Problems solved

- Смок уже гонял BLOCKER через runway (F5-S1 a), но НЕ через пиксели — ассертов на questions.html
  / index.html / дайджест не было вовсе. Разрыв «данные проверены, рендер нет» и был находкой;
  новая секция закрывает именно его, переиспользуя готовую фикстуру (ноль новых прогонов хроникёра
  — смок не подорожал).

## Problems remaining

- Ветка BLOCKER мобильной страницы (🛑 в build_mobile) сознательно не ассертится: мобильное — на
  паузе по приказу владельца; код не трогался.

## Pitfalls & workarounds

- Ассерт цвета — на ПРАВИЛО в отгруженной странице (`.tag.BLOCKER{background:var(--dead-soft)`), а
  не на вычисленный цвет: страницы самодостаточны (file://), правило и есть носитель семантики.
  Дефис-класс `blocker-flag` (GSL-160) — отдельная сущность, не проверяется здесь.
- Пустая ветка проверяется отрицанием («No blockers…» отсутствует), иначе тест прошёл бы и на
  экране, который рисует обе ветки разом.

## What didn't make it

- Отдельный ассерт в smoke для `lab-emit` BLOCKER-эмиссии — уже есть в базовом контракте очереди
  (per-type statuses); дублировать не стал.
