# GSL-198 — Вернуть спроектированный дебаунс-хук на записи в docs/lab/

## What was done

Вернул элемент, который был спроектирован в исходном исследовании (`05-lab-ui-mobile-autonomy.md`,
строка 184: «a `PostToolUse` async hook debounced on writes to `docs/lab/`») и выпал при реализации
GSL-83. Теперь любая запись в лабораторию — файл под `docs/lab/` или вызов lab-писателей
(`lab-emit.sh` / `lab-log.sh` / `lab-write.sh`) — взводит фоновый «ожидатель», и когда записи
утихают на 90 секунд, летописец пересобирает все производные поверхности сам, без участия агента.
Дашборд становится свежим по времени, а не по границе волны — именно то, что просили находки 1 и 11
аудита (обе MAJOR).

Три файла: движок `tools/lab/chronicler-debounce.sh` (вся логика), fail-open шим
`tools/hooks/chronicler-debounce-hook.sh` (то единственное, на что указывает settings.json), и две
записи в `.claude/settings.json` — дебаунс встал вторым хуком на уже существующие matcher'ы
`Bash` и `Write|Edit|MultiEdit`. Каждая пересборка оставляет строку `{"mode":"debounce",...}` в
`docs/lab/supervision/tick-ledger.jsonl` — журнал, который GSL-199 сделает общим для всего мотора.

## Problems solved

- **«git status ловушка».** В этом репозитории `docs/lab/events/*.jsonl` перманентно грязный, так
  что ВЫВОД почти любой git-команды упоминает `docs/lab/`. Наивный substring-матч по всему payload
  превращал бы каждый `git status` в пересборку. Решение двухступенчатое: грубый bash `case` по
  всему payload как быстрый ОТКАЗ (95% вызовов уходят без единого спавна процесса), затем точная
  python-проверка ТОЛЬКО по `tool_input` (file_path/command/edits/content) — `tool_response` не
  считается. Это то же самое разделение, что выстрадал lab-log в GSL-83: упоминание — не действие.
- **Самовозбуждение.** Летописец сам пишет в `docs/lab/` (site/, status.json, render_bundle) — но
  из фонового процесса, не через tool call, так что хук не срабатывает и петли нет. Паттерны
  триггера сознательно НЕ матчат `chronicler.sh`/`tick.sh`/`smoke.sh`.
- **Дебаунс, который нельзя заморить.** Чистый trailing-edge дебаунс при непрерывных записях не
  сработал бы никогда. Добавлен потолок `GOSLEEP_DEBOUNCE_MAX_WAIT` (600 c): пересборка случается
  не позже потолка, даже если лаборатория пишется без пауз.
- **Один ожидатель, переживающий смерть.** mkdir-лок с heartbeat (touch на каждом витке цикла):
  второй триггер видит живой лок и не плодит второго ожидателя; лок без heartbeat дольше
  `MAX_WAIT+QUIET+120` c считается трупом и крадётся.

## Problems remaining

- Между финальной проверкой ожидателя и снятием лока есть окно в миллисекунды, где новая запись
  увидит занятый лок и не взведёт нового ожидателя. Цена — один пропущенный дебаунс; страховка —
  ровно tick.sh (GSL-199), чья задача «летописец, если дебаунс не сработал».
- Реальный прожиг «Claude Code диспатчит PostToolUse → шим» для нового хука доказан транзитивно:
  синтетика гоняется через настоящий шим, а факт диспатча на этих же matcher'ах доказывает
  существующий real-run лег hooks-verify (vcs.commit через lab-log). Отдельного claude -p прожига
  для дебаунса не делал — минута реального прогона за проверку, которую покрывает сосед по matcher.

## Pitfalls & workarounds

- **settings.json перечитывается на лету.** Правка хуков бьёт по ЖИВОМУ флоту немедленно. Порядок
  работ был жёсткий: сначала движок + герметичные тесты в песочнице, потом шим, потом `jq .`
  валидация, и только затем запись в settings.json. Шим — точная копия доктрины lab-log-hook.sh:
  четыре строки, всегда exit 0, stderr в `.artifacts/lab/chronicler-debounce.err` (bash-синтаксис
  с exit 2 в протоколе хуков означает БЛОКИРОВАТЬ tool call — это уже замораживало флот 2026-07-12).
- **Ложный триггер дешевле пропущенного.** Правка `tools/lab/lab-emit.sh` (сам файл писателя, не
  запись в лабораторию) тоже взводит дебаунс — сознательно: цена ложного срабатывания — одна
  идемпотентная пересборка за 0 токенов; цена пропуска — устаревший дашборд.
- **Sleep-петля, а не launchd.** Ожидатель — обычный disowned фоновый процесс: живёт пока жива
  машина, не переживает перезагрузку и не тикает во сне. Это ОК: он страхует минуты между
  записями, а межсессионную регулярность несёт tick.sh на внешнем носителе (GSL-201).

## What didn't make it

- Отдельный real-run лег hooks-verify c claude -p специально для дебаунса (см. выше — покрыто
  транзитивно, дорого по времени гейта).
- Использование поля `if` в hook-правилах settings.json: на 2.1.207 задокументирована его
  двойная сработка (см. $comment в самом settings.json) — маршрутизация остаётся внутри скрипта.
