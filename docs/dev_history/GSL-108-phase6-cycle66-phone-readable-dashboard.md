# GSL-108 — phone-readable доставка дашборда (Phase 6, цикл 66)

**Задача:** `[Tooling][Docs]` закрыть **F5-S4c**, опровергнутый в Фазе 5.
**Ветка:** `GSL-102-mobile` · **Гейты:** smoke 276 → **285/285**, hooks-verify 14/14, `tsc` 0, chronicler 7 страниц.

## 1. Что было опровергнуто и что оказалось не так с опровержением

Фаза 5 (цикл 59) записала: дашборд с телефона через приватный GitHub **не читается**.
Измерения были верные и остаются верными:

* `raw.githubusercontent.com` → `Content-Type: text/plain` + `X-Content-Type-Options: nosniff`;
* Pages на приватном репо → 404 (нужен Enterprise Cloud);
* позитивный контроль: тот же raw отдаёт `text/plain` и для `README.md`.

Я воспроизвёл всё это первым делом — сходится до заголовка.

**Неверен был не замер, а вывод.** В `chronicler.py` (генератор `docs/lab/site/README.md`) он был
записан так:

> «There is no URL on github.com that renders these pages. **GitHub is a transport for the bytes, not
> a viewer.**»

Первое предложение истинно — для `.html`. Второе — обобщение шире собственных доказательств:
мерили `.html` и `raw`, а заключили про **GitHub**. Это обобщение и держало дыру открытой целую фазу,
потому что оно закрывает не тот путь, который был проверен, а все пути сразу.

## 2. Перемер (приватный репо, аутентифицированно, 2026-07-20)

| Что | Что вернулось |
|---|---|
| `.md` через Contents API (`Accept: html`) | `<article class="markdown-body">` — **отрендерено серверно** |
| `.html` через тот же API | `<pre class="plain">&lt;!doctype html&gt;` — **экранировано**, показан исходник |
| `README.md` папки (`GET /readme/<dir>`) | тоже рендерится |
| папка **без** `README.md` | `404` |

Последняя строка — негативный контроль, и он потребовал второй попытки: первый вариант я взял на
`docs/lab/events`, получил `200` и чуть не записал ложный вывод — **у этой папки README есть**.
Проверка диска перед выводом спасла контроль; переделал на три папки, где README действительно нет.

**Механизм:** `nosniff` никогда не управлял Markdown, потому что Markdown браузеру на интерпретацию
не отдают — GitHub рендерит его у себя и присылает готовый HTML. Препятствием был не приватный
репозиторий, а **расширение файла**. GitHub — и транспорт, и просмотрщик, в зависимости от того,
что ему дали.

## 3. Решение

`docs/lab/mobile/README.md` — проекция семи экранов, регенерируемая летописцем.

Три свойства, каждое несущее:

1. **Имя файла — это и есть механизм.** GitHub рендерит `README.md` при открытии **папки**, поэтому
   URL не содержит даты и переживает добавление в закладки. Дайджест эту роль взять не мог: он
   `<date>-morning.md`, то есть закладка, снятая сегодня, завтра ведёт в никуда — а телефон в 07:00
   ровно то место, где искать файл по имени невозможно.
2. **Собирается из `render_bundle.json`** — того же бандла, из которого рендерятся семь HTML-экранов.
   Поэтому это **вид** дашборда, а не второй дашборд: разъехаться неоткуда, схема `render/7` не
   тронута (я только читатель).
3. **Переживает смерть node.** HTML-экраны требуют node; эта страница нет — её пишет Python из
   бандла, который Python уже записал. Запись стоит **вне** ветки «рендер удался», иначе единственная
   поверхность, доступная из кровати, исчезала бы ровно в ту ночь, когда ломается сборка. И страница
   **говорит** читателю, что HTML рядом устарел.

Ссылки со страницы ведут только на `.md` и на папки: ссылка на `.html` открыла бы с телефона
экранированный исходник — тупик, замаскированный под пункт назначения.

## 4. Где я поймал себя на AI-слопе

Владелец в этот же день назвал текущий UI «AI-слопом». Первый прогон моей страницы был им же.
Прочитал вслух — и услышал четыре дефекта, из которых два содержательные:

* **«Latest decisions» печатал четыре самых старых решения.** `decisions.recent` приходит
  **oldest-first**, а я взял `[:4]`. Подпись прямо противоречила списку — то есть страница врала
  ровно в том месте, где обещала свежесть.
* **Решение печаталось как `d-2026-07-13-001 — q-2026-07-12-001`** — идентификатор, описанием
  которого служит другой идентификатор. Мой фолбэк `d.get("what") or d.get("re")` провалился в `re`,
  потому что поля `what` в записи нет вообще; настоящее поле — `decision`. На телефоне это хуже, чем
  отсутствие секции: стоит тапа и не сообщает ничего.
* **«101 unknown» первым номером** — сортировка по убыванию выносила вперёд отсутствие информации.
  Переставил на порядок доставки, а `unknown` отчитывается отдельно как разрыв измерения
  («столько пропустил опрос, а не столько задач простаивает»).
* **«in 0.46h»** — число, которое читатель должен досчитать сам. Теперь «28m».

Оба содержательных дефекта закреплены ⭐-тестами: фикстура решений охватывает 1900…2099, поэтому
любая несортированная нарезка кладёт вперёд не ту запись.

## 5. Тесты (⭐ = имеет мутанта, который краснит именно его)

| Чек | Механизм | Мутант |
|---|---|---|
| ⭐ имя файла | страница именно `mobile/README.md` — иначе открытие папки её не рендерит | переименование → красный |
| ⭐ производность | несёт `generated_at` **этого** прохода (сверка со `status.json`) | зашитая строка → красный |
| ⭐ только рабочие ссылки | ни одной ссылки на `.html` | вставка `.html`-ссылки → красный |
| ⭐ «latest» значит latest | первым идёт `NEWEST-DECISION-TEXT` из фикстуры 1900…2099 | `recent_dec[:4]` → красный |
| ⭐ решение читается как решение | печатается `decision`, не `re` | `d.get("re")` → красный |
| ⭐ переживает no-node | node срезан из `PATH`: HTML → `ui.reason=no-node`, страница написана и свежа | запись внутрь ветки «рендер ок» → красный |
| ⭐ и говорит об этом | на странице предупреждение про устаревший HTML | условие → `if False` → красный |
| PC ×2 | страница непуста и несёт 7 секций; no-node-фикстура действительно потеряла рендерер | — |

## 7. Готча

`tools/lab/chronicler.py` заканчивается `sys.exit(main())` **на уровне модуля**, без
`if __name__ == "__main__"`. Любой `import` запускает полный проход и пишет 12 файлов — я на это
наступил, пробуя протестировать генератор изолированно. Пострадали только derived-файлы (их летописец
и так перезаписывает), суверенные не тронуты. **Следствие:** юнит-тест импортом невозможен, проверять
только подпроцессом в throwaway-репо — как и делает весь `smoke.sh`.
