# GSL-201 — Преflight носителя тика: launchd против Claude Desktop scheduled tasks

## What was done

Подготовил всё для контрольной preflight-ночи обоих носителей — так, чтобы её запуск был одним
действием владельца (d-2026-07-28-005), а утро давало таблицу фактов для развилки вопроса 5
(d-2026-07-28-003: основной — тот, который фактически тикал; launchd остаётся страховкой).

Четыре артефакта в `tools/lab/preflight/` и рядом:
- **`com.gosleep.tick.plist`** — шаблон LaunchAgent (`__REPO__`-плейсхолдер): каждые 300 секунд
  `tick.sh --carrier launchd --quiet`, `RunAtLoad` как догоняющий тик после логина/загрузки,
  stdout/stderr в `.artifacts/lab/`.
- **`preflight-arm.sh`** — ОДНА команда владельца: рендерит plist абсолютным путём этого чекаута,
  `plutil -lint`, `launchctl load -w`, печатает дословную инструкцию для второго носителя
  (scheduled task в Claude Desktop — из шелла его не вооружить, это клик-путь в приложении) и как
  читать вердикт утром.
- **`preflight-disarm.sh`** — откат: unload + удаление plist, напоминание про Desktop-задачу.
- **`tools/lab/tick-preflight-report.sh`** — утренний отчёт: по каждому носителю из
  `tick-ledger.jsonl` — тиков всего, «тикал ли НОЧЬЮ» (окно 03:00–06:00 локального — интервал,
  в честь которого система названа и который аудит нашёл пустым), первый/последний, максимальная
  пауза и первый тик после неё («что случилось после пробуждения»), idle/ошибки. Таблица
  по-русски (адресована владельцу, d-2026-07-28-006), `--json` для машин.

## Problems solved

- **Как сравнить носителей одной ночью, не смешав их следы.** Каждый носитель штампует себя в
  строку леджера через `--carrier` (launchd / desktop; поле заведено в tick.sh ровно под это).
  Отчёт группирует по штампу — одна ночь, два ряда фактов, ноль ручной археологии.
- **«Ночью» — в чьей таймзоне.** Леджер в UTC, ночь владельца — локальная. Отчёт конвертирует в
  локальную зону машины и судит окно 03–06 по ней; окно переопределяется `--night HH-HH`.
- **Смок для того, что нельзя запускать.** launchctl — руки владельца, поэтому smoke доказывает
  то, что доказуемо без установки: шаблон линтуется, рендер `__REPO__` даёт линтуемый plist без
  плейсхолдера (ровно то, что установит arm), arm/disarm парсятся, а отчёт читает синтетическую
  ночь (launchd тикал 03:30–03:55, desktop только в полдень) в правильный повердиктный JSON.

## Problems remaining

- Сам ночной preflight НЕ проведён — и не должен был: дата — за владельцем (d-2026-07-28-005).
  Запуск: `bash tools/lab/preflight/preflight-arm.sh` вечером + создать Desktop-задачу по
  напечатанной инструкции; утром `bash tools/lab/tick-preflight-report.sh`.
- Desktop scheduled tasks на этом аккаунте не проверялись (аудит, вопрос 5) — инструкция написана
  по общей механике приложения; если UI задач в текущей версии называется иначе, шаги придётся
  подстроить на месте (сама команда тика от этого не зависит).
- Честная цена Desktop-носителя: каждая сработка — маленькая агентская сессия, т.е. токены
  тратятся на обёртку даже при idle-тике. Это не дефект, а измеряемое свойство — ровно то, что
  preflight сравнивает.

## Pitfalls & workarounds

- **plist — шаблон, не готовый файл**: абсолютный путь чекаута нельзя коммитить (сломался бы на
  любом другом клоне), а launchd не понимает относительных. Рендер в arm-скрипте, плейсхолдер
  `__REPO__`, смок проверяет рендер.
- **`launchctl load -w` после `unload || true`** — идемпотентное перевооружение: повторный arm
  не падает и снимает возможный disabled-флаг от прошлого disarm.
- **Ночь держится на caffeinate владельца** — arm сознательно не трогает pmset/caffeinate
  (стоячее правило + preflight должен мерить РЕАЛЬНУЮ ночь, а не постановочную).

## What didn't make it

- Автоустановка Desktop-задачи (API для этого нет — только UI приложения).
- Отдельный сторож «носитель молчит» — это территория эпика GSL-178 (watchdog, наблюдательный
  режим по d-2026-07-28-001); отчёт preflight и так делает молчание видимым постфактум.
