## Часть 1 — человеческим языком

### Что сделано

Написан `docs/reports/verifications/README.md` — стандарт верификационного рана, который до
сих пор существовал только как прецедент (`GSL-138/runs/01/`). Зафиксировано всё из тикета:

- путь и нумерация `docs/reports/verifications/<EPIC-KEY>/runs/NN/` (ведущий ноль; раны
  итеративны, run 01 — исторический срез) и цикл «run N → разбор владельцем → фикс-волна →
  run N+1» с правилом: незакрытая находка обязана снова оказаться в пунктах следующего рана;
- структура рана деревом: `index.html` (EN, основной) + `ru/index.html`, `assets/`
  (styles.css, lightbox.js, листы), обязательная `design/` (снапшот страниц `design/pages/`
  + визуальный обзор дизайн-системы) — ран остаётся свидетельством и после того, как
  фикс-волна изменит исходные страницы;
- самодостаточность file:// (zero deps, без CDN и внешних шрифтов; дубликаты листов внутри
  рана — осознанная цена);
- нумерованные пункты с Jira-чипами («пункт без ключа — не находка»), английские константы
  статусов/severity в обеих локалях, обязательная секция «на что обратить внимание», секция
  гейтов с командами воспроизведения;
- запрет fullPage-«полотен»: только viewport-кадры 1280×800 и 390×844, обе темы, computed
  background перед затвором, именование `<страница>-<ширина>-<тема>.png`;
- разграничение с dev_history (односторонний поток копий; перекрёстная ссылка на GSL-142);
- эталон верификации в три слоя с порядком разрешения конфликтов: спека (GSL-112,
  `docs/design/ui-redesign-spec.md`) → одобренный снапшот последнего принятого рана →
  индустриальные нормы (WCAG, токен-консистентность, паттерны Mastra Studio / Supabase);
- независимость верификатора (свежие глаза, `verifier-skeptic`; регрессия прошлых фиксов —
  отдельная работа).

### Решённые проблемы

- **Откуда взялись «три слоя».** В тикете слои названы списком; порядок и правило разрешения
  конфликтов (спека бьёт снапшот, снапшот бьёт индустриальную норму, конфликт — материал для
  «на что обратить внимание») сформулированы здесь — без них слоёв три, а нормы ноль.

### Оставшиеся проблемы

- Слой 2 (одобренный снапшот) до первого owner-вердикта по run 01 пуст — первый ран, который
  владелец примет, и станет первым эталонным снапшотом.

### Подводные камни

- Структура эталонного рана описана с натуры (find по `GSL-138/runs/01/`), не по памяти
  переписки — README и факт на диске совпадают.

### Что не вошло

- Автоматизация сборки рана (скрипт-генератор структуры) — стандарт описывает формат, не
  инструмент; рендер остаётся за скиллом `agentic-report-creator`.
