# GSL-246 — Две дыры в .gitignore: своя и чужая

## Что произошло

В корне репозитория лежал каталог `.playwright-cli/` — 59 файлов вида
`page-2026-07-23T22-41-32-974Z.yml`. Это рабочий след браузерного инструментария: по одному
снимку на каждый взгляд на страницу, десятки за сессию QA.

Ни одной строки в `.gitignore` про него не было. Значит он постоянно висел в `git status` как
незакоммиченный мусор — и это не косметика:

- каждый следующий агент, открывающий `git status`, разбирал 59 лишних строк, прежде чем увидеть
  свою работу;
- один `git add -A` — и весь этот мусор уезжал бы в чужой коммит.

Второе особенно неприятно, потому что все эти файлы **воспроизводимы простым повторным открытием
страницы**. Хранить их в истории репозитория незачем никогда.

Теперь `.playwright-cli/` в `.gitignore`, с комментарием.

## Чужая правка, которую нельзя было откатить

В рабочем дереве `.gitignore` был уже изменён — не мной. Кто-то добавил строку:

```
.gstack/
```

последней строкой файла, без комментария.

Задача требовала разобраться и **не откатить чужое**. Разбирались так:

- **Каталог настоящий?** Да: `.gstack/` существует, внутри `browse-audit.jsonl` (журнал
  браузерного скилла gstack) и `claude-available.json` (проба возможностей). Файлы от
  инструментария агента, не от проекта.
- **Не скрывает ли игнор задним числом что-то уже закоммиченное?** Нет: `git ls-files .gstack`
  пуст, `git log -- .gstack` пуст. Каталог никогда не был в истории.
- **Правка завершённая?** По сути — да, запись рабочая и осмысленная.

Вердикт: не откатывать. Строка уехала этим же коммитом.

Но у неё было два изъяна оформления, и оба чинились без изменения смысла:

**Первое — она стояла не там.** Последней строкой файла, сразу под блоком про лабораторию:

```
# Hidden atomic-write temps: a chronicler killed mid-write (kill -9 = no cleanup)
# leaves one beside its target. lab-write sweeps them on the next pass; git never sees them.
docs/lab/.*.tmp
docs/lab/**/.*.tmp
.gstack/          ← читается как продолжение блока про docs/lab/
```

Визуально `.gstack/` попадала под комментарий про хроникёра и временные файлы лаборатории,
к которым не имеет никакого отношения.

**Второе — она была единственной записью в файле без комментария.** `.gitignore` здесь
документирует каждую свою строку: что это, почему игнорируется, что было бы иначе. Двадцать
записей с объяснением и одна без — это не стиль, это забытая правка.

Обе строки сведены в один блок с общим заголовком:

```
# Browser tooling runtime — written by the agent's own tools, never by the project.
# gstack's browse skill drops its audit log and a capability probe here.
.gstack/
# The Playwright CLI dumps one page-<timestamp>.yml snapshot per look at a page:
# dozens per QA session, all reproducible by looking again. Untracked they only
# lengthened `git status` for the next agent — and rode along on any `git add -A`.
.playwright-cli/
```

Перемещение строки — не откат: правило действует ровно так же, `git check-ignore` подтверждает.
Изменилось только то, что теперь понятно, зачем она.

## Что проверялось

Три вещи, потому что игнор-файл — это место, где ошибка тихая:

1. **Обе записи действительно работают** — `git check-ignore -v` называет файл и номер строки
   для каждой (`.gitignore:54` и `.gitignore:58`). Не «вроде добавил», а подтверждение от git.
2. **Ни один из путей не был закоммичен раньше** — `git ls-files` по обоим пуст. Это важно:
   если бы файлы уже были в индексе, `.gitignore` их бы не выкинул, а только замаскировал
   будущие изменения — самый коварный вариант, когда игнор «не работает», а почему, непонятно.
3. **Каталоги пропали из `git status --porcelain`** — то, ради чего всё затевалось.

## Что осталось

Ничего по этой задаче.

Наблюдение на будущее: оба каталога — след **инструментов агента**, а не проекта. Похожие
каталоги будут появляться и дальше по мере смены инструментария. Блок «Browser tooling runtime»
теперь есть, и следующую такую запись логично класть туда же, а не в хвост файла.

## Техническая справка

**Файл:** `.gitignore`, +8 строк (2 записи + 5 строк комментария + пустая строка-разделитель).

**Проверка:**

```
git check-ignore -v .gstack/ .playwright-cli/
  .gitignore:54:.gstack/          .gstack/
  .gitignore:58:.playwright-cli/  .playwright-cli/

git ls-files .gstack .playwright-cli     → пусто (ничего не закоммичено ранее)
git status --porcelain | grep -E 'gstack|playwright'  → пусто
```

**Содержимое игнорируемых каталогов на момент задачи:**

| Путь | Файлов | Что внутри |
|---|---|---|
| `.playwright-cli/` | 59 | `page-<ISO-метка>.yml` — снимки страниц браузерного CLI |
| `.gstack/` | 2 | `browse-audit.jsonl`, `claude-available.json` |

**Чужая правка:** строка `.gstack/` присутствовала в рабочем дереве до начала задачи (автор —
другая работа, не эта). Не откачена, включена в этот коммит, перенесена из хвоста файла в
именованный блок и снабжена комментарием. Смысл правила не изменён.
