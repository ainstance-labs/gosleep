# GSL-196 — README очереди: queue.jsonl нельзя читать построчно

Эпик GSL-175 «Гигиена за вечер», задача 4 из 7. Находка аудита 69 (вердикт PARTIAL).

## Что сделано

Раздел Reading в `docs/lab/questions/README.md` теперь НАЧИНАЕТСЯ с прямого запрета жирным:
«НЕЛЬЗЯ читать queue.jsonl построчно — только через lab-emit.sh list» — и объясняет механику,
из-за которой запрет существует: файл append-only, статус — свёртка исходной записи со всеми
последующими патчами (`re:` по id, последний побеждает), и наивный построчный читатель видит
исходные `status: "open"`, но не видит закрывших их патчей. Названо и живое доказательство из
аудита: сырой файл читался как «20 открытых» при фактических 0 — на этом споткнулись сами
аудиторы. Запрет адресован любому читателю: человеку с cat/grep, агенту, скрипту.

## Решённые проблемы

Формулировка «инструкция, а не пересказ»: до правки README описывал patch-семантику в схеме
записей (раздел про `status` и Patch records), но раздел Reading не говорил, что из этого следует
запрет сырого чтения — читатель, открывший файл «естественным» способом, узнал о свёртке уже
после того, как сделал неправильный вывод. Рекомендация аудита выполнена дословно: README
начинается с запрета в первом же читательском разделе, правильная команда названа.

## Оставшиеся проблемы

Нет. Запрет — документация; технически файл по-прежнему читается кем угодно (и это правильно:
он остаётся источником для `lab-emit`, а его схема — публичной).

## Подводные камни и обходы

Ничего кода не менялось — риск только в расхождении текста с фактическим словарём статусов, и
он снят соседней задачей GSL-191, где «закрыто» перестало быть списком строк и стало
`status != open`.

## Что не вошло

Механическая защита (например, комментарий-строка первой записью самого queue.jsonl) — файл
append-only и пишется только через lab-emit; вставка не-записи сломала бы читателей. Запрет
остаётся на уровне README, где живёт вся остальная схема.
