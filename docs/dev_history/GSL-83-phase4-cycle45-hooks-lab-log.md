## Part 1 — Рассказ

### Что сделано

Ночь теперь оставляет машинный след сама. Раньше единственным свидетельством работы были коммиты и
handoff'ы, которые пишет модель — то есть след существовал ровно настолько, насколько агент решил его
оставить. Теперь параллельно этому пишется событийный лог, за который модель не отвечает вообще:
хуки Claude Code дёргают скрипт, скрипт дописывает строку в `docs/lab/events/YYYY-MM-DD.jsonl`. Ноль
токенов, ноль сотрудничества модели. Агент может забыть, соврать, зависнуть или быть убитым — событие
всё равно записано.

Сделаны три вещи. **`tools/lab/lab-log.sh`** — единственный писатель событий: принимает hook-JSON на
stdin, нормализует в конверт `{ts, run_id, seq, actor, type, data, src}` и атомарно дописывает одну
строку. **`.claude/settings.json`** — тринадцать хуков, подключённых рядом со старым Stop-хуком
владельца (он остался первым и нетронутым): жизненный цикл сессий и субагентов, компакции, отказы
API, задачи, уведомления и `PostToolUse` на git/gh, файлы и Jira. **`tools/lab/hooks-verify.sh`** —
проверочный стенд, который поднимает **настоящий** headless-процесс Claude Code, заставляет его
сделать **настоящий** коммит и убеждается, что события появились сами.

У каждого события есть поле `src`: `hook:<Имя>` для механических, `emit` для семантических (GSL-84),
`poll-fill` для дописанных постфактум (GSL-87). Это провенанс: критерий фазы F4-S1 («события пишутся
без кооперации модели») можно не декларировать, а **доказать** — отфильтровав строки с `src=hook:*`.

### Какие проблемы решены

Главная проблема была заявлена в PRD как риск ещё до начала работы: **хуки могут не срабатывать так,
как написано в документации**. Требование к циклу было жёстким — проверять фактическим прогоном, а не
верой в доки. Это требование окупилось пять раз: ровно пять багов не были бы найдены статической
проверкой, и каждый из них давал молчаливо неправильный лог.

**Первый — хук, который «работает» и не пишет ничего.** Скрипт был написан по образцу `lab-emit.sh`,
через идиому `exec python3 - <<'PY'`. Но `python3 -` читает **программу из stdin**, то есть heredoc
и *есть* stdin — а хуковый payload, который Claude Code подаёт именно на stdin, съеден до старта
программы. `lab-emit` этим не страдает, потому что читает только argv. Отказ абсолютно бесшумный:
пустой stdin → чистый выход с кодом 0 → ни ошибки, ни события, никогда. Ни один errlog бы не помог —
исключения-то не было. Лечится захватом heredoc'а в переменную в субшелле и запуском через `python3 -c`.

**Второй — сломанный скрипт блокирует весь флот.** Пока файл был на середине правки, bash упал с
синтаксической ошибкой и вернул **exit 2**. А в протоколе хуков Claude Code **exit 2 означает
«заблокировать операцию»**. То есть недописанный `lab-log.sh` заблокировал в живой сессии каждый
Write/Edit. И это не теория — так и произошло, прямо посреди задачи. Внутренний fail-open на python
бессилен: bash умирает раньше, чем python стартует. Ответ — `tools/hooks/lab-log-hook.sh`: шим на
четыре строки, единственное, на что смотрит `settings.json`, который всегда возвращает 0. Поломка
логгера теперь деградирует лог, а не останавливает доставку — тот же принцип, который PRD требует от
летописца (F4-S3).

**Третий — фантомные события.** Матчер `if:` в конфиге (он существует с v2.1.85) на живом прогоне
повёл себя не так, как ожидалось: два правила `if` под одним matcher'ом сработали **оба** на один
вызов (одно действие → два события), а `Bash(git *)` пропустил команду, которая лишь *упоминала* git
внутри строки. Мой собственный матчер был не лучше: он искал подстроку где угодно в команде. Итог —
в реальном логе появился `vcs.pr.opened` на команду, которая никаких PR не открывала. Такой таймлайн
хуже отсутствующего: дашборд Фазы 5 будет строиться на выдумках. Вылечено полностью: `if` убран (один
хук на Bash — максимум одно событие), а разбор команды переписан честно — вырезаются тела heredoc'ов
(их содержимое это **данные**, а не скрипт), строка режется по строкам и токенизируется через `shlex`,
который уважает кавычки. Теперь `echo "не забудь git commit"` не порождает коммита.

**Четвёртый — и его нашёл только живой прогон.** Синтетические тесты я писал тем же умом, что и код,
с той же слепой зоной: везде фигурировало `git commit`. А настоящий Claude Code выполнил
`git -C <путь> commit ...` — глобальная опция стоит **между** бинарём и подкомандой, и префиксный
матч её не пережил. Коммит был реально сделан — и не записан. Разбор verb'а научился перешагивать
глобальные опции git/gh.

**Пятый — нашёл догфудинг, на собственном коммите этой задачи.** Извлечение sha держалось на том, что
git печатает `[ветка 1a2b3c4] тема`. Но коммит делался с `-q` — git не напечатал ничего, и первое же
событие слоя о его собственном рождении получилось наполовину ложью: `vcs.commit` с пустым sha, то
есть строка таймлайна, которая никуда не ведёт. Теперь при пустом эхе sha спрашивается у самого git
(`rev-parse --short HEAD`, с учётом `-C`), а стенд отдельно проверяет именно тихий коммит.

### Что осталось нерешённым

**Не все хуки удалось проверить фактическим прогоном** — и это записано честно, без зелёных галочек
там, где их нет. Живым процессом подтверждены `SessionStart`, `Stop`, `SessionEnd` и `PostToolUse`
(последний — с настоящим коммитом, sha в логе совпал с тем, что git реально создал). Остальные
подключены, их разбор payload'а покрыт юнит-тестами, но **заставить их случиться стенд не может**:
`StopFailure` требует настоящего rate-limit от API, `PreCompact`/`PostCompact` — настоящей компакции,
`Notification` — запроса разрешения, `TeammateIdle` — простоя teammate'а в сессии оркестратора.
Скрипт `hooks-verify.sh` перечисляет их отдельной секцией «подключены, но не проверены здесь» —
чтобы зелёный отчёт не подразумевал больше, чем доказал.

Практический способ добить: следующий цикл просто грепает `docs/lab/events/` на `agent.idle`,
`context.pre_compact` и `api.failure` — за ночь работы флота они либо появятся сами, либо не появятся,
и это будет ответ. **`TeammateIdle` — главный кандидат на разочарование** (его никто не проверял и в
PRD он помечен как непроверенный); если он молчит, замена — периодический опрос в пульсе.

Статус `docs/lab/events/*.jsonl` в git пока не решён — он появляется в дереве как untracked. Это
предмет GSL-85 (layout + `.gitignore` + дисциплина), там же лежит развилка «коммитить ли сырой лог».

### Ловушки и костыли

- **`exec python3 - <<'PY'` нельзя применять там, где нужен stdin.** В `lab-log.sh` над этим стоит
  большой комментарий с просьбой не «упрощать» обратно к идиоме `lab-emit`. Это не стилистика — это
  разница между работающим и молча мёртвым хуком.
- **Хуки не снапшотятся при старте сессии.** Документация подтвердилась: file watcher подхватывает
  правки `settings.json` **на лету**. Это удобно (проверять можно без рестарта), но означает, что
  правка конфига бьёт по **живому флоту немедленно**. Отсюда и шим, и жёсткий fail-open.
- **`exit 2` = «блокировать»**, и синтаксическая ошибка bash тоже даёт 2. Любой скрипт, висящий на
  хуке, обязан быть за шимом.
- **Комментарий может завалить гейт.** Гейт C1 (`0 LLM-вызовов`) грепает файл на флаг headless-запуска;
  проза в docstring, упоминавшая его, честно уронила проверку. Гейт правильный — переформулирован
  комментарий, а не ослаблен гейт.
- Сознательное решение: **обычные вызовы инструментов событиями не становятся**. Логируются только
  значимые verb'ы (commit/push/pr/issue, Jira-переходы, запись handoff/dev_history). `tool.call` на
  каждый `ls` — это шум, который похоронит таймлайн. Всё, что отброшено, при `GOSLEEP_LAB_TRACE=1`
  видно в `scratch/hook-trace.jsonl` — так отличают «событие отброшено» от «хук не сработал».
- Неизвестный будущий хук пишется как `hook.unmapped` со всем payload'ом, а не отбрасывается: новое
  событие Claude Code должно всплыть как видимое «неизвестно», а не исчезнуть.

### Что не вошло

- **`async: true` не включён.** Семантика в доках не описана, а цена ошибки — тихо неработающий слой
  событий. Хуки быстрые (~50 мс) и fail-open; синхронный режим доказуемо работает. Включать имеет
  смысл только после отдельной проверки, что события при этом не теряются.
- **`if:`-фильтр не используется** (см. выше) — хотя он и сэкономил бы запуск процесса на каждом Bash.
  Отказ сознательный: корректность важнее ~50 мс, а на живом прогоне `if` повёл себя нестрого.
- **`tool.call` на все инструменты** — отброшено как шум (см. ловушки).
- `PermissionRequest`/`PermissionDenied` не подключены отдельно: `Notification` покрывает тот же
  сигнал одним хуком.

### Конверт

```json
{"ts":"2026-07-12T20:36:39Z","run_id":"2026-07-12","seq":2,"actor":"781cfb8b",
 "type":"vcs.commit","src":"hook:PostToolUse","data":{"cmd":"git -C … commit …","sha":"3c2563c"},
 "session_id":"…","agent_id":"…","agent_type":"…","cwd":"…"}
```

`run_id` = `$GOSLEEP_RUN_ID`, иначе дата UTC (одна ночь = один прогон = один дневной файл).
`seq` монотонен внутри файла; выделяется под mkdir-локом чтением хвоста (без sidecar-счётчика, который
мог бы разъехаться с файлом). Append-only: `O_APPEND` + один `write()`; коррекция — новая запись с
`supersedes`, файл никогда не переписывается. Кап `GOSLEEP_LAB_MAX_LINES` (50000) от рантаway-цикла:
на капе пишется один маркер `lab.capped`, дальнейшие потери считаются в `scratch/` — потеря обязана
быть видимой.

### Карта хуков → события

`SessionStart/End`→`pane.*` · `SubagentStart/Stop`→`agent.spawned|terminated` · `TeammateIdle`→
`agent.idle` · `Stop`→`agent.turn_ended` · `StopFailure`→`api.failure` (`error_type` — питает
quota-детекцию Фазы 2) · `PreCompact/PostCompact`→`context.*` · `TaskCreated/Completed`→`task.*` ·
`Notification`→`notification.raised` · `PostToolUse`: Bash→`vcs.commit|push|pr.opened|pr.merged`,
Write/Edit→`handoff.written|dev_history.written`, `mcp__atlassian__*`→`tracker.issue.*`.
Скрипт знает карту целиком; `settings.json` подключает только то, что существует в этой версии.
