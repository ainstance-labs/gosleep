## Часть 1 — человеческим языком

### Что сделано

Владелец вводит новую систему приёмки: вместо «скриншотов в ветке» — профессиональный
**HTML-дашборд-отчёт**, итеративными ранами. Построен **ран 01** для приёмки редизайн-эпика
GSL-111 (PR #135 merged, main @ `77b3bd8`):

- `docs/reports/verifications/GSL-138/runs/01/` — самодостаточная папка: `index.html` (EN,
  основной) + `ru/index.html` (русская версия) + `assets/` (стили, лайтбокс, 28 скриншотов).
  Открывается локально по `file://`, zero dependencies, светлая и тёмная темы (OS-преференс +
  ручной переключатель), скриншоты в клавиатурном лайтбоксе.
- Рендер по скиллу `agentic-report-creator` (шаблоны Vercel/Linear-эстетики): **19 пронумерованных
  пунктов**, каждый с Jira-чипом, severity-бейджем и статус-чипом (LANDED / PARTIAL / NOT-LANDED):
  10 закрытых MAJOR (было/стало + гейт + живой прогон), 5 попутных MINOR, 4 открытых MINOR как
  известные ограничения рана.
- Главная секция для владельца — **«На что обратить внимание»**: где смотреть (7 страниц +
  мобильная md-проекция, обе темы, 390px) и честный список спорных решений: табы вместо сайдбара
  (`q-2026-07-20-008`), кап 34ch+`break-word` в таблицах вместо `anywhere` (`theme.ts:263`,
  несущий комментарий `:248`), span-scope статусных цветов (GSL-124), CVD-ограничение светофора
  (red↔green ΔE 4.2, мера — слово рядом с цветом), расхождение папки скриншотов с текстом тикета
  GSL-138 (находка финализатора).
- Секция **Gates & verification**: таблица до/после (smoke 312→358/0, tsc 0, chronicler 7,
  hooks 14/14, схема `render/7` цела) + команды воспроизведения + протокол скриншотов (28 листов,
  computed background перед каждым затвором, 14 различающихся sha256-пар).
- Галерея: 7 страниц × 4 листа (1280/390 × light/dark) в лайтбоксе.

Ошибки, которые владелец отметит по этому отчёту, становятся входом `runs/02`.

### Решённые проблемы

- **Факты — только из файлов и Jira, не из брифа по памяти.** Каждое утверждение отчёта сверено:
  34ch подтверждён кодом (`theme.ts:263`), список 10 MAJOR / 5+4 MINOR — сводным dev_history
  GSL-111 **и** живым JQL-чтением Jira. Важное расхождение с текстом GSL-111-файла: там
  «8 MAJOR ещё в To Do» — на момент рана Jira уже показывает массовый Done (после вердикта
  эпика), открытыми остались ровно 118/122/123/132. Отчёт отражает актуальное состояние доски.
- **Термины не переведены** (hard rule скилла): CRITICAL/MAJOR/MINOR, LANDED/PARTIAL/NOT-LANDED,
  functionality/design — английские константы в обеих локалях; инвариант «текст бейджа ==
  data-severity» проверен скриптом в живом браузере на обеих страницах.

### Оставшиеся проблемы

- Открытые MINOR (GSL-118/122/123/132) — это содержимое секции «известные ограничения рана 01»,
  не долг этой задачи; уходят в бэклог до следующего рана.
- `assets/` отчёта дублирует 27 МБ скриншотов из `docs/dev_history/assets/GSL-138/` — осознанно:
  самодостаточность отчёта (требование владельца) важнее веса репозитория. Исходники не тронуты.

### Подводные камни

- **Doc-комментарий шаблонов скилла — источник ложных срабатываний самопроверки.** Верхний
  `<!-- … -->` в `dashboard.html`/`ru-shell.html` перечисляет слоты (`{{SUMMARY_HTML}}` …) и
  запрещённые слова («Критично» …) — наивный греп по готовому файлу видит их и врёт. Лечение:
  вырезать комментарий при инстанцировании (`html.replace(/^(<!doctype html>\n)<!--[\s\S]*?-->\n/, "$1")`),
  после чего самопроверка чистая.
- **`loading="lazy"` ломает наивную проверку картинок**: сразу после загрузки страницы все
  `naturalWidth === 0`. Проверять битые src надо после форса `loading='eager'` + ожидания
  onload/onerror; 38/38 резолвятся на обеих страницах.
- **Второй аргумент `String.replace` с готовым HTML** — передавать функцией (`() => html`),
  а не строкой: в подставляемом контенте `$`-последовательности интерпретируются.
- Генератор — временный (`.artifacts/report-gsl139-run01/build.mjs`, gitignored): данные EN+RU
  в одном месте, обе версии собираются из одного источника и не могут разъехаться.

### Что не вошло

- Payload JSON как отдельный коммитнутый артефакт (контракт скилла) — данные живут в генераторе.
- Скриншоты мобильной md-проекции — в приёмочном наборе GSL-138 их нет (28 = только 7 страниц);
  проекция упомянута в «где смотреть» текстом.
- Автопрогон гейтов при генерации отчёта — числа взяты из приёмки GSL-138, не перепрогонялись.
