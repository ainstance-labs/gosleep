## Part 1 · Простыми словами

### Что теперь умеют два экрана

**Timeline** — лента событий, новые сверху, с четырьмя фильтрами: кто (actor), что (type),
насколько плохо (severity) и **чем это подтверждено** (src). Последний — не украшение: строка,
которую увидел хук, и строка, добытая сверкой постфактум, — разного веса, и фильтр по `src`
позволяет спросить «покажи только то, что машина видела своими глазами».

**Library** — один плоский кросс-индекс всех артефактов со ссылками, с фильтром по типу полки
и по тексту. Раньше это были пять отдельных списков; теперь это один индекс, потому что владелец,
который ищет «что мы писали про перерасход токенов», не обязан заранее знать, лежит это в reports
или в RCA.

### Три вещи, которые тут важнее самого фильтра

**1. Фильтр не имеет права прятать молча.** Это единственная причина, по которой у фичи вообще есть
рейка безопасности. Дашборд с включённым и забытым фильтром выглядит как пустая ночь — а от этого
враньё Фаза 4 избавлялась целый цикл. Поэтому: как только скрыта хотя бы одна строка, страница пишет
словами «23 из 200 показаны — 177 скрыто фильтром». А если фильтр спрятал **всё** — предложение
меняется и краснеет: «0 из 200 показаны — фильтр скрывает все строки». Пустой таблице не позволено
говорить за себя.

По той же причине фильтр **не сохраняется**: ни localStorage, ни хеш в URL. Каждое открытие страницы
начинается с полного списка. Фильтр, переживающий перезагрузку, — это та же ловушка, но с памятью.

**2. Неизвестное событие — «unknown», а не «info».** У события в этой лаборатории **нет** поля
severity и никогда не было. Значит severity выводится из типа, по таблице. Соблазнительная форма —
«инцидент, иначе рутина» — врёт ровно в ту сторону, которая стоит ночи: добавь завтра в эмиттер
`breaker.tripped`, и такая таблица покрасит падение флота в зелёный, в той самой колонке, которую
владелец просматривает в поисках красного. Поэтому неизвестный тип — громкий `unknown`, никогда не
`info`. А чтобы «таблица может отставать» не превратилось в тихую течь, в smoke стоит проверка:
все 42 типа, которые умеют писать эмиттеры, обязаны быть в таблице.

**3. Инцидент отмечен в разметке, а не скриптом.** Владелец читает эту страницу с телефона через
приватный GitHub, где наш JS не выполняется вообще. Маркер, который появляется только после JS, —
это маркер, отсутствующий ровно там, где страницу читают в 02:00.

### Что оказалось неправдой в задании

**`chronicler.py` уже не рендерил эти страницы.** Описание Jira (и бриф цикла) требовали удалить
`build_timeline` и `build_library`. Их нет: они были удалены ещё в `6b4cbed` (GSL-92), когда весь
view переехал в TS. Описание Jira писалось до GSL-92 и с тех пор устарело. Проверено `git log -S`,
удалять было нечего — пункт приёмки закрыт до этого цикла.

**Настоящая дыра Library была в другом месте.** `docs/reviews/` (9 файлов), `docs/research/` (11) и
все incident-разборы **не индексировались вообще** — `library_index()` про них просто не знал. PRD
называет их поимённо. Это и была работа.

### Пустая полка обязана доказать, что искала

Каждая секция Library печатает **свой glob** прямо на странице. «Инцидентов нет» и «мне показали не ту
директорию» — противоположные факты, которые выглядят одинаково пустыми, если не сказать, где искали.
Директории `docs/rca/` в репо нет; разборы лежат под `docs/reports/` и названы по делу — секция
находит их по имени и печатает, каким именно шаблоном. Владелец может вставить его в шелл и проверить
за страницей домашнюю работу.

### Ключевые решения

**Остров — единственный способ доставки данных в браузер.** `readJson(id)` + `<script
type="application/json">` уже существовали (staleness verdicts). Второй способ не изобретался.
`fetch()` соседнего файла из `file://` запрещён CORS — страница обязана открываться с самолёта и с
телефона через GitHub blob.

**Одна свёртка — два потребителя.** `timelineIndex(b)` / `libraryIndex(b)` вызываются дважды: экраном
(для `<tr>`) и `render.tsx` (для острова). `rows[i]` ↔ `<tr data-row="i">` по конструкции, а не по
договорённости. Клиент **не читает отрендеренные ячейки** — фильтр, грепающий свой HTML, сопоставляет
картинку данных и ломается в день, когда в колонку добавят ссылку.

**Fail-open.** Если остров и DOM разошлись, строка без записи **остаётся**. Показать лишнюю строку —
видимый сюрприз, который читатель отбросит; спрятать нужную — невидимое вычитание из ленты, которую
он читает, чтобы узнать, что сломалось ночью.

**Схема `/4 → /5`** (DECISION `q-2026-07-13-004`, обратимость high). Добавлены **обязательные** поля
bundle → это ровно тот случай, ради которого версия схемы существует. Правка в четырёх местах разом.

### Мутационное тестирование (9 мутаций)

Ассерт, который не покраснел на сломанном коде, не охраняет ничего. **Каждый из 7 ⭐-тестов имеет
мутацию, которая красит ровно его:**

| мутация | краснит |
|---|---|
| M1 `severityOf` fallback `unknown` → `info` | ⭐ unknown ≠ info |
| M9 incident-класс убран только из разметки | ⭐ incident-маркер в HTML |
| M3 эмиттер получил тип, которого нет в таблице | ⭐ drift-guard (42 типа) |
| M8 остров грейдит всё `info` (разметка цела) | ⭐ сужение Timeline |
| M4 нулевой случай перестал говорить о скрытии | ⭐⭐ **тихое скрытие** |
| M5 fail-open → fail-closed | ⭐ строка без записи выживает |
| M7 Library-остров потерял фасет `kind` | ⭐ Library-фильтр |

M2 (все severity-классы убраны) и M6 (фильтр вообще не сужает) — широкие поломки, красят по 2–3
теста: больше поломка — больше сирен, это норма.

**Мутации нашли дефект в моём же тесте:** первая версия проверки Library-фильтра ассертила только
предложение-счётчик и осталась **зелёной** под M6, когда фильтр перестал скрывать что-либо вообще —
счётчик был прав относительно строк, которые все остались на экране. Добавлен ассерт `SHOWN`.

### Известные ограничения (сказаны на самих страницах, в blind-spots)

- severity выводится из **типа**, не из payload: `verify.verdict` с FAIL читается как `info`;
- счётчики «за все дни» берутся из `events`, а фид и его фильтр покрывают только `recent_cap` (200)
  строк, которые донёс этот билд;

  гонка по таймингу под нагрузкой. Проверено 3/3 зелёных и с моими правками, и без них. Не чинил.
