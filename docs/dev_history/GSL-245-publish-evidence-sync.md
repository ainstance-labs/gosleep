# GSL-245 — Снимок доказательной базы догнал источник, и README пришлось переписать

## Что произошло

Эпик GSL-169 несколько часов назад спас доказательную базу аудита из `.gitignore` — скопировал
материалы в трекаемый `docs/reports/system-audit-2026-07-24/evidence/`. Задача была правильная,
но снимок снимали **посреди работы**: аудит в этот момент ещё шёл, синтез-архитектор и третья
красная команда дописывали свои файлы.

Снимок устарел ещё до того, как отчёт опубликовали.

Расхождение с источником на момент этой задачи:

| Файл | Было в снимке | На самом деле |
|---|---|---|
| `SYNTHESIS.md` | 118 607 Б, промежуточная версия | 115 356 Б, финальная |
| `redteam-skills-verdicts.md` | нет | 64 319 Б — **третья красная команда** |
| `PRD-delta-draft.md` | нет | 78 565 Б — 18 операций правки PRD |
| `report-payload.json` | нет | 257 435 Б — машинная форма синтеза |

Теперь папка синхронизирована: двенадцать файлов, `diff -r` чист.

## Главное в этой задаче — не копирование, а одна фраза в README

Копирование заняло одну команду. Работа была в другом.

`evidence/README.md` — это не оглавление, а инструкция по чтению: GSL-171 написал её, чтобы
материалами не пользовались неправильно. И там был раздел с заголовком **«Чего не проверял
никто — читайте с осторожностью»**, который говорил:

> `skills-findings.md` **не проходил адверсариальную проверку**: он дописан в 22:06, позже первой
> красной команды (21:55), а второй достался веб. […] к меткам CRITICAL в этом файле стоит
> относиться как к непроверенным заявкам, а не как к фактам.

На момент написания — чистая правда. К моменту этой задачи — **ложь**, потому что появился
`redteam-skills-verdicts.md`: третья красная команда проверила ровно этот файл, все 25 находок.

Оставить фразу значило бы соврать читателю в сторону недоверия к уже проверенному материалу.
А поскольку README прямым текстом велит «сначала откройте вердикт», читатель, дошедший до пункта
«Для `skills-findings.md` вердикта нет ни у кого», просто не стал бы искать существующий файл.

Поэтому раздел переписан, и на его место встали два новых.

## Что теперь говорит README про скиллы

Третья красная команда дала результат, который стоит того, чтобы его пересказать здесь: он
меняет приоритеты плана развития.

- Из **пяти** меток CRITICAL не устояла **ни одна**: три понижены до MAJOR, одна до MINOR, одна
  развалилась целиком. Понижений всего пятнадцать.
- Единственное **повышение** — запрет `git stash` в общем дереве, которому аудитор поставил INFO.
  Красная команда подняла его: это единственный дорогой урок, у которого нет дома нигде, кроме
  памяти машины.
- По заказанному вопросу: заявлено, что скилл **в пяти местах приказывает нарушать правила
  владельца**. Настоящих противоречий **два** (ролл по самооценке контекста; Workflow tool без
  обязательного «спроси владельца»), и каждое чинится правкой одного абзаца. Одно — устаревание,
  а не приказ (скилл на 14 дней старше правила о моделях). Два разваливаются полностью: каденция
  пульса — потому что личный файл-урок владельца предписывает **ровно те же числа**, что и скилл;
  запрет читать транскрипт — потому что он адресован оркестратору про транскрипт *воркера*.
- Практическое следствие, записанное в README: **переписывание скиллов первым эпиком плана на
  этих основаниях не обосновано.** Обоснован другой первый эпик — процедура правки авторитетной
  копии плюс четыре точечные правки текста примерно на час.

Отдельно ценно, что эта команда проверила два предсказания аудитора эмпирически — по файлу
пульса за четыре дня (200 записей), которого аудитор вообще не касался. Оба предсказания
(«будет пульсировать не так, как ждёт владелец», «свалится в ролл на 70% — гарантированно»)
оказались ложными.

## Закономерность, которую теперь видно целиком

Раздел «Чего не проверял никто» не исчез — он изменил предмет. Раньше он предупреждал про
непроверенную панель. Теперь панелей с метками CRITICAL непроверенных не осталось, и вместо
предупреждения там стоит вывод:

**Из тринадцати меток CRITICAL не устояла ни одна.** Четыре по первой красной команде, четыре по
второй, пять по третьей. Три независимые проверки, три раза одна и та же картина: факты верны,
числа почти всегда воспроизводятся точно, а серьёзность завышена. Это уже не случайность
отдельного аудитора, а систематическая ошибка калибровки — и читатель должен знать про неё
прежде, чем начнёт верстать план по меткам.

Непроверенным осталось другое, и это в README сохранено: **шесть тем, которые не брал никто** —
права и безопасность агентов (в `.claude/settings.json` нет ни `allow`, ни `deny`), целостность
данных при параллельной записи нескольких агентов в одно дерево, отсутствующий потолок расходов,
поведение флота при исчерпании квоты посреди задачи, восстановление после выключения машины,
массовая смена версии CLI под работающей сессией.

## Ловушка: два файла в папке — не находки

`PRD-delta-draft.md` и `report-payload.json` приехали в папку доказательств, но доказательствами
не являются, и читать их надо иначе. В README добавлен раздел, который это разделяет:

- **`PRD-delta-draft.md` — черновик, который никто не применял.** 18 операций правки PRD, часть
  из которых (новые фазы 7 и 8, ограничение C9) прямо помечена «ждёт решения владельца». Это
  предложение, а не свершившийся факт. Показательно, что сам черновик уже пересмотрен после трёх
  калибровок: фаза 8 сократилась втрое, когда выяснилось, что противоречий два, а не пять.
- **`report-payload.json` — машинная форма того же синтеза**, вход генератора отчёта уровнем
  выше. Расхождение между ним и `SYNTHESIS.md` означает ошибку сборки, а не второе мнение.

Без этого разделения через месяц кто-нибудь процитирует черновик дельты как решение владельца.

## Что было важно не испортить

То же, что и в GSL-171: это свидетельство, а не рабочий документ. Ни один файл находок не
редактировался — только скопирован. Правился ровно один файл, `README.md`, и он единственный в
папке, который вообще разрешено править: он описывает папку, а не свидетельствует.

Это записано и в самом README, в пункте «файлы не обновляются»: сделано явное исключение для
README, иначе следующий агент упрётся в противоречие между правилом и фактом правки.

## Что осталось

Ничего. `diff -r` источника против снимка чист, единственное расхождение — `README.md`, которого
в источнике нет и быть не должно.

Если аудит когда-нибудь допишут ещё раз — синхронизировать тем же способом и **обязательно**
перечитать README на предмет утверждений, которые новый файл делает ложными. Эта задача — второй
случай подряд, когда снимок отстал; проверка README должна идти в комплекте с копированием.
