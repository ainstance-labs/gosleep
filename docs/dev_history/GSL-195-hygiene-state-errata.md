# GSL-195 — Эррата поправок красных команд для суверенного ORCHESTRATION-STATE.md

Эпик GSL-175 «Гигиена за вечер», задача 5 из 7. Находки аудита 54 и 94 (контекст калибровок).

## Что сделано

`docs/handoff/ORCHESTRATION-STATE.md` — суверенный файл (правит только владелец или оркестратор
смены), поэтому сам файл НЕ тронут ни байтом. Подготовлен точный, механически применимый текст
поправки — `docs/handoff/GSL-195-errata-orchestration-state.md`: две замены «старая строка →
новая строка» для телеметрийной строки `cycle=105 worker=audit-autonomy`, где записаны три
утверждения, снятые калибровкой первой красной команды ПОСЛЕ записи:

1. «13 из 19 дефолтов применены РАНЬШЕ дедлайна» → фактически 10 из 20;
2. «q-2026-07-23-001 в ту же секунду» → опровергнуто (сравнение шло со временем постановки,
   фактически −2ч до дедлайна);
3. «0 из 21 решения цитируют РЕАЛЬНО существующий пункт» → 3 цитируют выдуманный,
   ~8 — реальный раздел в неканоническом формате.

Стиль поправки — C8-дисциплина проекта: исправление не стирает историю. Опровергнутое число
остаётся видимым внутри маркера «[ПОПРАВКА …: было …]» со ссылкой на источник (строка `cycle=109`
в том же файле + `redteam-verdicts.md` в закоммиченной доказательной базе), но строка больше не
УТВЕРЖДАЕТ его. Эррата включает и раздел «чего в файле НЕ нашлось»: остальные три опровергнутых
числа калибровки («за три тика», «ctx=98 в 178 строках», «14 интервалов») в файле либо
отсутствуют, либо живут только внутри цитат-опровержений `cycle=109` — править нечего, и это
проверено грепом.

## Решённые проблемы

Точность замены: оба «старых фрагмента» сверены с файлом дословно (`grep -cF` → ровно по одному
вхождению каждого), так что применяющему не нужно ничего интерпретировать — замена механическая.
Формат «в файле нет опровергнутых чисел, рядом с каждым исправлением ссылка на источник» — это
дословно критерий приёмки задачи, и раздел «Как проверить» эрраты повторяет его грепами.

## Оставшиеся проблемы

Эррата НЕ применена — по построению: применение за оркестратором смены или владельцем. До
применения строка `cycle=105` продолжает нести опровергнутые числа.

## Подводные камни и обходы

- Дилемма «править историческую телеметрию нельзя (append-only дух) vs приёмка требует убрать
  опровергнутые числа» решена маркером поправки: число остаётся как цитата внутри «было …»,
  утверждение снимается. Обе нормы соблюдены.
- В новых фрагментах сохранено существующее написание якоря `manifest §2.default-hit-at-deadline`
  (это цитата уже существующего текста; правило «писать раздел N словами» — про новые тексты,
  существующее не переделывается).

## Что не вошло

Правка самой строки — за пределами полномочий исполнителя (суверенитет). Поправки для файлов
доказательной базы не нужны: они — свидетельство на дату, не живой документ (README базы это
фиксирует), и вердикты красных команд там уже лежат рядом с исходными находками.
