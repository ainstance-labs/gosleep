# GSL-88 — Хендофф сам объявляет себя таймлайну: одна строка, которую хук написать не может

> Фаза 4 (PRD «Laboratory / auto-doc»), эпик GSL-81, цикл 47, воркер impl-lab-3 (Opus 4.8).
> Требование R4.2 (ярус T2). PRD, Scope: «T2: существующие конвенции без изменений (+ **одна строка**
> `lab-emit handoff.written`)» — это буквально вся разрешённая правка яруса T2 за фазу.
> Коммит: `GSL-88 [Skill] handoff skill emits handoff.written semantic event on write`.

---

## Part 1 — Рассказ

### Что сделано

В `skill/handoff/SKILL.md` появился шаг 5 процедуры: после того как файл хендоффа лёг на диск, скилл
дописывает в событийный лог одну строку.

```bash
[ -x tools/lab/lab-emit.sh ] && tools/lab/lab-emit.sh event --type handoff.written \
  --data path="$FILE" --data nn="$NN" --data topic="$TOPIC" --data date="$(date +%F)" \
  --data resume="<the resume point, one line>" || true          # + --task <KEY> if it closes one
```

Тип `handoff.written` уже был в закрытом вокабуляре `lab-emit` (GSL-84 положил его туда с пометкой
«GSL-88»), так что задача — не «добавить тип», а **позвать его из конвенции**.

### Какие проблемы решены

**Хук видит файл, но не видит смысла.** `lab-log.sh` уже маппит `PostToolUse` (Write/Edit по пути
`docs/handoff/*.md`) в `handoff.written` — механически, за ноль токенов. Но всё, что он способен
положить в событие, — это `path`. Он не знает, **какой** это хендофф по счёту, **о чём** он и **куда
резюмировать** следующему агенту. Хук наблюдает *запись файла*; конвенция заявляет *смысл*. Поэтому
строка эмита несёт `nn`, `topic`, `date`, `resume` и (когда хендофф закрывает задачу) `--task`.

Оба события живут рядом и не конфликтуют: они различаются полем `src` (`hook:PostToolUse` против
`emit`) — ровно так, как задумано в `docs/lab/events/README.md`: «Все три [провенанса] — правда. Это
не один и тот же *вид* правды, поэтому они никогда не носят один ярлык».

Побочно это чинит и шум: хук срабатывает на **любой** `.md` под `docs/handoff/` — включая
`ORCHESTRATION-STATE.md`, который правится по многу раз за ночь. Строка эмита — единственный сигнал,
по которому потребитель может отличить «оркестратор поправил STATE» от «родился новый хендофф»:
`select(.type=="handoff.written" and .src=="emit")`.

### Что осталось нерешённым

Строку исполняет **агент**, а не машина, — значит она наследует надёжность яруса T2: агент, который
забыл её позвать, оставит хендофф без семантического события. Компенсация уже встроена в архитектуру:
хук всё равно запишет факт записи файла (`src=hook:*`), а расхождение «файлов в `docs/handoff/` больше,
чем строк `handoff.written` с `src=emit`» — это готовый диагностический запрос для летописца. Не стал
ловить это автоматикой в этом цикле: PRD прямо ограничивает ярус T2 одной строкой, и превращать
конвенцию в машинерию — задача уже другой фазы.

### Ловушки и костыли

**Скилл — глобальный, лаборатория — нет.** `handoff` установлен в `~/.claude/skills/` и работает в
репозиториях, где никакого `tools/lab/` не существует. Голый вызов там упал бы (или, хуже, оставил
после себя `command not found` в чужой сессии). Отсюда guard `[ -x … ] && … || true`: в репозитории без
лаборатории шаг 5 — тихий no-op, а не ошибка.

**Порядок обязателен.** В тексте шага явно: эмит — **после** того, как файл лёг на диск. Событие,
написанное раньше файла, — это заявка на хендофф, которого может не случиться (агент упал между
строками). Лог не должен утверждать то, чего нет; вся Фаза 4 — про это.

**Smoke — в отдельной lab-директории, и это не перестраховка.** Проверять эмит боевым вызовом означало
бы записать в живой `events/2026-07-13.jsonl` событие о хендоффе №26, которого в тот момент ещё не
существовало. Проверка прошла под `GOSLEEP_LAB_DIR=.artifacts/gsl88-smoke/lab`. Настоящее событие лог
получил позже — когда хендофф 26 был действительно написан.

### Что не вошло

Правка остальных конвенций T2 (dev_history, reviews) — PRD выносит это из скоупа явным «Изменение
T2-конвенций — они уже работают, не трогаем». `dev_history.written` хук пишет и так, и этого хватает:
у dev_history, в отличие от хендоффа, нет «точки резюмирования», которую стоило бы заявлять.

## Part 2 — Технический справочник

### Файлы

| Файл | Что изменилось |
|---|---|
| `skill/handoff/SKILL.md` | +шаг 5 процедуры (эмит после записи файла, с guard'ом); +строка в таблице Quick reference. Старый шаг 5 («Never put secrets») стал 6. |
| `~/.claude/skills/handoff/` | синхронизирован `./install.sh` (local → global, `rsync -a --delete` по именованной поддиректории). |

Правок в `tools/` нет: писатель (`lab-log.sh`), семантический слой (`lab-emit.sh`) и тип
`handoff.written` в `SEMANTIC_TYPES` существовали до этого коммита.

### Интерфейс

```bash
tools/lab/lab-emit.sh event --type handoff.written \
  --data path=<путь> --data nn=<NN> --data topic=<topic> --data date=<YYYY-MM-DD> \
  --data resume="<одна строка>" [--task GSL-N]
```

Пишет одну строку через `lab-log.sh` — единственного писателя `events/*.jsonl` (один аллокатор `seq`,
один лок, один конверт). `src="emit"`. Тип валидируется по закрытому списку `SEMANTIC_TYPES`: опечатка
в типе — это строка, которую никто никогда не прочитает, поэтому она ошибка, а не новый тип.

### Два события об одном хендоффе — и чем они отличаются

| | `src=hook:PostToolUse` | `src=emit` |
|---|---|---|
| Кто пишет | Claude Code hook на Write/Edit | сам скилл, шаг 5 |
| Стоимость | 0 токенов | уже оплачено (агент и так пишет) |
| Надёжность | механическая: сработает, даже если агент солгал/завис/убит | поведенческая: настолько же надёжна, насколько агент |
| Что несёт | `path` | `path`, `nn`, `topic`, `date`, `resume`, `task` |
| Срабатывает на | **любой** `.md` в `docs/handoff/` (в т.ч. `ORCHESTRATION-STATE.md`) | только на настоящий новый хендофф |

