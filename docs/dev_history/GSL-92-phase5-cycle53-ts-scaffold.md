# GSL-92 — TypeScript-скаффолд: view-слой уехал из Python, а вместе с ним уехало и право лаборатории соврать, что она свежая

> Цикл 53, `impl-ui-1`, Opus 4.8. Эпик GSL-90 (PRD Фаза 5), GitHub #105.
> Ветка `GSL-90-ui-orchestration`. Гейты: smoke **142/142** (было 130), hooks-verify **14/14**.

## Part 1 — Рассказ

### Что сделано

Появился `tools/lab/ui/` — весь видимый слой лаборатории на TypeScript + Preact, отрендеренный
статически на этапе сборки (esbuild). Python-код, который рисовал HTML, **удалён**, а не оставлен
рядом: `CSS`, `esc`, `src_class`, `VERDICT`, `STALENESS_JS`, `page`, `html_events_table`,
`build_index`, `build_timeline`, `build_library` — минус 290 строк из `chronicler.py`.

Между слоями ровно один артефакт — `docs/lab/render_bundle.json`. Python читает три тира, сворачивает
superseded-строки, считает все числа и складывает их в bundle. TypeScript берёт bundle и печатает
семь (пока три) страниц. Больше они друг о друге ничего не знают.

Chronicler зовёт рендерер сам (`render_site()`), а не через `chronicler.sh` — потому что результат
рендера обязан попасть в `status.json` (`ui.ok`, `ui.reason`, `ui.last_success_at`), а `.sh` — это
`exec python3` в одну строку и никакого места для отчёта у него нет.

### Какие проблемы решены

**Два рендерера одной правды — это дрейф, и он уже случался.** В цикле 50 баннер свежести
переоценивал себя при открытии страницы, а фраза под ним оставалась замороженной на момент сборки —
и страница выходила с красной плашкой **DEAD** над предложением «Live — the laboratory is writing
itself right now» (REVIEW-gsl81 M1). Это не небрежность конкретного коммита, это то, что два
рендерера производят всегда. Поэтому переезд, а не сосуществование: словарь вердиктов теперь один
(`src/verdicts.ts`), сервер печатает из него прозу, клиент из него же переоценивает — разойтись им
негде.

**node стал зависимостью build'а — и не стал новым способом умереть в 03:00.** Слой данных остался
`python3` + stdlib и о node не знает. Если node нет, если `npm install` не запускали, если esbuild
упал — chronicler всё равно регенерирует `status.json`, лог и утренний дайджест, а поверх каждой
страницы, которую не смог пересобрать, кладёт красный баннер с датой последней удачной сборки.
Страницы при этом **сохраняются**, а не обнуляются. Честно-несвежая страница — это продукт;
свежая на вид вчерашняя — это провал.

Баннер идемпотентен в обе стороны: пара маркеров `<!--UI-DEGRADE-START--><!--UI-DEGRADE-END-->`,
Python заменяет то, что между ними, а следующий удачный рендер пишет пустую пару обратно. Warning,
переживший свою причину, — это warning, который владелец учится пролистывать.

**Позитивный контроль вскрыл три холостых теста — и они были холостыми ещё в Python.** Фикстура smoke
кладёт события на 20 часов назад (чтобы grade вышел `dead`), то есть на *вчера*. Экран Timeline
показывал только `day_events` за сегодня → таблица пустая. А три проверки C8 («superseded-событие не
отрендерено») грепали HTML на **отсутствие** строки — и проходили на пустой странице. Три зелёные
галочки над ничем.

Починено по существу, а не подгонкой теста: Timeline стал сквозной лентой (`recent_events`,
cross-day), какой его и просит PRD R5.2 («feed newest-first»). Заодно это чинит реальный дефект
продукта — таймлайн, пустой в 00:05 и пустой всё утро после тихой ночи, неотличим от мёртвого слоя
хуков. И добавлен сам позитивный контроль: **живой sha обязан быть на странице**, иначе все
греп-на-отсутствие ничего не значат.

### Что осталось нерешённым

- **Экранов три, а PRD просит семь.** Overview / Timeline / Library есть; Tasks / Questions / Fleet /
  Cost — за GSL-93. Навигация намеренно перечисляет только существующие: ссылка на ненаписанную
  страницу — это 404 на телефоне в 03:00, первая ложь дашборда о себе.
- **`no-deps` покрыт кодом, но не тестом.** Тест потребовал бы прятать живой `node_modules` — слишком
  инвазивно для smoke. Путь разделяет ту же машинерию `fail()` + баннера, что и `no-node`, который
  покрыт полностью (включая round-trip: сборка → node исчез → баннер → node вернулся → баннер ушёл).
- **Скриншот-проверка light/dark на ширине телефона** — это гейт GSL-100, не этот.

### Ловушки и костыли

- **`chronicler.py` нельзя писать словами `tmux`, `spawn`, `teammate`, `Agent tool`.** smoke грепает
  файл на них (инвариант C5: летописец — ограниченная задача, не четвёртый живой агент, он не должен
  даже уметь занять панель). Это ловит и безобидное `spawn_cap` в имени переменной. Слоты флота в
  GSL-94 придётся называть без этого корня.
- **`--dry-run` рендерит, но не пишет.** Соблазн пропустить рендер в dry-run велик и неверен: тогда
  `--dry-run` отчитается «ok» о проходе, чей рендерер упал бы. Работу придерживает не рендерер —
  запись придерживает Python (`lab_write` коротит).
- **node не получает файловую систему вообще.** `build.mjs` читает stdin, печатает stdout. Все байты
  в репозиторий кладёт Python через `lab-write.sh` (temp + rename). Node, убитый на пятой странице,
  не может оставить рваный дашборд — ему нечем. smoke это и проверяет: `writeFile` в `build.mjs` =
  FAIL.
- **Клиентский бандл не минифицируется.** Он весит пару килобайт, лежит внутри файла, который
  владелец может открыть и прочитать, и smoke ассертит по его исходнику.

### Что не вошло

Утренний дайджест **остался в Python**. Он markdown для телефона в 07:00, а не экран, и обязан
собираться, когда node нет вовсе. Это не нарушение границы «view-слой = TypeScript» — это признание,
что дайджест не view-слой.

### Интерфейс

```bash
cd tools/lab/ui && npm install        # bootstrap, один раз на клон. Никогда не автоматически.
bash tools/lab/chronicler.sh          # данные + рендер
bash tools/lab/chronicler.sh --dry-run # рендерит (сбои всплывают), не пишет
bash tools/lab/ui/render.sh < docs/lab/render_bundle.json | jq .ok
(cd tools/lab/ui && npx tsc --noEmit)  # типы проверяются, никогда не эмитятся
```

`render.sh` → stdout, всегда JSON:

```json
{"ok":true,  "renderer":"preact-render-to-string (esbuild SSG)", "pages":{"index.html":"…"}}
{"ok":false, "reason":"no-node", "hint":"…"}
```

`reason` — закрытый словарь, синхронный с `UI_REASONS` в `chronicler.py`:
`no-node` · `no-deps` · `build-failed` · `bad-bundle` · `no-renderer`.
Он же приезжает в `status.json` → `ui`, в `degraded[]` и на баннер.

### Контракт `render_bundle.json`

`schema: "gosleep.lab.render/1"`. Несовпадение схемы — **ошибка сборки**, а не пустая карточка:
экран, читающий поле, которое producer перестал слать, в 03:00 выглядит как «ничего не произошло».

Лента событий **спроецирована** (`project_event`): `ts`, `seq`, `actor`, `type`, `src` + `data`,
суженная до ключей, которые реально печатает колонка detail (`sha`, `path`, `key`, `question`,
`error_type`, `decision`, `cmd`). Конверт несёт ещё `session_id`, `cwd`, `agent_id` и сырой payload
хука — ни один экран их не показывает, а bundle **коммитится**, так что каждый лишний ключ это вес и
нечитаемый diff на каждом проходе. Полный конверт не теряется: он в `docs/lab/events/*.jsonl`,
откуда всё это и выведено. Bundle 148K → **76K**, timeline.html 84K → **48K**.

Лента ограничена (`RECENT_CAP=200`, env `GOSLEEP_RECENT_CAP`). **Усечение объявляется на странице** —
кэп, о котором страница молчит, это ложь умолчанием: владелец прочитает последнюю строку как «начало»,
хотя это лишь начало того, что мы решили донести.

### Отклонение от брифа (осознанное)

Бриф отдавал удаление `build_index`/`build_timeline`/`build_library` в GSL-93. Удалено здесь: иначе
между 92 и 93 существует коммит с **двумя** рендерерами — ровно то состояние, чей дрейф эта задача и
приехала лечить. GSL-93 остаётся полноценной задачей: типизированный контракт на все 7 доменов,
4 недостающих экрана, навигация.

Расположение — `tools/lab/ui/`, а не `docs/lab/ui/`. `docs/lab/` — это **данные** лаборатории,
`tools/lab/` — её **код**; рендерер это код. Плюс жёсткая причина: smoke гоняет chronicler с
`--repo <throwaway>`, значит рендерер обязан находиться относительно скрипта, а не репозитория.
