# AutoSK Go CLI/TUI (`autosk lazy`) — internals (GSL-61, GH #70)

**Sources:** clone `.research-cache/autosk` @ `fd4c22e` (v0.2.4), Go side only: `cmd/` + `internal/` — 119 .go files, ~15.7k non-test LOC. Deep-read pass by Explore subagent (sonnet), key files spot-verified.
**Date:** 2026-07-10 · **Researcher:** res-anatomy · **Method:** static read only, nothing executed

---

## 1. Framework verdict

**gocui + lazycore (lazygit's own stack), NOT bubbletea** — `go.mod:8-9` pins `jesseduffield/gocui` + `jesseduffield/lazycore`; zero bubbletea imports anywhere. `charmbracelet/lipgloss` + `glamour` (go.mod:6-7) are used for styling/markdown rendering only, not the event loop. The package doc admits the lineage: *"the architecture still mirrors the lazygit shape (gui + state + arrangement + helpers + render) but in fewer files"* (internal/lazy/tui/gui.go:1-14) — deliberately one mutex-guarded state struct + 4 panels instead of lazygit's 35+ context tree.

## 2. CLI layer (`cmd/autosk`)

- One flat Cobra tree in `main.go:18-65`; global `--json` and `-q/--quiet` persistent flags (main.go:13-27) consulted by every render helper. Sentinel `errSilentExit1` (exit.go:9) → exit 1 without double-printing.
- **Every command is a thin RPC call**: `create`→`task.create(+block/enroll)` (create.go:13-90), `list`→`task.list` (list.go:15-74), `ready/next`→`task.list{status:new,blocked:false}` (ready.go:25-95), `done/cancel/reopen/update`→`task.*` (status_verbs.go), `session list/get/transcript/abort/input` (session.go:36-189), `workflow list/show`→`registry.workflow.*` (workflow.go:31-104), `enroll`/`resume` (enroll.go:13-51, resume.go:13-46), `comment add/list/edit/delete` (comment.go:19-155), `ext add/list/remove/update`→`extension.*` (ext.go:39-277), `metadata show/set/unset` (metadata.go:34-107), `lazy` (lazy.go:29-141).
- `version` probes the daemon best-effort with `NoAutoSpawn:true` + 1.5s timeout — "zero side effects" (version.go:65-80). No self-upgrade command; packaging is Homebrew's job.
- **Auto-init gate** (client.go:60-103 + autoinit.go): project resolved by walking up to `.autosk/` from `$AUTOSK_CWD`-or-cwd (projectdb.go:35-48). Missing project = hard error on READ verbs, interactive y/n prompt on WRITE verbs — and the prompt fires only if **both stdin and stderr are TTYs** (autoinit.go:24-26), with `$AUTOSK_NO_AUTOINIT` / `$AUTOSK_AUTOINIT_ASSUME_YES` escape hatches. Three-way branch: never prompt in a script, never silently create interactively, allow forcing both ways.

## 3. RPC client (`internal/daemon/rpcclient`, `internal/daemon/api`)

- **Framing:** one JSON object per line over UDS, integer-`id` correlation (client.go:70-94). **Fresh dial per call** — stateless transport, documented as a deliberate simplicity trade ("locally the connect cost is negligible", client.go:113-115). Socket: `Options.Sock` → `$AUTOSK_SOCK` → `~/.autosk/daemon.sock` (client.go:166-186). Every project-scoped request carries only `{cwd}` (client.go:144-155).
- **Auto-spawn** (connector.go): failed connect → `locate()` autoskd (explicit → `$AUTOSKD_BIN` → alongside own binary → PATH, connector.go:106-123) → `exec.Command(bin, "serve", "--sock", …)` detached with `Setsid:true`, stdio nil'd, `Process.Release()` (connector.go:63-74) → bounded poll 5s/25ms (connector.go:32-35,81-102). Cross-process double-spawn is harmless because the daemon single-instances on the socket (connector.go:16-20).
- **Errors:** typed `RPCError{Code,Message,Details}`; codes mirror `daemon/sdk/src/proto.ts` — `1001 ProjectNotFound, 1002 InvalidProject, 1003 NotFound, 1004 Conflict (retryable), 1005 EnvironmentDirty (retired, reserved-not-reused)` (client.go:82-110).
- **Streaming = two dedicated persistent connections**, separate from the per-call transport: `NoteStream` (`task.subscribe`+`project.subscribe`+`session.subscribeProject` demuxed into a cap-16 channel, notify.go:66-151) and `SessionStream` (`session.subscribe{id, from_line}` → `session-event` frames `message|status|done|error|partial`, cap-64 channel, stream.go:68-104; subscribe failure becomes a synthetic error frame, stream.go:138-145). **Reconnect is owned by the TUI, not the client** — one-shot subscriptions; `watchLoop` re-subscribes with capped exponential backoff 250ms→5s and forces a refresh on every reconnect (tui/gui.go:324-372).
- No default request timeout in the client — callers bring their own deadlines (client.go:122-124; e.g. refresh.go:56-59).

## 4. TUI architecture (`internal/lazy/tui`)

- **Setup** (gui.go:200-312): `gocui.NewGui{OutputMode: OutputTrue}` (24-bit color forced so the TokyoNight palette renders), `InputEsc`, `SupportOverlaps`, `Mouse=true`; single `SetManagerFunc(layout)`; `ErrorHandler` swallows `ErrUnknownView` mid-flush races instead of crashing (gui.go:295-300). A `Headless` mode drives the TUI through a tcell simulation screen for e2e tests (gui.go:36-40).
- **Layout** (arrangement.go, layout.go): a `boxlayout.Box` tree — 4 side panels (Tasks/Sessions/Workflows/Agents) in lazygit's **accordion** side stack (focused panel Weight 3, others 1; arrangement.go:168-181), Detail (Weight 3) + toggleable command-log (Size 8) right column, 1-row status bar + options strip. The session-input overlay is injected **manually** over Detail's bottom rows because boxlayout has no overlap support (layout.go:104-134). Views not in the current dims map are GC'd every frame (layout.go:143-157).
- **Update loop — push-first, poll-fallback:** `watchLoop` subscribes to daemon `task-changed`/`project-changed`/`session-changed` and calls `scheduleRefresh()` per notification, with a 30s safety resync (gui.go:321,340-372); the poll fallback `adaptiveTickLoop` **doubles its interval (cap 30s) whenever the last fetch took >½ the budget** — a circuit breaker born from a real "100%-CPU lazy" incident (gui.go:169-188,415-441). `scheduleRefreshWith` is CAS-coalescing: a refresh in flight flips a `pending` flag and the worker loops until it clears — the latest state always eventually renders, spam collapses to one trailing refresh (gui.go:504-546, explicit lazygit RefreshHelper parity gui.go:74-75). `refreshAll/fetchRefresh/applyRefreshLocked` split pure I/O from state mutation for testability (refresh.go:49-187). `spinnerLoop` ticks 100ms **only while a session is `running`** — idle dashboards burn zero cycles (gui.go:465-502).
- **Focus model:** `panelID` enum incl. a synthetic `panelSessionInput` focus identity so layout's `SetCurrentView` doesn't yank the caret out of the composer every frame (state.go:73-106); Esc-pop focus stack (state.go:530-543); lazygit's scrollOff margin-2 look-ahead on all cursor moves (gui.go:778-975).
- **Keybindings:** ONE registry `bindingSpecs()` (keys.go:81-366) drives `SetKeybinding` AND the `?` cheatsheet AND the bottom options-strip hints (keys.go:38-69,874-972; render.go:1244-1340) — help can't drift from reality. Highlights: `1..4/0/Tab` panel focus; `/` filter, `:` palette, `@` log toggle, `*` clear scopes; Tasks: `n/c/d/x/e/r/b/u/m/M/o`; Sessions: Enter=composer-or-detail, `K`=abort; composer: **Ctrl-D=steer, Ctrl-F=follow-up, Ctrl-A=abort**.

## 5. Screens & flows

- **Task list** (render.go:330-399): `[id(blue,10ch)] [marker(1ch)] [status(6ch,hue-coded)] [title]`. Status = pure color, no glyph: new=cyan, work=purple, human=yellow(Warn — "shares the workflow entity colour on purpose", render.go:91-94), done=green, cancel=gray (render.go:229-246). The 1-cell **session-presence marker**: animated 10-frame braille spinner (⠋⠙…) when a session runs for that task, static magenta `>` when sessions exist, blank otherwise (render.go:253,369-375). Session glyphs: `· queued ◐ running ◯ done ✗ failed ‣ aborted` (render.go:263-277).
- **Transcript view** (jobdetail.go + jobtranscript.go): per-session bounded cache (LRU 32 entries, 30s terminal TTL — state.go:15-21,449); a 2s debounce on live-subscribe so j/k-spam over running sessions collapses to one `StreamSession` (jobdetail.go:106-127); live pump coalesces bursts into ≤1 `g.Update` per **30ms** ("~30ms is what lazygit uses", jobdetail.go:249-297). Each transcript line renders as a rounded labeled box; assistant text through glamour markdown, tool-call-only turns collapse to a `→ ToolName` summary (jobtranscript.go:211-299). Perf discipline: boxes pre-rendered per event, joined once per frame (`joinedBody`, jobtranscript.go:167-202) + a body-equality short-circuit before touching gocui buffers (gui.go:1083-1145) — spinner frames stay O(1) on long sessions.
- **Sticky tail with intent preservation** (gui.go:1199-1318): transcripts open anchored at bottom, docs at top; auto-tail continues **only if the user was already at the bottom** — manual scroll-up is never yanked back.
- **Composer semantics:** input view exists only for non-terminal sessions (jobdetail.go:56-58); the draft's target session is **stamped on first keystroke** (`sessionInputOwner`, state.go:465-472; jobdetail.go:662-714) so a refresh-driven list reshuffle can't redirect an in-flight message to a different session. Comment = single-pane compose (Ctrl+S submits); task create/edit = lazygit-style two-pane summary+description; metadata editing **shells out to $EDITOR** on a temp JSON with gocui suspend/resume, then diffs at top-level-key granularity into set/unset calls (metadata.go:22-111,138-184).
- **Enroll/resume picker** (popup_enroll.go, keys.go:1190-1306): two-pane workflow/step picker; resume locks the workflow pane; picking the *current* step on resume routes to the status-only flip instead of a re-transition ("no-bump" CLI-parity rule, keys.go:1223-1246).
- **Popups** (popup.go, state.go:213-269): menu/confirm/prompt/composes/isolation-flip/enroll/cheatsheet/changelog, all through one `replacePopup()` chokepoint; the changelog auto-popup's "seen" stamp fires even when another popup replaces it (popup.go:38-53). Flash toasts: 4s, 3 levels, rendered in the command-log line (gui.go:565-589; render.go:1342-1363).

## 6. Render/support layer

- **Theme** (`internal/lazy/theme`): every swatch dual-encodes `{RGB, Hex}` for gocui (`NewRGBColor`) AND lipgloss; 13 semantic slots; default TokyoNight; `SetActive()` bumps a version counter that keys downstream style/renderer caches (theme.go:70-127).
- **Markdown** (`internal/lazy/markdown`): glamour themed from the palette; renderer cache keyed `(width, paletteVersion)` + 64-entry output LRU keyed `(md, width, paletteVersion)` (markdown.go:80-186). **Fail-open hardening:** 64KB input cap, 16-level blockquote cap (a real prior incident: "27 GB peak RSS for 100 levels", markdown.go:53-67), `recover()`-wrapped render that drops the poisoned cache and falls back to raw text — "a raw markdown string … is always preferable to a blank, crashed, or frozen TUI" (markdown.go:20-24,251-257).
- **No diff rendering anywhere**; `→ ToolName` lines are the entire tool-call visualization (jobtranscript.go:284-299).
- **timeformat**: single choke point for ALL operator-facing timestamps; wire formats stay RFC3339 UTC; "today" drops the date (format.go:1-11,61-92).
- **Support packages:** `internal/store` = type-only vocabulary, "v2 has no database in the Go tree" (store.go:1-5); `internal/projectdb` = client-side `.autosk/` walk-up mirror (48 lines); `internal/userstate` = `~/.autosk/state.json` (LastSeenChangelog) with tempfile+rename atomic write, 0600/0700, and malformed-JSON-surfaces-as-error-not-overwrite (userstate.go:73-78,117-164); `internal/id` = `ask-XXXXXX` crypto/rand ids with 16-attempt uniqueness retry; `internal/changelog` = go:embed CHANGELOG parser, fully fail-open ("a typo would crash every lazy start"), with a strict release-vs-dev classifier gating the what's-new popup (version.go:29-61); `internal/buildinfo` = 3 ldflags vars incl. hardcoded `Backend="autoskd"`.

## 7. Known-bug forensics (issues #7, #8)

- **#7 paste/dictation freeze:** no paste-specific handling exists anywhere (grep-verified). Most plausible mechanism: every textarea routes each keystroke through `gocui.DefaultEditor.Edit` + a full `withLock`→`g.Update`→layout→renderViews pass (jobdetail.go:599-610); a bracketed-paste burst of N chars = N full-dashboard redraws. The code itself flags the options-strip-per-redraw cost as fine "…if it ever becomes a measurable hotspot" (keys.go:71-80) — paste is that hotspot.
- **#8 enroll picker ignores chosen step:** no smoking gun found; nearest pinned bug class is popup z-order/stale-view races (popup_zorder_test.go:23-30; `pinOnTop` fix popup.go:418-431) — the enroll picker's two independently-`SetView`'d panes are exposed to the same class.

## 8. What gosleep's future admin TUI should steal (ranked)

1. **Push-driven redraw + 30s safety resync + TUI-owned reconnect backoff** (gui.go:321-372) — the whole freshness contract for a fleet dashboard in ~80 lines.
2. **CAS trailing-refresh coalescing** (gui.go:504-546) — never drops the final update under spam; strictly better than debounce for state dashboards.
3. **Adaptive poll fallback that backs off when the backend slows** (gui.go:169-188) — a dashboard must never DoS its own control plane.
4. **First-keystroke owner-anchored composer** (jobdetail.go:662-714) — in a multi-agent list that reshuffles under live updates, the input target must be authored, not cursor-derived. Directly applicable to "steer worker N" in gosleep.
5. **Single binding registry = keys + cheatsheet + options strip** (keys.go:81-366) — help that cannot drift.
6. **Live-tail perf recipe**: 2s subscribe debounce + 30ms event coalescing + pre-rendered-and-joined frames + body-equality short-circuit (jobdetail.go, jobtranscript.go, gui.go:1083-1145).
7. **Fail-open, capped markdown for agent-generated content** (markdown.go) — agent output is untrusted input to the renderer; crash-proof it.
8. **Intent-preserving sticky tail** (gui.go:1199-1318) and **spinner-only-when-running** (gui.go:465-502).
9. **Idle-cheap animated presence markers** — braille spinner in the task list tells "an agent is working here" at a glance in 1 cell (render.go:369-375).
10. **Anti-pattern to avoid:** partial frames decoded but unrendered (jobdetail.go:225-241 has no `case "partial"`) — autosk's TUI shows nothing during a long assistant turn while its GUI streams live; if gosleep builds a TUI, wire partials from day one (the daemon side already proves the protocol).
