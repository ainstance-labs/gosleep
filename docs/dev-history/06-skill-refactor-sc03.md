# 06 — REFACTOR скилла по слабым местам (SC-03 первым)

**Jira:** TLM-64 · **Статус:** ⏳ следующий · **Дата:** 2026-06-09

## Какую проблему решаем
Тест нашёл реальную дыру в скилле. На сценарии **SC-03 (оркестратора скомпактили посреди цепочки)**
GREEN = 0.67 — то есть даже со скиллом агент в трети случаев действует неправильно.

**Что именно идёт не так (из вердиктов судей):** агент объявляет файл состояния `ORCHESTRATION-STATE.md`
«отсутствующим» и сразу прыгает в live-проверки (git/gh), **вместо того чтобы сначала прочитать состояние
с диска** — например, самый свежий пронумерованный handoff. То есть скилл недостаточно чётко описывает
fallback «нет state-файла → всё равно сначала диск (последний handoff), и только потом live».

## План (это и есть TDD-REFACTOR)
1. Поправить раздел восстановления в `skill/SKILL.md`: явный шаг «нет ORCHESTRATION-STATE.md → читай
   highest-numbered handoff на диске ПЕРВЫМ; live-проверки — потом, для подтверждения».
2. `./install.sh` — обновить активный скилл.
3. Перегнать **только слабые сценарии** (дёшево) и убедиться, что GREEN(SC-03) вырос ≥0.8.
4. Добавить в список любые другие GREEN<0.8, которые покажет полный scorecard из 05.
