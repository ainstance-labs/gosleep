# 07 — Observability-harness: дизайн (web vs console)

**Jira:** TLM-66 · **Статус:** ✅ дизайн готов (билд позже) · **Дата:** 2026-06-08

## Какую проблему решаем
Хотим в будущем «профессиональный harness»: запускаешь команду — и в браузере видишь живьём, что
происходит (флот агентов, их статусы, как они общаются между собой, что создаётся в Jira/GitHub).

## Что зафиксировали (консультация)
- **Главный принцип:** сначала — стабильная **схема событий + единый append-only поток**; UI (любой) —
  это уже потребитель. Один лог событий даёт сразу live-просмотр, **replay прогонов**, audit-trail и
  фикстуры для тестов.
- **Транспорт:** SSE (просто, сервер→браузер) или WebSocket (если из UI ещё и управлять — пауза/kill).
- **Стек:** Next.js (он у нас уже есть) — приём событий + SSE + React-вью.
- **Рекомендация:** делать **web** поверх событийного потока; tmux-панели оставить как «сырой» вид. Для
  настоящего продукта — рассмотреть **Claude Agent SDK** (свой цикл → чистая эмиссия событий).

Подробно: `../design/event-schema.md` и `../design/web-harness-design.md`.
