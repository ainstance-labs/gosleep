Что спросил владелец и что мы выяснили

2026-08-03 · исследование

Владелец 24 июля 2026 попросил веб-админку, где можно смотреть отчёты, видеть индикаторы автономности, вопросы и задачи в одном месте, а в перспективе — оркестрировать с телефона. Проект построил профессиональный статический дашборд из семи страниц (docs/lab/site/*.html), но ни одной кнопки, которая что-то меняет в системе: клиентский код в 425 строк умеет только показывать. Решение об отказе от интерактивной версии приняли не обсуждением — оркестратор автоматически применил дефолт d-2026-07-28-004 28 июля, когда владелец не ответил на вопрос q-2026-07-24-006 в срок до 25 июля 08:00 UTC.

Референсы дают три разных ответа. AutoSK работает под подпиской, но у него не браузерный интерфейс, а нативная Tauri-обёртка. Warren — живой рабочий шаблон под наш стек (React + TS + NDJSON), но требует API-ключ Anthropic, а мы работаем по подписке. Overstory — духовный предшественник Warren, архивирован. Рынок сходится на паттерне «локальный демон + браузерный SPA + SSE» — ровно тот класс, куда ложится наша задача.

Из трёх реалистичных вариантов рекомендуем вариант A: тонкий TypeScript-сервер (~700 строк) поверх нынешнего конвейера, единая точка — кнопка «Опубликовать скилл». Первая рабочая кнопка — 3.5–5 дней с нуля, полный первый релиз — 10–14 дней. Главный запрет владельца — «агент не должен уметь опубликовать» — защищён биометрией TouchID внутри публикатора: сенсор — единственный ресурс машины, к которому агент под тем же UID структурно не имеет доступа. Красная команда нашла три критические ошибки в первой редакции — все закрыты механизмами, не оговорками; про остаточный риск на машине без биометрии сказано честно.

1. Что построено сегодня

Веб-контур лаборатории существует и работает как наблюдательный дашборд. Он профессионально свёрстан, регенерируется автоматически, читается с телефона через Markdown-проекцию и с ноутбука через file://. Ни один обработчик клиентского JS не отправляет ничего наружу; в исходнике нет ни fetch(, ни WebSocket, ни EventSource.

Страниц 7 index, timeline, tasks, questions, fleet, cost, library
Клиентский TS 425 строк, 6 функций — все только отображение
Кнопок с действием 0 кнопок, меняющих состояние системы, ноль
Сервер нет grep по всему дереву даёт 0 совпадений на http.server, express, fastify

Что уже умеет

Показать 7 экранов из render_bundle.json, пересчитать возраст, обратный отсчёт дедлайнов, фильтры и поиск, переключение темы.

Чего физически не может

file:// не имеет права на сетевой запрос к соседнему файлу (CORS). Кнопка была бы декоративной. Правило зафиксировано в docs/lab/site/README.md.

tools/lab/lab-emit.sh и lab-write.sh — атомарная запись под dir-локом. Из веба туда попасть нечем: посредника не построено.

Решение об отказе от интерактивной версии принял оркестратор дефолтом, не владелец

24 июля 2026 21:24 UTC агент-планировщик задал в очередь вопрос q-2026-07-24-006: «Раскрываем ли v2 веб-интерфейса?». Три опции, дефолт — «держим v1», дедлайн ответа — 25 июля 08:00 UTC. Владелец не ответил в срок. 28 июля 06:52 UTC оркестратор автоматически применил дефолт d-2026-07-28-004 по правилу «decide-by-default».

Формально всё соблюдено: у вопроса стоит reversibility: high. Но семантически владелец в это время читал свой мандат иначе и десять дней ждал админку с кнопками. Разрыв — не в коде, а в мандате.

2. Как это делают другие

Панель прочитала три ключевых референса построчно и обозрела рынок из 20+ инструментов. Ниже — сжатая карта.

Референс Стек Транспорт Работает под подпиской

  • Паттерн A — IDE-extension WebView. Cline, Roo Code, Continue.dev, Zed, Cursor. Живёт рядом с редактором, но привязан к IDE.
  • Паттерн B — локальный демон + браузерный SPA. OpenHands, vibe-kanban, amux, agent-dashboard, Aider --browser, LangGraph Studio. Ближайшая к нам форма.

3. Три варианта для нас

Все три сохраняют существующий стек и не переписывают статические страницы. Отличаются размером новой поверхности и сроком до первой рабочей кнопки.

Рекомендуем

A. Тонкий TypeScript-сервер над конвейером

Node + Hono, ~700 строк TS + 40 строк Swift для TouchID + 30 строк bash для top-level lock хроникёра. Клиент — два новых инлайн-модуля рядом с существующим клиентом на 425 строк. Статика продолжает работать без сервера.

Первая кнопка: 3.5–5 дней Полный первый релиз: 10–14 дней Обратимость: launchctl bootout Риск: низкий, аддитивный
Дороже

B. Bun + React SPA калька Warren

Bun-сервер + Vite + React 18 + Tailwind v4 + shadcn/radix + TanStack Query + Recharts. ~1500 строк сервера и ~4000+ строк SPA. Дублирует все семь экранов. Проекция JSONL в SQLite добавляет новый источник рассогласования.

Первая кнопка: ~11–12 дней Полный первый релиз: ~25–30 дней Требует: дизайн-лид Риск: средний, design-drift
Не рекомендуем

C. Полная замена на Next.js

Next.js 15 App Router, React 19, server actions. Выкидывает работающий SSG. Server-actions размывают границу «клиент → сервер», из-за чего проще случайно записать в docs/lab/ в обход CLI. Прямо противоречит указанию владельца «стек не переписывать».

Первая кнопка: ~12–17 дней Полный первый релиз: ~30–45 дней Обратимость: слабая, откат из git Риск: высокий, cut-over

4. Что нашла красная команда и как это закрыто

Первая редакция варианта A имела три критические ошибки. Все они закрыты механизмами в архитектуре, не текстовыми оговорками. Ниже — каждая находка и то, чем она заменена во второй редакции.

  1. Локальный порт не защищён от локальных агентов

    В первой редакции защита была только от чужих сайтов в браузере. Ни один механизм не отказывал curl, запущенному под UID владельца. Ровно то, о чём предупреждал владелец: агент под тем же UID — главный запрет.

    Закрыто: три слоя защиты. Bearer-токен на веб-эндпойнте (случайный curl без токена отклоняется). Env-секрет GOSLEEP_WEB_TOKEN внутри publish.sh (обход веб-сервера через прямой запуск CLI отклоняется). Биометрический гейт TouchID внутри publish.sh — агент структурно не может пройти биометрический сенсор.

  2. Гонка «синхронный chronicler после write» не закрывает параллельного debounce

    chronicler.py не имеет top-level exclusive lock. Два chronicler.sh могут бежать одновременно; порядок победителя определяется тем, кто позже закроет os.replace. Сценарий: сервер спавнит publish, затем chronicler; параллельный debounce-хроникёр читает старое состояние и заканчивает после сервера — клиенту возвращается 200, а страница не обновилась.

    Закрыто: 30 строк bash в tools/lab/chronicler.sh — top-level mkdir-lock + флаг --coalesce-since=<epoch>. Если bundle уже свежее переданного времени, второй caller выходит без работы. Гарантия: в любой момент работает ровно один chronicler.

  3. Действия из веба невидимы в timeline — hook-фильтрация мимо интерактива

    PostToolUse-хуки Claude Code срабатывают только на вызовы Bash/Edit самого CLI-клиента. child_process.spawn из Node-сервера — это системный execve, до него хук клиента не дотягивается. Значит все действия из веба проходят мимо timeline и debounce-хроникёра.

    Закрыто: обёртка withTimeline(endpoint, params, fn) на каждом POST. До спавна CLI пишет server.intent, после — server.outcome (успех или ошибка). Плюс touch .artifacts/lab/debounce/web-last-write как дополнительный сигнал debounce-waiter'у. Если сервер упал между CLI и хроникёром, tick.sh на следующем пасе видит осиротевший intent и пишет server.outcome со status=orphan.

Про остаточный риск честно. Если MacBook без TouchID (старый Air, headless-сессия по SSH), fallback читает одноразовый шестизначный код из /dev/tty. Агент в неинтерактивном контексте /dev/tty владельца не имеет и отсекается, но keyboard-скрипт под тем же UID может подсунуть код symbolic-ом. Это слабее биометрии; без Yubikey абсолютной защиты нет. TouchID — лучшее, что даёт macOS без аппаратного ключа. Остаточный риск в 1–2% сценариев остаётся, и мы это не прячем.

6. Что решает владелец

Требуется решение

Утвердить вариант A и запустить работы по эпику GSL-XXX

Дальше без явного решения не пойдём: любое расширение мандата — именно тот класс вопросов, который манифест запрещает закрывать дефолтом (урок 28 июля 2026). Ниже — два самостоятельных вопроса. На каждый ответьте «да» или «нет».

  • Q1. Утверждаем ли вариант A — тонкий TypeScript-сервер поверх нынешнего конвейера, три слоя защиты публикации (Bearer + env-secret + TouchID), первая кнопка «Опубликовать скилл» за 3.5–5 дней с нуля?
  • Q2. Если да, запускаем ли работы сейчас — отдельным эпиком поверх уже согласованного плана skills-governance-plan.md (этапы 2–3 идут как предпосылки, шаги 4–10 моего migration path — веб-часть)? Или откладываем до другого сигнала.

Что не строим ни при каком «да»

  • Electron / Tauri — не делаем.
  • WebSocket — не делаем (SSE достаточно, автор Warren съехал с WS).
  • PWA-manifest, service-worker, push, ntfy, tailscale — заморожены решениями владельца, не проектируем без явной команды.
  • Warren-калька c ключом Anthropic API — работаем под подпиской.
  • Прямая запись сервера в docs/lab/ — только через CLI.
  • Массовые операции (--all, «опубликовать все скиллы») — не проектируем в принципе.
  • git commit из сервера — не делаем.
  • Отключение guard в install.sh — guard остаётся включённым и после сборки веб-контура.
