01

Что такое «loop engineering» на самом деле

Каждый термин ниже вводится с нуля. Никакого словаря знать заранее не требуется.

Одним предложением: loop engineering — это дисциплина обёртывания кодинг-агента во внешний управляющий цикл (outer loop): перезапустить его с чистого листа, скормить сохранённое на диске состояние, проверить прогресс и решить — продолжить / остановить / эскалировать — так, чтобы полезная работа шла за пределами любой одной памяти и без человека, жмущего «continue».

Инсайт, с которого началась область, почти неловко прост. LLM-агент уже цикл: модель думает, вызывает инструмент, читает результат, снова думает — по кругу, пока не решит остановиться. Но этот цикл живёт внутри одного context window (контекстного окна — конечного объёма текста, который модель держит одновременно) и умирает, когда окно заполняется. Ответ сообщества: обернуть всего агента в while true и сделать файловую систему + git той памятью, что переживает каждый перезапуск. Всё дальнейшее — stop conditions, budgets, circuit breakers, checkpoints — это инженерная дисциплина, наслоённая поверх этого while true.

Ключевая ментальная модель — два вложенных цикла Inner loop (внутренний) = собственный цикл агента think→tool→observe внутри одного context window. Ограничен окном, и это проблема вендора модели. Outer loop (внешний) = harness, который заново запускает свежего агента поверх окон — тот самый while true. Ограничен только вашими guard'ами, и это ваша проблема. Loop engineering = инженерия внешнего цикла.
Словарь-карта — каждый термин встретится ниже снова
  • Inner loop — цикл агента think→tool→observe внутри одного context window.
  • Outer loop — harness, заново вызывающий агента поверх окон (while true).
  • Harness — всё вокруг модели: инструменты, файлы состояния, логика рестарта, guard'ы. «Harness engineering» ≈ «loop engineering»; второе делает акцент на цикле перезапуска.
  • Stop condition / definition-of-done — машинно-проверяемое условие, завершающее внешний цикл (а не «модель почувствовала, что готово»).
  • Circuit breaker / loop guard — детекторы, останавливающие цикл, который не даёт прогресса (защита от runaway).
  • Checkpoint & resume — устойчивое состояние, записанное на каждой границе, чтобы свежий агент продолжил с диска.
  • Heartbeat — периодический дешёвый «тик»: «я жив / есть что делать?».
  • Watchdog — отдельный процесс, который следит за циклом и вмешивается, когда тот залипает.
  • Park / escalate — увести застрявшую задачу в очередь к человеку, а не ретраить её вечно.

03

Каталог паттернов — десять переиспользуемых ходов

Всё, что область успела выучить, разложено на десять паттернов. Каждая карточка: ◆ суть простыми словами · ▚ где реализовано (реальные системы) · ▲ подводные камни, на которых спотыкаются.

1

Outer loop vs inner loop

несущее различие — на нём висит всё остальное
Суть

Inner loop (model→tool→observe) ограничен одним context window и это проблема вендора. Outer loop (запустить свежего агента → навести на устойчивое состояние → проверить прогресс → решить continue/stop/escalate) ограничен только вашими guard'ами и это ваша проблема. Loop engineering — это инженерия внешнего цикла.

Где

Однострочник Ralph; split «initializer / coding agent» у Anthropic; каждый раннер ниже.

ghuntley/ralphanthropic harness
Подводные камни

Смешение двух циклов. Трюки inner-loop (compaction, окна побольше) откладывают, но не отменяют нужду во внешнем цикле — Osmani: context rot деградирует качество задолго до лимита токенов, поэтому рестарт со свежим контекстом лучше растягивания уставшего.

2

Stop conditions & definition-of-done

как цикл понимает, что действительно закончил
Суть

Цикл должен завершаться по машинно-проверяемому условию, объявленному до прогона — никогда «модель почувствовала, что готово». Формулируй done как данные, а не прозу.

Где

Anthropic: JSON feature list (200+ пунктов, все стартуют как failing; done = все passing; спека запрещает править/удалять тесты). У Carson (snarktank/ralph) истории в prd.json переключают passes:false→true; выход только при <promise>COMPLETE</promise> И all-pass, плюс жёсткий max_iterations. У ralph-claude-code — самый проработанный exit где-либо: двойной gate (≥2 накопленных сигнала завершения И явный EXIT_SIGNAL:true) плюс аварийный force-exit.

anthropic feature-listsnarktank/ralphralph-claude-code
Подводные камни

Одно-сигнальные выходы (модель рано объявляет победу — Anthropic видели это постоянно). Модель, правящая сам done-предикат (отсюда пункты «не трогать тесты»). Устаревшие exit-сигналы, пережившие рестарт (ralph-cc чистит .exit_signals между сессиями).

3

Budget guards / token ceilings

жёсткие потолки, переживающие рестарт
Суть

Жёсткие механизменные потолки на итерации, вызовы, токены и доллары — потому что потолок, живущий только в промпте, не самоисполняется под давлением.

Где

ralph-claude-code: MAX_CALLS_PER_HOUR=100 (сброс каждый час), опциональный кумулятивный лимит токенов, MAX_COST в USD на прогон в sandbox, таймаут 15 мин на вызов. autosk хранит бюджеты по visit-count в task.json, сбрасываемые человеком. warren добавляет выстраданное правило: кривой бюджет должен fail OPEN — опечатка в бюджете не должна молча отменить каждый прогон.

ralph-claude-codeautosk task.jsonwarren
Подводные камни

Бюджеты, живущие только в промпте (игнорируются). Бюджеты без персистентности (рестартнутый цикл забыл, что уже потратил потолок). Бюджеты, которые fail closed на опечатке конфига (урок warren — убивает каждый прогон).

4

Checkpoint & resume

писать состояние на каждой границе, чтобы любой продолжил с диска
Суть

Каждая итерация заканчивается записью устойчивого состояния (коммит + заметка о прогрессе), чтобы любая следующая итерация — тот же цикл или холодный рестарт спустя дни — продолжила с диска, а не из памяти.

Где

Anthropic: claude-progress.txt + описательные коммиты; initializer agent существует только чтобы создать эту поверхность resume. Carson: память — это только история git + append-only progress.txt + флаги prd.json, и он чекпоинтит ещё и знание — дописывает codebase-грабли в AGENTS.md, чтобы поздние итерации их наследовали. warren гонит даже убитые watchdog'ом прогоны «через reap, а не голый finalize», чтобы частично закоммиченная работа не пропала.

anthropic progress.txtsnarktank AGENTS.mdwarren reap
Подводные камни

Чекпоинт в чат/скроллбэк (теряется при compaction). Resume устаревшей сессии вместо свежего контекста (класс багов «session hijacking»). Progress-файлы, растущие безгранично. Доверие чекпоинту вместо живого git (gosleep это уже решает атомарным temp+rename и правилом «live git wins»).

5

Self-pacing & cache window

решить, когда просыпаться — и почему важны 5 минут
Суть

Автономный цикл должен решать, когда проснуться снова. Фиксированный cron либо расточителен (ничего не изменилось), либо медлителен (что-то срочное). Уточнение 2026-го: подбирать интервал под время жизни prompt-кэша, потому что экономика кэша доминирует в стоимости простаивающего цикла. Полностью раскрыто в §04.

Где

Каноничный split OpenClaw heartbeat vs cron: heartbeat — периодический ход в основной сессии, читающий крошечный стабильный чеклист и пакующий все проверки в один ход; cron — отдельные изолированные джобы. Рычаги цены: изолированные сессии (~100K → 2–5K токенов/прогон), дешёвая модель, окна активных часов. Собственный ScheduleWakeup / динамический /loop в Claude Code кодирует ровно правило cache-окна («не бери 300s»).

OpenClaw heartbeatScheduleWakeup
Подводные камни

Пуллинг «на всякий случай» каждые N минут — каждый тик это полный ход агента (выгорание-по-счёту-за-токены). Wake-up'ы, заново запускающие дорогую работу вместо дешёвого triage. Heartbeat, чей контекст сессии растёт вечно (ответ: изолированная сессия + крошечный чеклист). Фиксированный cron без быстрого пути «делать нечего → сказать OK и выйти дёшево».

6

Overnight / unattended

работа, пока человек спит; читаемое утро, а не сырые логи
Суть

Цикл работает, пока человек спит. Каждая точка касания человека либо убрана (auto-approve в рамках scoped-прав), либо отложена (утренняя очередь), либо фатальна (park). Утренний артефакт — читаемый дайджест, а не сырые логи.

Где

Линия Ralph («отгружай фичи во сне… вернись к готовым фичам, зелёным тестам, закоммиченному коду»). Явный unattended mode ralph-cc авто-ждёт сквозь 5-часовой лимит подписки вместо выхода. Morning-brief cron + активные часы + «будить человека только на алерты» у OpenClaw. Gas Town гоняет весь «город» на патрулях и выдаёт владельцу читаемый утром capability ledger. Park-to-human утренняя очередь у autosk.

geocod.io ralphralph-cc unattendedOpenClaw briefGas Town ledger
Подводные камни

Auto-approve за пределами scoped-прав (консенсус сообщества держит merge/deploy/деструктив под human-gate даже на максимальной автономии). Окна rate-limit, прочитанные как ошибки. Проснуться к 40 неподписанным веткам — дайджест так же важен, как работа. Отсутствие пути отката.

7

Question buffering

не останавливать весь цикл из-за одного вопроса
Суть

Ночью блокирующий вопрос — это stall. Три ответа по возрастанию зрелости: (a) park — увести задачу и идти дальше; (b) pause с бюджетом — ждать асинхронный ответ человека, авто-решить по таймауту; (c) buffer & continue — залогировать вопрос, взять обратимый дефолт, продолжать работать, показать буфер в утреннем дайджесте. (c) — идеал для gosleep и наименее реализован в публичном коде.

Где

warren — самое конкретное: воркеры эмитят question_posed в event-лог → прогон переходит в paused; человек отвечает по API, ИЛИ pause budget истекает и прогон продолжается. Вопросы — это события, а не модальные диалоги. autosk использует park-to-human как универсальный сток. OpenClaw по дизайну rate-лимитит канал вопросов (пакетирование, подавление OK-шума). Osmani: «delegated approval с полным сохранением execution-state».

warren pause-budgetautosk parkOpenClaw suppress
Подводные камни

Слишком охотный park (один неоднозначный lint-правило не должно стопить фичу — для этого buffer-and-default). Ответ необратимым дефолтом (буферизация работает, только когда дефолт дёшево откатить). Спам вопросов — буферу нужен dedup (один вопрос от 5 циклов = 1 утренний пункт).

8

Verification loops

свежий судья, потому что генератор не проверяет сам себя
Суть

Генератор не должен оценивать свою же работу. Отдельная стадия — свежий агент, тест-сьют или браузер — верифицирует каждый инкремент до того, как переключится done-флаг; ratchets (храповики) не дают регрессий (метрика может только расти).

Где

Решающая находка Anthropic: Claude помечал фичи готовыми преждевременно, пока ему не дали browser automation (Puppeteer MCP), чтобы тестировать «как пользователь». planner/worker/judge split + test ratchets у Osmani. «backpressure» у Huntley: компиляторы и статические анализаторы вшиты так, что плохая итерация не проходит дальше. Gas Town: Refinery ревьюит вывод воркера; Witness верифицирует прогресс независимо от заявлений самого воркера.

anthropic puppeteerosmani judgegastown witness
Подводные камни

Верификатор, разделяющий контекст генератора (наследует его допущения — свежий контекст в этом весь смысл). Верификация, которую модель может править (удаление тестов). Верификатор, который зависает и морозит цикл (E17 watchdog в gosleep существует ровно для этого; per-call timeout у Ralph — эквивалент на уровне цикла).

9

Anti-runaway protections

крутящийся цикл хуже остановленного
Суть

Цикл, крутящийся без прогресса, жжёт бюджет и может повредить дерево — хуже остановленного. Детекция много-сигнальная (прогресс, повтор ошибки, форма вывода); реакция ступенчатая (halt → cooldown → человек). Полностью разобрано в §05.

Где

Полноценный circuit breaker в стиле Nygard у ralph-claude-code (CLOSED/HALF_OPEN/OPEN; открывается на 3 циклах без прогресса, 5 циклах с той же ошибкой, >70% падении вывода или 2 циклах permission-denial; 30-мин cooldown, затем проба). Цепь watchdog'ов Gas Town (Witness → Deacon → Boot-the-Dog проверяет Deacon каждые 5 мин) с жёстким правилом никогда не объявлять агента застрявшим по одному store. warren выводит heartbeat из новейшей строки события и self-arm'ится по умолчанию.

ralph circuit_breaker.shgastown bootwarren liveness
Подводные камни

Одно-сигнальная детекция «застрял». Watchdog'и, за которыми никто не следит (Boot существует, потому что сам Deacon на практике умирал). Kill-пути, уничтожающие частичную работу (правило reap у warren). Самозаявленные heartbeat'ы — залипший агент не может отчитаться; выводи liveness из артефактов (события, коммиты, mtime файлов).

10

State-on-disk

файловая система + git ЕСТЬ память цикла
Суть

Файловая система + git и есть память цикла. Всё, нужное для решения «что дальше», должно быть повторно выводимо с диска читателем с нулевым предыдущим контекстом.

Где

Каждая серьёзная система сходится на одной тройке: (1) work state — флаги prd.json / feature-list JSON / Beads ledger / счётчики task.json / event-лог. (2) narrative — append-only progress.txt / capability ledger / накопление AGENTS.md (цикл улучшает собственные будущие промпты). (3) loop-control state — .ralph/ exit-сигналы + JSON circuit breaker'а + метрики, heartbeat-store'ы, pause/visit-бюджеты.

все системы
Подводные камни

Состояние только в сессии (умирает с ней). Неатомарные записи (обрезанные батоны — правило temp+rename в gosleep). Нечитаемое человеком состояние (владелец должен триажить с телефона — сбрасываемые человеком JSON-счётчики autosk — образец). Стены прозы вместо структурированного состояния.

04

Экономика self-pacing

Почему стоимость простаивающего цикла определяется одним числом, которого не видно на дашборде — временем жизни prompt-кэша.

Сперва — что такое prompt-кэш. Когда вы шлёте большой промпт (системные инструкции, стоящий файл состояния, чеклист) в модель, провайдер может закэшировать этот префикс. Если вскоре вы шлёте почти тот же промпт, за закэшированную часть вы платите долю цены. Загвоздка: у кэша есть время жизни (TTL). Промахнулись мимо окна — следующий вызов заново платит полную цену за весь префикс. Это cache miss.

Что изменилось. Дефолтный TTL кэша у Anthropic молча упал с 1 часа → 5 минут 2026-03-06. Циклы, пуллившие раз в 15–30 минут, были настроены под старое часовое окно; ночью они внезапно стали съедать полный cache miss на каждом тике — сообщения об +30–60% эффективной стоимости.

Возникшее правило Пуллить внутри cache-окна (<5 мин) ИЛИ уходить в длинные сны (20–30 мин+) и съедать ровно ОДИН cache miss. Худшая из возможных каденций — чуть за TTL (скажем, 6–10 минут), где вы платите полный miss каждый раз и не получаете за это ничего.

Принцип дешёвого triage Поскольку каждый wake-up — полный ход агента, wake-up должен делать минимум, отвечающий на вопрос «есть что делать?». Wake-up, заново запускающий дорогую slash-команду вместо дешёвого triage — классическая самонанесённая рана (баг Claude Code #54086).
05

Anti-runaway, эталонного качества

Две production-системы решили «остановить крутящийся цикл» правильно. Их код несёт уроки, которых не передаст ни один дизайн-док — каждый из них шрам от реального инцидента.

Эталон A — ralph-claude-code

Двойной exit gate + circuit breaker

v0.11.x, 784 теста — bash-однострочник, превращённый в production-раннер цикла.

Двойное условие выхода — для done нужно ОБА:

  • ≥2 накопленных сигнала завершения по недавним циклам (в JSON .exit_signals), И
  • явный EXIT_SIGNAL: true в ответе агента.

Плюс аварийный force-exit после 5 подряд EXIT_SIGNAL=true на случай, если нормальный путь залип; и STATUS: COMPLETE с EXIT_SIGNAL:false явно продолжает. Exit-сигналы чистятся между сессиями, чтобы устаревший не выстрелил.

Circuit breaker — конечный автомат Nygard в circuit_breaker.sh:

CLOSED
норм. поток
HALF_OPEN
проба
OPEN
сработал

Открывается на любом из: 3 цикла без прогресса · 5 циклов с той же ошибкой · >70% падение вывода · 2 цикла permission-denial. Затем 30-мин cooldown → HALF_OPEN (одна дешёвая проба) — не хард-стоп, а один ретрай. Все пороги настраиваются через env; состояние — в JSON. Прогресс = git-коммиты внутри цикла, но git-движение никогда не считается завершением.

Эталон B — Gas Town

Цепь watchdog'ов и её шрамы

Индустриального масштаба оргструктура циклов от Steve Yegge — прочитана из Go-исходников.

Кто за кем следит:

Witness → воркеры· Deacon → система· Boot → Deacon, каждые 5 мин

Boot — не тупой таймер, а свежий LLM-triage-агент на каждом тике демона, выбирающий одно из четырёх действий: start / wake / nudge / nothing. flock + marker-файл держат его single-flight (не может пересечься сам с собой).

Production-шрамы (каждый — исправленный инцидент):

  • Startup grace period — heartbeat-проверка убивала только что стартовавшие сессии до того, как те успевали записать первый heartbeat (issue #567). Каждому watchdog нужна разминочная поблажка.
  • Счётчик + cooldown, никогда не one-shot — force-kill только после 3 подряд провалов ping, затем 5-мин cooldown между убийствами.
  • Zombie debounce — нужно ≥3 подряд цикла «tmux-сессия есть, а процесса агента нет» до рестарта. Pane-alive и process-alive — разные сигналы, штатно расходящиеся при handoff'ах.
  • Crash-loop backoff — RestartTracker с экспоненциальным backoff (warren независимо пришёл к тому же бюджету 5-рестартов-за-60с).
  • Mass-death detection — много смертей разом — другой (системный) сбой, чем одна смерть.
  • Bounded fan-out — watchdog проверяет rig'и в worker-pool с per-rig таймаутами, чтобы один медленный rig не блокировал все.
Дистиллят урока для watchdog-над-оркестратором в gosleep Каждое решение watchdog должно быть (a) counter-debounced, (b) cooldown-limited, (c) освобождено на время warm-up и (d) сам watchdog single-flight + rate-limited. Наивный скрипт «STATE устарел → рестартнуть оркестратор» выстрелит на ложных срабатываниях в первую же ночь — сессия между ходами, свежий старт посреди записи, транзиентная дыра handoff'а. Debouncing — это не gold-plating, а разница между watchdog'ом и самонанесённой аварией.

Что внедрять, по рангу

Ранг = ценность для «владелец спит» ÷ усилие. Каждый пункт называет механизм, что он детектит/решает и стоимость сборки. Пункты 1 + 2 + 3 вместе — минимальный жизнеспособный пакет «владелец идёт спать».

Минимальный пакет «владелец спит» #1 self-pulse (никогда не задремать) + #2 night mode & morning digest (читаемое утро) + #3 question buffer (не стопиться на вопросах). Все — усилие LOW–MED, без новой инфраструктуры. #4 делает так, чтобы это пережило смерть самого оркестратора; #5–#8 поднимают качество и экономику на длинной дистанции.
1

Armed self-pulse с cache-aware каденцией MVP

Оркестратор никогда не завершает ход, пока флот жив, без запланированного wake-up (ScheduleWakeup в Claude Code; cron/sleep-обёртка где-то ещё). Pulse — это дешёвый triage-тик: прочитать STATE, прощупать сигналы liveness, действовать только на дельтах — форма heartbeat OpenClaw (крошечный стабильный чеклист, быстрый путь «OK → ничего не делать»). Каденция из канона: <5 мин, пока активно расклиниваешь stall (кэш тёплый), 20–30 мин, пока воркеры пашут (один амортизированный miss).

Решает: весь класс «оркестратор задремал / ход завершился и никто не следит» — мандат pulse-rule владельца, наконец механизированный.

УСИЛИЕ · LOWЦЕННОСТЬ · HIGHтекст скилла + таблица каденции; инструменты уже есть
2

Night mode + morning digest MVP

Объявленное unattended-окно. Внутри него AskUserQuestion запрещён кроме denylist-пунктов; каждый потенциальный вопрос идёт в буфер (#3). На закрытии окна оркестратор пишет docs/handoff/MORNING-DIGEST-<date>.md: что приземлилось, вердикты, parked-пункты, буферизованные вопросы, потрачено vs потолок.

Решает: владелец, проснувшийся к 40 веткам без нарратива; делает «идти спать» явным режимом с ужатыми рельсами.

3

Question buffer с pause-budget дефолтами MVP

Трёхуровневый triage любого форка вне denylist: (a) обратимо + низкие ставки → взять дефолт, залогировать вопрос+выбор в QUESTIONS.md (buffer-and-continue); (b) существенно, но не опасно → warren-style пауза этой задачи с бюджетом, park её, переназначить воркера на следующую разблокированную задачу; (c) denylist/необратимо → BLOCKED_ON_HUMAN как сейчас. Dedup одинаковых вопросов между циклами.

Решает: ночные stall'ы на вопросах — сегодня каждая неоднозначность стопит тред до утра.

УСИЛИЕ · MEDЦЕННОСТЬ · HIGHпротокол в шаблоне воркера + triage-правила оркестратора
4

Watchdog над оркестратором (слой Boot)

Внешняя, тупая, не-LLM проверка (cron-скрипт или дешёвый Monitor-цикл): «продвинулись ли mtime ORCHESTRATION-STATE.md / строка TELEMETRY за N мин, пока open_workers>0?». Если stale → уведомить владельца И/ИЛИ перезапустить свежего оркестратора, наведённого на cold-start протокол, под warren-style restart-бюджетом (напр. 3/ночь, дальше — пейджить владельца). Liveness из артефактов (mtime, git), никогда self-report. Применить уроки debounce из §05 — counter-debounce, cooldown, warm-up grace, single-flight.

Решает: мёртвый/сжатый оркестратор, осиротивший живой флот ночью — единственный сбой, из которого скилл не может восстановиться сам.

Машинно-проверяемый definition-of-done на фазу

Взять паттерн feature-list/prd.json: каждый epic несёт JSON-чеклист с флагами passes, переключаемыми только после верификации; done уровня цикла = все-passing + PR смёржен, а не «воркер сказал COMPLETE». Запретить правку done-предиката (клауза «unacceptable» у Anthropic) в брифах воркеров.

Решает: преждевременную победу через границы циклов; даёт loop guard'у реальный предикат для проверки.

Circuit-breaker апгрейд для loop guard

Расширить существующий loop guard сигналами ralph-claude-code: same-error-N-раз между циклами, падение output/прогресса и cooldown + HALF_OPEN проба (один дешёвый ретрай после паузы) вместо хард-STOP. Счётчики персистятся в STATE и сбрасываются человеком (phone-editable счётчики autosk).

Решает: и ложные halt'ы (транзиентный flake навсегда взводит guard), и busy-runaway, которые нынешний двух-сигнальный guard пропускает.

8

Sleep-time consolidation (idle-gap compute)

Пока воркеры пашут, а оркестратор ждёт, тратить простаивающие wake-up'ы на дешёвую работу с памятью: сжимать старые записи лога STATE, дистиллировать ночные LEARNINGS, преднабрасывать morning digest. Исследовательский родственник — sleep-time compute у Letta (paper 2025-04): фоновые агенты делят память с основным и переписывают её асинхронно — заявлено до +18% точности и 2.5× ниже стоимость/запрос за счёт предвычислений в простое. Держать различие острым: Ralph-циклы делают больше работы ночью; sleep-time compute делает работу следующего дня дешевле и умнее.

Решает: разрастание файла STATE и латентность morning digest — бесплатно, во время ожиданий.

Выводы

Что устоялось в области
  • Loop engineering — реальная датированная дисциплина, не метафора. У неё есть документ-основание (Ralph, 2025-07), благословение вендора (Anthropic harness, 2025-11) и имя (2026-06).
  • Вся область — это одна идея плюс дисциплина: while true вокруг агента, файловая система + git как память — а дальше stop conditions, budgets, breakers, checkpoints поверх.
  • Фронтир 2026-го экономический: 5-минутный cache TTL теперь диктует каденцию wake, а idle-стоимость доминирует в ночных счетах.
  • Два самых выстраданных урока — оба про недоверие одному сигналу: не верь «я готово» от модели и не верь одному heartbeat-store, объявляя агента застрявшим.
Что это значит для gosleep
  • Наша сторона воркера уже канон-уровня или лучше — state, батоны, patience-часы, verification, telemetry, authority model. Сохранить.
  • Наша единственная структурная дыра — оркестратор как самопланирующийся, самовосстанавливающийся цикл. Каждая недостающая способность — её грань.
  • Починка — в основном проза + шаблоны, не инфраструктура: adoptions #1–#3 (self-pulse, night mode, question buffer) — сон-разрешающий минимум, все усилия LOW–MED.
  • #4 (debounced watchdog над оркестратором) — то, что превращает «работает ночью» в «переживает собственную смерть ночью». Строить со шрамами §05 в уме — debounce, иначе выстрелит ложно в первую же ночь.
