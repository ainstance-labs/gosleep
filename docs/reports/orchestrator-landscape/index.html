Orchestrator Landscape

0How to read this report — the concepts

The report assumes zero prior context. Every system below is built from the same vocabulary; here is that vocabulary in plain language. Terms are also re-explained the first time they matter inside a section.

Orchestrator / worker
The split every system converges on: an orchestrator decides what to do next, spawns workers, watches them, and talks to the human; workers are disposable agents that each execute one bounded chunk of work and then exit. gosleep's own skill mandates a "pure orchestrator" that executes nothing itself.
Headless mode / claude -p
Normally claude opens an interactive chat in your terminal. claude -p "do X" (--print) runs the exact same agent once, with no UI: it does the task, prints the result, and exits — Claude Code as a Unix command you can pipe, script, cron, and loop. Same model, same tools, same login; nobody is present to answer permission prompts, so tools must be pre-approved.
stream-json (NDJSON over stdio)
A machine-readable dialect of headless mode: --output-format stream-json --input-format stream-json turns the agent into a live event stream (one JSON object per line) on stdout, and accepts new user messages — even a mid-turn interrupt — on stdin. This is how a program "talks to" a running headless agent.
Subscription vs API key
Two ways to pay for Claude. A Pro/Max subscription is flat-rate with usage windows (a rolling 5-hour window plus weekly caps) and covers the official apps, including Claude Code. An API key is pay-per-token with no ceiling. Which one a tool can run on is the single question that now sorts the entire orchestrator landscape (§5).
tmux / pane
A terminal multiplexer: one terminal window split into independent panes, each running its own process, surviving disconnects. gosleep, Gastown, Claude Squad, and Overstory's escape hatch all run interactive claude sessions inside tmux panes so a human can attach and watch any agent live.
Agent Teams
Claude Code's first-party multi-agent primitive (~Feb 2026): one lead session spawns teammate sessions with their own context windows, peer-to-peer messaging, and a shared task list — all inside the official client, so it runs on the subscription's interactive quota. This is gosleep's current surface.
Git worktree
A second (third, …) working directory checked out from the same repository. Each agent gets its own worktree, so parallel agents can't overwrite each other's files; merged back via branches. The standard isolation unit across the landscape.
MCP (Model Context Protocol)
A standard for giving an agent extra tools over a network or socket. AutoSK mints a tiny private MCP server per agent session, so the agent can call control-plane tools (like "advance this task to the next step") as ordinary tool calls that the host validates.
Watchdog
A supervising process that periodically checks whether agents are alive and making progress, and intervenes (nudge → kill → escalate) when they are not. The key design question: is the watchdog mechanical (plain code, deterministic) or an AI itself? The field's answer converged hard on mechanical (§4, §8).
Heartbeat
A periodic, durable proof of life: "the newest timestamp this component wrote somewhere on disk / in a DB". Liveness is judged from that durable record — never from a process merely existing, and never from what the supervisor remembers. Both Warren and Overstory arrived at this rule independently.
Park-to-human
The universal failure sink: when an agent crashes, loops, exceeds a budget, or can't decide, the task is not silently retried — it is parked into a "waiting for a person" state with an explanatory note. The set of parked tasks IS the owner's morning review queue.
Handoff / ledger
gosleep vocabulary: a handoff is a self-contained document one agent writes so a fresh agent (with zero memory) can resume; the ledger (ORCHESTRATION-STATE.md) is the orchestrator's on-disk state file. Other systems keep the same information in task files (AutoSK) or a database (Warren).
Kickback / corrections loop
AutoSK's turn-level guard: if an agent ends its turn without declaring the required transition, the host re-prompts it with a correction — at most N times (default 3) — then parks the task to a human. Bounded retries with a single exit, never an infinite loop.
Circuit breaker
Ralph's loop-level guard, borrowed from electrical engineering: the loop "trips open" when it detects no progress, the same error repeating, or output collapsing — then cools down before retrying, instead of burning quota on a stuck loop.
Usage window / quota
Subscription limits arrive as windows: a rolling 5-hour window plus weekly caps (since 2025-08-28). When a window is exhausted, every agent riding that login stalls at once. Overnight autonomy therefore needs window-aware waiting, not just error handling.
Spawn-per-turn / fresh-context-per-step
Instead of keeping one long-lived agent whose context window slowly fills up, spawn a fresh process for each step/turn and carry all state in files or a DB. Context exhaustion is designed away rather than fought. AutoSK, late Overstory, and gosleep's cycle-worker model all converge here.
Daemon
A background service that keeps running independently of any terminal — AutoSK's autoskd owns all state and serves every UI; Warren is itself a server process. gosleep currently has no daemon: the orchestrator is an interactive session.

1Executive summary

Five findings carry the whole report. Details and evidence live in the sections that follow.

VALIDATED  gosleep's core bets are the field's convergence points

Independently of us, the strongest projects landed on the same fundamentals gosleep already uses: state in plain files / durable records (AutoSK abandoned its v1 database for files), fresh context per step instead of fighting compaction, interactive CLI in tmux as the subscription-legal spawn surface (Gastown, Claude Squad), and recovery by re-attach + reconcile from durable state, never blind respawn (Warren). Our architecture is not exotic — it is the emerging standard, minus a few hardening layers.

POLICY SHIFT  Subscription-first survives — but headless is now metered

Anthropic spent Jan–Apr 2026 cutting third-party harnesses off from subscription OAuth, and in June split programmatic usage (claude -p, SDK, CI) into its own monthly credit pool ($20 Pro / $100 Max 5x / $200 Max 20x at API list rates). Interactive Claude Code — gosleep's tmux + Agent Teams surface — is explicitly unaffected and remains the most generous $/token surface. Verdict: keep interactive quota as the engine; treat headless as bounded glue (§5).

CONVERGENCE  The field pushed the LLM out of the supervision loop

Overstory built a 4-tier watchdog with AI triage and an AI monitor-agent; its successor Warren kept one mechanical 30-second tick over durable heartbeats and dropped AI from supervision entirely. AutoSK's loops are all bounded counters with a single human exit. The lesson for gosleep's "who watches the orchestrator" gap: the watcher must be dumb code over durable state — the LLM belongs inside bounded runs, not in the control loop (§4).

GAPS = OPPORTUNITY  Nobody ships the two features an owner-asleep system needs most

Across the whole landscape, no tool notifies anyone when work parks for a human (AutoSK's parks are silent; a fleet can quietly die at 1am), and no tool is usage-window-aware (quota exhaustion parks everything; nothing resumes when the window resets — only Ralph auto-waits). Push-on-park and window-aware scheduling are gosleep's clearest differentiators (§8).

TOP ADOPTIONS  The five highest-value transplants
  • External mechanical watchdog over an orchestrator heartbeat file, with a restart budget (Warren's supervisor semantics on tmux).
  • Park-to-human as the single failure sink with an explanatory note (AutoSK) — the owner's morning queue.
  • Persisted, human-resettable loop budgets: turn corrections → step-visit caps → park (AutoSK) + Ralph's circuit breaker & exit gate.
  • Quota auto-wait (Ralph) grown into fleet-level window-aware scheduling.
  • claude -p stream-json harness for bounded headless glue — the proven wire pattern (AutoSK's driver).
ECONOMICS  Wide swarms lost the argument

Overstory's own in-repo self-critique (STEELMAN.md) reports a 20-agent swarm finishing 15 tasks in 6h for ~$60 of tokens where a single agent did the same in 8h for ~$9 — a 2-hour speedup bought for $51 of coordination overhead. Warren's answer: serial, PR-gated execution, one child at a time. gosleep's ~3-pane cap and one-commit-per-task discipline sit on the right side of this trade already (§4).

Sources: sections §2–§8 below; primary research in docs/research/2026-07-07-orchestration/01-autosk.md, 02-warren-overstory.md, 03-headless-subscription-landscape.md.

2.2 Architecture

Fig. 2a — AutoSK: three thin clients over one daemon that owns all state as files and drives each workflow step as a fresh headless claude -p subprocess. Sources: AGENTS.md:6-19, daemon/extensions/claude-agent/src/index.ts:386-396, engine.ts:48-57.

How agents are launched — the exact mechanism

Agents are headless CLI subprocesses speaking NDJSON over stdio — no PTY, no tmux, no Agent SDK. The claude extension spawns claude -p --output-format stream-json --input-format stream-json --verbose --include-partial-messages --replay-user-messages, default --permission-mode acceptEdits, optional --dangerously-skip-permissions intended only for worktree-isolated runs. A ClaudeDriver wraps the child: parses the event stream, mirrors messages 1:1 into the transcript, coalesces partial deltas at ~40 ms into an ephemeral "partial" channel. Steering a live run is solved on the wire: a steer while the model is streaming writes a {type:"control_request", request:{subtype:"interrupt"}} frame, then the new message; a follow-up queues after the current turn.

Sources: claude-agent/src/index.ts:386-413, driver.ts:60-126, 254-272, 487-489.

The transit protocol — how a step ends

The agent must end its step by calling the MCP tool mcp__autosk__transit {to: "<step>|done|cancel|human"} — the model declares the workflow transition as a validated tool call. Subtlety: the tool is ack-only on the MCP server; the driver observes the tool_use on the stream and host-side code commits the transition after the turn ends. If the turn ends without a transit, or the workflow's onTransit hook rejects the target, the kickback loop re-prompts with a correction (budget: 3); when the budget is spent, the engine parks the task to human with reason agent_did_not_transit. This is the "agent must explicitly hand off or park" discipline gosleep's phase gates want, made mechanical.

Sources: driver.ts:18-21, 385-389, index.ts:225-269.

Scheduler — race-free dispatch with no database

  • Event-driven, not polled: transit/enroll/resume/finish kick a coalesced scan (scans never overlap); a 30s safety rescan backstops out-of-band file edits.
  • Session-creation-as-claim: a scan claims a schedulable task by creating a queued session — guaranteeing one session per task; dispatch re-reads the task fresh before claiming ("the snapshot is never trusted").
  • Commit-before-seal ordering: a closing session writes the task's new position FIRST while still running (live → scans skip it), only then flips its own meta terminal — closing the double-dispatch window.
  • Interactive chats run off the bounded pool so an idle chat can't starve the 4-worker task scheduler.
  • Isolation is agent-owned, not engine-owned: the engine abolished its isolation abstraction; agents wrap themselves via @autosk/sandbox (per-task git worktree, or a docker container that reaches the host MCP via host.docker.internal), with a final cleanup workflow step.

Sources: engine.ts:1-20, 48-57, 363-453, session.ts:30-35, 309-341, sandbox pkg, README.md:149-151.

2.3 State & resilience

All state is plain files under <project>/.autosk/ — no DB anywhere (v2 dropped v1's DB). tasks/<id>/task.json is pretty-printed and explicitly human-editable; sessions are a meta JSON + a JSONL transcript. The write discipline is production-grade:

Atomic writes, byte-stable format

Every mutation: temp file in same dir → fsync temp → rename → fsync parent dir. Serializers reassemble records with fixed key order; golden tests pin the exact bytes — "any byte-level change must fail a test". Readers never see torn writes.

Concurrency without transactions

A KeyedMutex serializes read-modify-write per task id; distinct keys run parallel. Combined with atomic rename, this replaces a database's transactions entirely. A change-signature (mtime:ctime:size:ino) powers a read cache and lets the file watcher recognize the daemon's own writes (echo suppression).

External edits reconciled

Recursive fs.watch + a 5s rescan both funnel into one reconciliation: accept/reject per ownership policy (the engine owns status/step/workflow while a session is live). The watcher is "intentionally dumb — no diffing". Humans and agents may edit task.json directly by contract.

Crash recovery = reap-then-park

On daemon start, any session left running/queued → failed: daemon_restart, structural error lines appended to its transcript, and its task parked to human. No auto-resume of in-flight runs; the captured claude session_id is stored "for future --resume" but unused. Every daemon upgrade fills the human queue.

Surviving context exhaustion: there is no within-run checkpoint/compaction handling at all. Each workflow step is a fresh claude -p process with fresh context; durable state crosses step boundaries via task.json + comments + the git worktree — never via the agent's context. Loop state (metadata.step_visits counters) persists in the task file, so a human can un-park a task and reset its budget from any text editor — including a phone.

Sources: store/paths.ts:1-15, store/atomic.ts:1-24, store/records.ts:1-15, store/lock.ts, store/watcher.ts:1-14, engine.ts:483-508, transition.ts:80-95, driver.ts:195-196, 363.

2.4 Auth — subscription-native, verified

Verdict: zero API-key code anywhere

There is no ANTHROPIC_API_KEY / OAuth / token handling in the entire codebase (grep across daemon/, gui/, cmd/ — no hits). AutoSK simply spawns the operator's already-authenticated claude CLI from $PATH. The docs state the contract: "The claude CLI, already authenticated. The run is unattended — a headless Claude that hits an auth or permission prompt aborts." This is a working proof that a full autonomous orchestrator can run purely on a Claude subscription by treating the authenticated CLI as the only auth boundary.

  • Login-shell PATH probe: at startup the daemon runs the operator's shell -ilc to capture the real $PATH (Homebrew/asdf/nvm), because a GUI/launchd-spawned daemon has a bare PATH and would fail to find claude. A hard time cap prevents a broken rc file from wedging startup — a classic unattended-run failure, solved in ~150 lines.
  • Docker sandboxes reuse subscription creds by bind-mount: ~/.claude/.credentials.json:ro is mounted into the container with HOME aligned so the harness finds it. Works — but mounting long-lived creds into a container that may run --dangerously-skip-permissions is a real blast-radius trade-off.
  • --allowedTools auto-allowlists the minted MCP tools so headless runs never die on a permission prompt.

Sources: docs/extensions-tutorial-claude.md:25-27, rpc/path-env.ts, sandbox/src/docker.ts:52-59, index.ts:398-406.

2.5 UI — three thin clients, one contract

All three front ends are pure JSON-RPC clients; no client owns storage. The GUI enforces exactly one invoke chokepoint (a single file may call Tauri invoke) and one listen chokepoint (a ref-counted event hub) — and a CI script lints that discipline. Two ideas stand out:

The state-aware composer

One text box whose verb follows the selected entity's state: on a running session it steers / follows-up / aborts; on a parked task it comments / resumes; on a bare task it enrolls. The owner never chooses a verb — the state does. This is exactly what a gosleep morning-review UI needs.

Replay-then-tail transcript streaming

Subscribe = replay history, then tail live events, deduped by a monotonic line cursor. During a live turn, ~40 ms-coalesced partial frames render a growing bubble, cleared when the durable line commits. Durable lines vs cosmetic partials cleanly split — the correct streaming contract for any dashboard.

Sources: gui/README.md (Architecture, ~:100-120), scripts/check-ipc-discipline.mjs, README.md:88-91.

2.6 Mobile / remote access

The transport is raw TCP JSON-RPC + a token — that's the whole stack. The daemon listens on 0.0.0.0:7077 by default; the first request on a TCP connection must be meta.auth {token} (32 random bytes hex, auto-minted at ~/.autosk/daemon-token, mode 0600). The iOS app (TestFlight) is the same Tauri app compiled for iPhone as a remote-only companion — full parity once connected: live transcripts, steer/abort mid-turn, park/resume, task CRUD, in a compact single-pane layout.

The three gaps = gosleep's mobile opportunity

No TLS (token crosses the wire in cleartext; no tunnel guidance at all), no push notifications (zero APNs code — the phone must be foreground + connected to see anything), and no relay (the phone reaches the daemon only on the same LAN or a DIY VPN). AutoSK proves the daemon side of "steer a live agent from your phone" is the easy 90%; a Tailscale-assumed transport + push-on-park would leapfrog it.

Sources: docs/daemon.md:69-90, 444-451, rpc/token.ts:1-40, gui/src-tauri/src/client/remote.rs:14-40, gui/README.md:258, 273-274.

2.7 Loop engineering — claimed vs implemented

The marketing is modest and honest: "a real pipeline you can watch, steer, and trust" — no "sleep while it works" claims, no scheduling, no self-healing. The code implements three nested, bounded loops, and the design philosophy is visible in every exit: bounded autonomy, park early, never spin.

3.2 How agents are spawned — crash-safe dispatch

  • Warren never spawns agent processes itself. It delegates to burrow over the socket in 3 steps: resolve the rendered agent definition and freeze it onto the run row (runs.rendered_agent_json — reproducibility); provision a workspace (seed files placed in one atomic round-trip, rollback on failure); dispatch the run.
  • Row-before-spawn: the run row is created before any burrow call, with runtime IDs nulled; IDs are attached as calls succeed. If the orchestrator dies mid-spawn, a reconciler finds rows with null runtime IDs and cleans up — failures transition queued → cancelled with best-effort destroy.
  • Placement before row-creation: a worker is picked first so runs.worker_id lands at creation; burrow→worker pinning stays sticky for cancel/steer/reap.
  • Agents are prompt definitions, not code. Built-ins include claude-code, planner, pr-fixer, healer, the leveret overseer — and two cron patrol agents: nightwatch (nightly: scan repo → produce a plan of fixes, never fixes itself; reap auto-dispatches a plan-run per plan) and bugwatch (2×/week: triage bugs → ≤3 conservative fix-plans). Planners plan; executors execute — a working owner-sleeps loop, on API-key economics.
  • Worker prompt discipline worth stealing (claude-code builtin): "Quality gates are terminal, not advisory. You are NOT done until the gate exits zero… If genuinely unfixable, say so explicitly and leave the work open rather than claiming success." The agent commits but never pushes — warren pushes host-side after the run terminates. Model tiering is pinned per builtin (Sonnet for scoped coding; operators raise to Opus per run).

Sources: src/runs/spawn/dispatch.ts:1-45, src/registry/builtins/nightwatch.ts:1-17, bugwatch.ts:1-23, claude-code.ts:24-30, model-tiers.ts.

3.3 State, persistence, recovery

Recover by re-attach, not restart

On boot, warren walks the runs table for {queued, running} rows with a live runtime id and re-attaches an event-stream bridge to each — a resume-sequence filter makes re-subscription idempotent. Rows in active states without a runtime id surface as skipped partial spawns for the operator. Restart recovery is a first-class, acceptance-tested path.

Re-wake from the transcript

When a conversation's anchoring run has died, warren spawns a fresh run seeded purely from the DB transcript — it survives the old workspace being destroyed; token cost grows with transcript length (accepted v1 trade-off). The direct answer to context exhaustion: kill the exhausted agent, seed a fresh one from the durable ledger — never "resume" dead context.

Belt-and-suspenders terminal detection

A run-state poller polls burrow in parallel with the event stream, so agents that never emit a terminal envelope still reach terminal state in warren.

Reap — the single terminal path

Every ending — clean, cancelled, watchdog-killed — routes through one reap pipeline: push the partial branch, open a PR, mirror memory/issue state, destroy the workspace, GC. Committed work is never lost, even when the killer is the watchdog.

Sources: src/runs/stream/recover.ts:1-13, 39-50, run-state-poller.ts:1-11, conversation-rewake.ts:1-21, src/runs/reap/.

3.4 Queues, scheduling, budgets

  • Cron triggers: .warren/triggers.yaml per project; an in-process scheduler tick dispatches on the same composition path as manual runs. Per-trigger maxCostUsd overrides the agent-level cap.
  • Serial plan-run dispatch — warren's "epic executor": a plan's children run one at a time, each gated on the previous PR merging before the next dispatches; re-dispatching a partially-done plan resumes from the next open child.
  • Cost caps enforced mid-run: the event bridge cancels + reaps a run when cumulative cost crosses the cap. Malformed cap values fail OPEN — "a budget typo must never silently cancel every run at $0".
  • Human gates with timeouts: an agent's question flips the run to paused; a human answers via API or the pause budget (default 30 min) elapses — then warren respawns a turn with the answer or a timeout warning folded in; the respawned agent re-reads state from disk. Autonomy never blocks forever on a human.
  • Idle coordinator: conversations idle >20 min are finalized (resources reclaimed) without being closed.

Sources: src/triggers/tick.ts, src/plan-runs/coordinator*.ts, src/runs/cost-cap.ts:1-31, src/runs/pause.ts:1-16, README.md:34-36.

3.5 The self-supervision stack — four layers, each watching a different failure class

Fig. 3a — Warren's four supervision layers. The asymmetry is deliberate: the substrate (burrow) is restarted in-process under a budget; the orchestrator (warren) is never restarted in-process — its crashes escalate to the outer layer. Sources: src/supervisor/main.ts:1-23, 78-80, 199-205, src/runs/watchdog.ts:1-47, detector-wiring.ts.

  • The heartbeat watchdog exists because of a real incident (2026-06-05: a stuck bash tool pinned biome at ~57 CPU-min forever; nothing reaped it). It detects silent-but-busy hangs the exit-code layer can't see: 30s tick over running runs; heartbeat = timestamp of the newest event; older than 45 min (deliberately generous) → watchdog.timed_out → cancel → route through reap so committed work still ships as a branch.
  • Design details worth copying verbatim: on by default ("a lifecycle-reclaim safety net must not depend on an operator remembering an env var"); single-flight ticks (an overlapping tick is dropped, not stacked); per-run error isolation (one bad row can't kill the loop); long-lived conversation runs exempted so idle ≠ hung; invalid config throws at boot ("a typo… fails loud rather than silently mis-arming the safety net").
  • Closed-loop healer: production alerts (Sentry/Grafana) → fingerprint → route to a project → dispatch a healer agent run, guarded by per-fingerprint max-retries + cooldown — so an alert storm can't become an agent storm.

3.6 UI & steering

Web SPA, CLI, and raw HTTP are "three thin clients of one pipeline". Live NDJSON event tail (GET /runs/:id/events?follow=1); steer-by-inbox — POST /runs/:id/steer drops a message into the agent's inbox, picked up at the next turn boundary (durable delivery, unlike a raw terminal keystroke); clean abort via cancel. The opt-in Workspace UI walks Shape (conversation with the leveret overseer) → Plan (planner run + human sign-off gate that arms dispatch) → Run (serial plan-run with per-child PR status) → Activity (unified human+agent timeline with inline answer-cards on open questions).

Sources: README.md:31-37.

3.7 Weaknesses — from gosleep's seat

BLOCKER  API-key economics

No subscription path at all. Every pattern transfers; the billing model doesn't. Warren's own cost-cap machinery exists because API spend is unbounded.

FRICTION  Cloud-shaped

Containers, Fly.io, bubblewrap, a resident server — a heavier operational footprint than a laptop-first, skill-driven system wants. The semantics port to launchd + tmux; the runtime doesn't need to.

TRADE-OFF  Re-wake cost curve

Re-seeding a fresh session from the whole DB transcript grows linearly with conversation length — acknowledged as a v1 trade-off. gosleep's compact handoffs are the cheaper equivalent.

The unifying principle (Warren, verbatim design rule)

Every liveness decision is made from durable state (DB event timestamps), never from in-memory beliefs — so every detector survives a warren restart for free, and the same logic works on the recovery path. For gosleep: heartbeat = ledger/handoff file mtimes and tmux liveness — never pane-content scraping, never what the orchestrator "remembers".

4.2 The supervision hierarchy — who watches whom

Fig. 4a — Overstory: a four-level work hierarchy watched sideways by a tiered watchdog. The coordinator is watched for death but not for hangs, and nothing restarts it — the same gap gosleep has one level up. Sources: src/watchdog/daemon.ts:1-22, 556-611, 892-903, triage.ts:1-7, 29-75, health.ts:4-31, 88-103, supervisor.ts:453, 472.

  • Death notifications: when the watchdog terminates a worker it sends a synthetic worker_died mail to the parent, so the coordinator never blocks forever waiting for worker_done; run completion counts zombies as terminal ("a run that mixes them strands the coordinator forever").
  • Forward-only state machine with CAS guards: booting < working < completed < stalled < zombie; completed → * is rejected so a late watchdog tick can't reclassify a clean exit as a zombie.
  • Failure memory: every watchdog intervention is recorded (agent, capability, reason, triage verdict) to the mulch memory store — institutional memory of how agents die, fire-and-forget so recording can't break the watchdog.

5Headless mode & the subscription question

Can gosleep run on a Claude Pro/Max subscription — legally, reliably, overnight? This section explains what claude -p actually is, reconstructs Anthropic's policy timeline with dated sources, and ends in an approach matrix. Claims are labelled FACT / COMMUNITY-REPORT where the evidence differs.

5.1 What claude -p actually is

Normally claude opens a chat UI in your terminal and waits. claude -p "do X" runs the exact same agent once, with no UI: it does the task, prints the answer, exits. It is not a different product or a raw API call — same model, same tools, same CLAUDE.md/skills/MCP context, same login. Two things change: (1) nobody can answer permission prompts — tools must be pre-approved via --allowedTools / --permission-mode, or the run aborts; (2) output becomes machine-readable — --output-format json (result + session id + cost) or stream-json (live event stream). The Agent SDK is the same engine in library form — it bundles and spawns the Claude Code binary and talks to it over stdio — but its docs only document API-key auth (that difference matters below).

FlagWhat it gives an orchestrator
-p / --printOne-shot non-interactive run; reads stdin (capped 10 MB since v2.1.128).
--output-format json|stream-jsonParseable result, session id, per-call cost; stream-json + --verbose --include-partial-messages = live token/event stream incl. system/init, system/api_retry.
--resume <id> / --continueMulti-step workflows across separate invocations — state persists; session lookup is scoped to the project dir + its worktrees.
--allowedTools / --disallowedToolsPermission-rule syntax (Bash(git commit *)) — the whole safety model for unattended runs.
--permission-modeBaseline posture; dontAsk = fully non-interactive deny-by-default.
--permission-prompt-toolDelegate approvals to your own MCP tool — programmatic human-in-the-loop.
--max-turns, --max-budget-usdHard caps per run (budget cap is print-mode only).
--bareSkip ALL auto-discovery for reproducible CI runs. ⚠ Also skips OAuth/keychain — subscription login does NOT work in bare mode; docs say bare "will become the default for -p in a future release" — a flag change worth pinning against.

Auth precedence in headless mode (highest wins): cloud-provider creds → ANTHROPIC_AUTH_TOKEN → ANTHROPIC_API_KEY ("in non-interactive mode the key is always used when present" — a stray exported key silently hijacks your subscription; unset it) → apiKeyHelper → CLAUDE_CODE_OAUTH_TOKEN (from claude setup-token: official, one-year, subscription-backed token for CI, accepted first-class by anthropics/claude-code-action) → subscription OAuth from /login, the Pro/Max default. Bottom line: claude -p on a logged-in Pro/Max machine just works on the subscription, by design, today.

5.3 Where this leaves gosleep today (2026-07-07)

Interactive tmux + Agent Teams — the protected surface

Third-party harnesses on OAuth — never

The realistic risk is tightening, not banning

Anthropic just built a metering system for headless — you don't meter what you intend to kill. Mitigation: design every autonomous loop to degrade to wait-for-window (Ralph's pattern), and keep an ANTHROPIC_API_KEY escape-hatch config path (same CLI, one env var), OFF by default.

6.1 Gastown + Beads (Steve Yegge) — gosleep at 10× scale

Model

A Town holds Rigs (one per repo). Each rig has Crew (human workspace), Polecats (workers — persistent identity, ephemeral sessions) and Hooks (git-worktree-backed storage that survives crashes). The Mayor — a Claude Code instance with full workspace context — is the coordinator you talk to. Convoys bundle work; convoys labeled mountain get autonomous stall detection and smart skip logic for epic-scale runs. All work state lives in Beads — Yegge's git-backed issue tracker (~24k★) — so "agent memory" is structured data in git, not conversation history.

Verdict for gosleep

The mapping is 1:1 — Mayor≈orchestrator, polecats≈workers, Beads≈Jira/GH+handoffs, hooks≈worktrees. What gosleep lacks and gastown has: zombie-session detection, mailbox handoffs, per-worker persistent identity, convoy stall detection. Go codebase — hard to vendor, but the ideas port cheaply.

6.2 Ralph (frankbria/ralph-claude-code) — the overnight-loop engine

Geoffrey Huntley's "Ralph Wiggum" technique (Jul 2025): an infinite shell loop re-invoking the agent with the same prompt file, filesystem as memory — famous for months-long runs. This is the best-maintained implementation (bash, v0.11.5, 784 tests) and GoSleep's literal namesake problem is what its hardening solves:

Dual-condition exit gate

Exit needs ≥2 heuristic completion indicators AND an explicit EXIT_SIGNAL: true in a structured status block — preventing both premature exit (docs containing the word "done") and infinite loops.

Circuit breaker

CLOSED→HALF_OPEN→OPEN on: 3 no-progress loops, 5 same-error loops, >70% output decline, 2 permission-denial loops; cooldown auto-recovery for unattended runs.

Quota auto-wait

4-layer limit detection (timeout guard → structural rate_limit_event → filtered text → Extra-Usage exhaustion); unattended mode waits for the window to reset instead of dying. The single most gosleep-relevant pattern in the ecosystem.

Question detection & file protection

Catches Claude asking questions instead of acting (headless has no human) and injects corrective guidance next loop; granular allowlists + per-loop integrity checks stop the agent deleting its own control files.

Loop mechanics: build context (loop #, remaining fix_plan.md tasks, breaker state, previous-loop summary) → invoke claude -p --output-format json with --allowedTools and session --resume → analyze JSON → continue/exit. Plus: rate limiter (100 calls/h), git backup branches + rollback, tmux monitor dashboard, GitHub-issue queue. Strategic read (ADR 0001): the maintainer bets headless moves to API-credit billing, refuses TUI-driving hacks as ToS-adversarial, and goes provider-agnostic. Details worth stealing: only Claude and Gemini support race-free pre-assigned session ids (--session-id at create); "unsupported features degrade with a logged warning, never a silent misbehavior."

8What gosleep adopts — the merged, ranked plan

De-duplicated across all three research reports. Tier 1 = do now, ordered by leverage; Tier 2 = next, cheap or already half-built; then the explicit do-not-adopt list. Source tags: ASK AutoSK · W/O Warren/Overstory · ECO ecosystem report.

Tier 1 — the six moves that change what gosleep is

  1. Heartbeat file + external mechanical watchdog with restart budget & human escalation V highE medR lowW/O

    Each orchestrator pulse appends {ts, context%, fleet} to a fixed file (the write is the FIRST act of the pulse). A launchd agent every 2–5 min checks session-exists / heartbeat-age / context-ceiling; dead → respawn from the cold-start protocol (re-attach, never respawn workers); stale → one nudge then kill by explicit id; budget 3-in-60-min, then stop and escalate. Warren's supervisor + watchdog semantics transplanted onto tmux. Removes "orchestrator died at 3am, fleet idled until morning" — the single biggest gap.

  2. Park-to-human as the single failure sink, with an explanatory note V highE lowR lowASK

    Every failure mode — crash, no-handoff, cap hit, watchdog kill, structural drift — converges on ONE parked state with a machine-written explanation, forming the owner's morning queue. gosleep has BLOCKED_ON_HUMAN; this generalizes it into the universal sink with an auditable reason field.

  3. Persisted, human-resettable loop budgets — the full vocabulary V highE lowR lowASKECO

    AutoSK's three tiers (turn corrections ×3 → step-visit caps → park) merged with Ralph's breaker thresholds (no-progress ×3, same-error ×5, output-collapse, permission-denial ×2) and dual-condition exit gate. Counters live in the ledger/task files, not memory — the owner can pardon a parked task from any editor and the morning state is auditable.

  4. Quota auto-wait, grown into usage-window-aware fleet scheduling V highE medR lowECOASK

    Detect subscription-limit exhaustion (Ralph's 4-layer detection), quiesce the fleet cleanly, and auto-resume when the window resets — instead of AutoSK's park-everything-at-1am. Nobody in the landscape ships this; it is gosleep's namesake feature.

  5. Push-on-park notifications (ntfy / Telegram / APNs) V highE lowR lowASK

    The moment work parks for a human — or the watchdog escalates — the owner's phone knows. Zero tools in the survey have this; it is the difference between "runs unattended" and "safe to sleep on".

  6. Recovery = re-attach + reconcile, never blind respawn (harden the cold-start path) V highE lowR lowW/O

    Warren's recover.ts pattern: walk durable state, re-attach to live workers, surface partial spawns; re-wake = fresh orchestrator seeded from the ledger, never "resume" dead context. Mostly encoded in the skill already — make it the watchdog's respawn prompt and acceptance-test it.

Explicitly NOT adopting

  • Ruflo / claude-flow — API-only, banned-on-subscription category, hype-heavy.
  • vibe-kanban — company shut down 2026-04-10; maintenance risk.
  • GUI managers (Conductor / Crystal) — wrong form factor for a tmux/skill system.
  • TUI-driving hacks (maestro-p style) — ToS-adversarial per Ralph's ADR; unnecessary — Agent Teams is sanctioned.
  • Paired orchestrators (active/standby) — split-brain risk; nobody shipped it; extra watch tiers didn't earn their keep (Overstory deprecated its own).
  • Continuous AI patrol agents — Overstory built it, Warren deleted it; AI belongs in bounded on-anomaly triage only.
  • Vendoring Beads / a DB — Jira + GH Issues + handoff files already play that role; files won the state argument twice (AutoSK v2, our own ledger).
The one-paragraph strategy

Keep the engine exactly where it is — interactive Agent Teams on the subscription's interactive quota, the surface Anthropic keeps protecting. Wrap it in Warren-grade supervision (heartbeat + dumb external watchdog + restart budget), AutoSK-grade failure discipline (park-to-human with reasons, persisted budgets), and Ralph-grade loop hardening (breaker, exit gate, quota auto-wait). Then ship the two features nobody else has — push-on-park and window-aware resume — and gosleep is, by construction, the safest thing in this landscape to sleep on.
