0Как читать этот отчёт — базовые понятия

Отчёт не требует предварительного контекста. Все системы ниже собраны из одного и того же словаря; вот этот словарь простым языком. Сложные термины дополнительно поясняются при первом появлении внутри разделов.

Оркестратор / воркер
Разделение, к которому приходят все системы: оркестратор решает, что делать дальше, запускает воркеров, следит за ними и общается с человеком; воркеры — одноразовые агенты, каждый из которых выполняет один ограниченный кусок работы и завершается. Скилл gosleep требует «чистого оркестратора», который сам не выполняет ничего.
Headless-режим / claude -p
Обычно claude открывает интерактивный чат в терминале. claude -p "сделай X" (--print) запускает того же самого агента один раз, без интерфейса: он выполняет задачу, печатает результат и завершается — Claude Code как Unix-команда, которую можно пайпить, скриптовать, ставить в cron и зацикливать. Та же модель, те же инструменты, тот же логин; но отвечать на запросы разрешений некому — инструменты нужно разрешать заранее.
stream-json (NDJSON через stdio)
Машиночитаемый диалект headless-режима: --output-format stream-json --input-format stream-json превращает агента в живой поток событий (один JSON-объект на строку) на stdout и принимает новые сообщения — вплоть до прерывания посреди хода — на stdin. Так программа «разговаривает» с работающим headless-агентом.
Подписка vs API-ключ
Два способа платить за Claude. Подписка Pro/Max — фиксированная цена с окнами использования (скользящее 5-часовое окно плюс недельные лимиты), покрывает официальные приложения, включая Claude Code. API-ключ — оплата за токены без потолка. Вопрос «на чём может работать инструмент» — единственный, который сегодня сортирует весь ландшафт оркестраторов (§5).
tmux / панель (pane)
Терминальный мультиплексор: одно окно терминала делится на независимые панели, каждая со своим процессом, переживающие отключения. gosleep, Gastown, Claude Squad и запасной режим Overstory — все запускают интерактивные сессии claude в панелях tmux, чтобы человек мог подключиться и наблюдать любого агента вживую.
Agent Teams
Штатный мультиагентный примитив Claude Code (~февраль 2026): одна ведущая сессия порождает сессии-тиммейты с собственными контекстными окнами, обменом сообщениями и общим списком задач — всё внутри официального клиента, то есть на интерактивной квоте подписки. Это текущая поверхность gosleep.
Git worktree
Второй (третий, …) рабочий каталог, выписанный из одного и того же репозитория. Каждому агенту — свой worktree, чтобы параллельные агенты не перезаписывали файлы друг друга; слияние обратно — через ветки. Стандартная единица изоляции во всём ландшафте.
MCP (Model Context Protocol)
Стандарт, дающий агенту дополнительные инструменты через сеть или сокет. AutoSK поднимает крошечный приватный MCP-сервер на каждую сессию агента, чтобы агент вызывал инструменты управления (например, «переведи задачу на следующий шаг») как обычные tool-вызовы, которые валидирует хост.
Watchdog («сторожевой пёс»)
Надзирающий процесс, который периодически проверяет, живы ли агенты и есть ли прогресс, и вмешивается (подтолкнуть → убить → эскалировать), когда прогресса нет. Ключевой вопрос дизайна: watchdog механический (простой детерминированный код) или сам является ИИ? Ответ отрасли жёстко сошёлся на механическом (§4, §8).
Heartbeat («пульс»)
Периодическое, долговечное доказательство жизни: «самая свежая отметка времени, которую компонент записал на диск / в БД». Живость судится по этой записи — никогда по факту существования процесса и никогда по тому, что надзиратель помнит. Warren и Overstory пришли к этому правилу независимо.
Park-to-human («парковка на человека»)
Универсальный сток отказов: когда агент падает, зацикливается, превышает бюджет или не может решить, задача не ретраится молча — она паркуется в состояние «ждёт человека» с пояснительной запиской. Множество запаркованных задач — это и есть утренняя очередь владельца.
Handoff / леджер
Словарь gosleep: handoff — самодостаточный документ, который агент пишет, чтобы свежий агент (с нулевой памятью) мог продолжить; леджер (ORCHESTRATION-STATE.md) — файл состояния оркестратора на диске. Другие системы держат ту же информацию в файлах задач (AutoSK) или в базе данных (Warren).
Kickback / цикл поправок
Страховка AutoSK на уровне хода: если агент закончил ход, не объявив требуемый переход, хост переспрашивает его с поправкой — максимум N раз (по умолчанию 3), — затем паркует задачу на человека. Ограниченные повторы с единственным выходом, никогда не бесконечный цикл.
Circuit breaker («автоматический выключатель»)
Страховка Ralph на уровне цикла, по аналогии с электрикой: цикл «выбивает пробки», когда видит отсутствие прогресса, повтор одной и той же ошибки или резкое падение вывода — и остывает перед новой попыткой, вместо того чтобы жечь квоту на застрявшем цикле.
Окно использования / квота
Лимиты подписки приходят окнами: скользящее 5-часовое окно плюс недельные потолки (с 2025-08-28). Когда окно исчерпано, все агенты на этом логине встают разом. Ночной автономии поэтому нужно ожидание с учётом окна, а не просто обработка ошибок.
Spawn-per-turn / свежий контекст на шаг
Вместо одного долгоживущего агента, у которого медленно заполняется контекстное окно, — свежий процесс на каждый шаг/ход, а всё состояние в файлах или БД. Исчерпание контекста не побеждают — его проектируют прочь. AutoSK, поздний Overstory и цикл-воркеры gosleep сходятся именно здесь.
Демон (daemon)
Фоновая служба, работающая независимо от терминала — autoskd у AutoSK владеет всем состоянием и обслуживает все интерфейсы; Warren сам является сервером. У gosleep демона пока нет: оркестратор — это интерактивная сессия.

ПОДТВЕРЖДЕНО  Ключевые ставки gosleep — точки схождения всей отрасли

Независимо от нас сильнейшие проекты пришли к тем же основам, на которых уже стоит gosleep: состояние в простых файлах / долговечных записях (AutoSK отказался от БД версии v1 в пользу файлов), свежий контекст на каждый шаг вместо борьбы с компакцией, интерактивный CLI в tmux как легальная для подписки поверхность запуска (Gastown, Claude Squad) и восстановление через переподключение + сверку с долговечным состоянием, а не слепой перезапуск (Warren). Наша архитектура не экзотика — это формирующийся стандарт, минус несколько слоёв закалки.

СДВИГ ПОЛИТИКИ  Ставка на подписку выживает — но headless теперь тарифицируется

С января по апрель 2026 Anthropic отрезала сторонние обвязки от OAuth подписок, а в июне выделила программное использование (claude -p, SDK, CI) в отдельный месячный пул кредитов ($20 Pro / $100 Max 5x / $200 Max 20x по прейскуранту API). Интерактивный Claude Code — поверхность gosleep (tmux + Agent Teams) — явно не затронут и остаётся самой щедрой поверхностью по $/токен. Вердикт: интерактивная квота — двигатель; headless — ограниченный «клей» (§5).

КОНВЕРГЕНЦИЯ  Отрасль вытолкнула LLM из контура надзора

Overstory построил четырёхуровневый watchdog с ИИ-триажем и агентом-монитором; его наследник Warren оставил один механический 30-секундный тик по долговечным heartbeat'ам и убрал ИИ из надзора совсем. Все циклы AutoSK — ограниченные счётчики с единственным выходом на человека. Урок для дыры gosleep «кто следит за оркестратором»: наблюдатель должен быть глупым кодом над долговечным состоянием — LLM место внутри ограниченных запусков, а не в контуре управления (§4).

ДЫРЫ = ВОЗМОЖНОСТЬ  Никто не делает две функции, которые нужнее всего системе «владелец спит»

Во всём ландшафте ни один инструмент не уведомляет никого, когда работа паркуется на человека (парковки AutoSK молчаливы; флот может тихо умереть в час ночи), и ни один не учитывает окна квоты (исчерпание паркует всё; ничто не возобновляется по сбросу окна — только Ralph умеет ждать). Push-по-парковке и планирование с учётом окон — самые ясные дифференциаторы gosleep (§8).

ТОП ЗАИМСТВОВАНИЙ  Пять самых ценных трансплантаций
  • Внешний механический watchdog над heartbeat-файлом оркестратора, с бюджетом перезапусков (семантика супервизора Warren на tmux).
  • Park-to-human как единственный сток отказов с пояснительной запиской (AutoSK) — утренняя очередь владельца.
  • Персистентные, сбрасываемые человеком бюджеты циклов: поправки хода → лимиты визитов шага → парковка (AutoSK) + circuit breaker и exit gate от Ralph.
  • Автоожидание квоты (Ralph), выращенное до планирования флота с учётом окон.
  • Обвязка claude -p stream-json для ограниченного headless-клея — проверенный сетевой паттерн (драйвер AutoSK).
ЭКОНОМИКА  Широкие рои проиграли спор

Собственная само-критика Overstory в репозитории (STEELMAN.md): рой из 20 агентов сделал 15 задач за 6 часов и ~$60 токенов там, где один агент сделал то же за 8 часов и ~$9 — экономия двух часов куплена за $51 накладных расходов на координацию. Ответ Warren: последовательное исполнение с PR-гейтом, по одной задаче за раз. Лимит gosleep в ~3 панели и дисциплина «один коммит на задачу» уже на правильной стороне этого размена (§4).

2.2 Архитектура

Рис. 2a — AutoSK: три тонких клиента над одним демоном, который владеет всем состоянием в виде файлов и гоняет каждый шаг workflow как свежий headless-подпроцесс claude -p. Источники: AGENTS.md:6-19, daemon/extensions/claude-agent/src/index.ts:386-396, engine.ts:48-57.

Как запускаются агенты — точный механизм

Агенты — это headless-подпроцессы CLI, говорящие NDJSON через stdio — без PTY, без tmux, без Agent SDK. Расширение для claude запускает claude -p --output-format stream-json --input-format stream-json --verbose --include-partial-messages --replay-user-messages, по умолчанию --permission-mode acceptEdits, опционально --dangerously-skip-permissions — только для запусков в изоляции worktree. ClaudeDriver оборачивает дочерний процесс: парсит поток событий, зеркалит сообщения 1:1 в транскрипт, склеивает частичные дельты с шагом ~40 мс в эфемерный «partial»-канал. Руление живым запуском решено на уровне протокола: steer во время стриминга пишет фрейм {type:"control_request", request:{subtype:"interrupt"}}, затем новое сообщение; follow-up встаёт в очередь после текущего хода.

Источники: claude-agent/src/index.ts:386-413, driver.ts:60-126, 254-272, 487-489.

Протокол transit — как заканчивается шаг

Агент обязан завершить шаг вызовом MCP-инструмента mcp__autosk__transit {to: "<шаг>|done|cancel|human"} — модель объявляет переход workflow валидируемым tool-вызовом. Тонкость: на MCP-сервере инструмент лишь подтверждает приём; драйвер видит tool_use в потоке, а код на стороне хоста коммитит переход после окончания хода. Если ход закончился без transit или хук onTransit отклонил цель, цикл kickback переспрашивает с поправкой (бюджет: 3); когда бюджет исчерпан, движок паркует задачу в human с причиной agent_did_not_transit. Это та самая дисциплина «агент обязан явно передать эстафету или запарковаться», которой хотят фазовые гейты gosleep, — сделанная механической.

Источники: driver.ts:18-21, 385-389, index.ts:225-269.

Планировщик — диспетчеризация без гонок и без БД

  • По событиям, а не поллингом: transit/enroll/resume/завершение пинают слитый скан (сканы не перекрываются); 30-секундный страховочный рескан подхватывает внешние правки файлов.
  • Создание сессии как захват (claim): скан «забирает» задачу, создавая queued-сессию — гарантия одной сессии на задачу; перед захватом задача перечитывается заново («снапшоту никогда не доверяют»).
  • Порядок «commit до финализации»: закрывающаяся сессия СНАЧАЛА записывает новую позицию задачи, пока сама ещё running (живая → сканы её пропускают), и только потом помечает свою мету терминальной — окно двойной диспетчеризации закрыто.
  • Интерактивные чаты живут вне ограниченного пула, чтобы простаивающий чат не задушил 4-воркерный планировщик задач.
  • Изоляция принадлежит агенту, а не движку: движок упразднил абстракцию изоляции; агент оборачивает себя сам через @autosk/sandbox (git worktree на задачу или docker-контейнер, достающий хостовый MCP через host.docker.internal), с финальным шагом cleanup в workflow.

Источники: engine.ts:1-20, 48-57, 363-453, session.ts:30-35, 309-341, пакет sandbox, README.md:149-151.

2.3 Состояние и живучесть

Всё состояние — простые файлы в <проект>/.autosk/, БД нет нигде (v2 выбросила БД из v1). tasks/<id>/task.json красиво отформатирован и по контракту редактируем человеком; сессия — мета-JSON плюс JSONL-транскрипт. Дисциплина записи — продакшен-уровня:

Атомарная запись, байт-стабильный формат

Каждая мутация: temp-файл в том же каталоге → fsync temp → rename → fsync родительского каталога. Сериализаторы собирают записи с фиксированным порядком ключей; golden-тесты фиксируют точные байты — «любое байтовое изменение обязано уронить тест». Читатели никогда не видят рваных записей.

Конкурентность без транзакций

KeyedMutex сериализует read-modify-write по id задачи; разные ключи идут параллельно. Вместе с атомарным rename это полностью заменяет транзакции БД. Сигнатура изменения (mtime:ctime:size:ino) питает кэш чтения и позволяет вотчеру узнавать собственные записи демона (подавление эха).

Внешние правки сверяются

Рекурсивный fs.watch + рескан каждые 5с сходятся в одну сверку: принять/отклонить по политике владения (движок владеет status/step/workflow, пока сессия жива). Вотчер «намеренно глупый — без диффов». Люди и агенты могут править task.json напрямую — это часть контракта.

Восстановление после крэша = собрать и запарковать

На старте демона любая сессия, оставшаяся running/queued → failed: daemon_restart, в транскрипт дописываются структурные строки ошибки, а задача паркуется в human. Автовозобновления нет; захваченный session_id сохраняется «для будущего --resume», но не используется. Каждое обновление демона наполняет очередь человека.

Переживание исчерпания контекста: внутри запуска нет никакой обработки чекпоинтов/компакции. Каждый шаг workflow — свежий процесс claude -p со свежим контекстом; долговечное состояние пересекает границы шагов через task.json + комментарии + git worktree — никогда через контекст агента. Состояние циклов (счётчики metadata.step_visits) хранится в файле задачи, так что человек может распарковать задачу и сбросить её бюджет из любого текстового редактора — хоть с телефона.

Источники: store/paths.ts:1-15, store/atomic.ts:1-24, store/records.ts:1-15, store/lock.ts, store/watcher.ts:1-14, engine.ts:483-508, transition.ts:80-95, driver.ts:195-196, 363.

2.4 Аутентификация — нативно на подписке, проверено

Вердикт: нигде нет ни строчки кода про API-ключи

Во всей кодовой базе нет обработки ANTHROPIC_API_KEY / OAuth / токенов (grep по daemon/, gui/, cmd/ — ни одного попадания). AutoSK просто запускает уже аутентифицированный claude CLI оператора из $PATH. Контракт прописан в доках: «claude CLI, уже аутентифицированный. Запуск без присмотра — headless-Claude, упёршийся в промпт авторизации или разрешения, аварийно завершается». Это работающее доказательство: полноценный автономный оркестратор может жить на чистой подписке Claude, если единственной границей аутентификации считать залогиненный CLI.

  • Проба PATH через логин-шелл: на старте демон выполняет шелл оператора с -ilc, чтобы получить настоящий $PATH (Homebrew/asdf/nvm) — демон, запущенный из GUI/launchd, имеет голый PATH и не нашёл бы claude. Жёсткий таймаут не даёт битому rc-файлу заклинить старт. Классическая беда автономных запусков, решённая в ~150 строк.
  • Docker-песочницы переиспользуют креды подписки через bind-mount: ~/.claude/.credentials.json:ro монтируется в контейнер с выровненным HOME. Работает — но монтировать долгоживущие креды в контейнер, который может бежать с --dangerously-skip-permissions, — реальный размен на радиус поражения.
  • --allowedTools автоматически разрешает поднятые MCP-инструменты, чтобы headless-запуски никогда не умирали на промпте разрешений.

2.5 UI — три тонких клиента, один контракт

Все три фронтенда — чистые JSON-RPC-клиенты; ни один не владеет хранилищем. В GUI ровно одна точка invoke (только один файл может звать Tauri invoke) и одна точка listen (событийный хаб со счётчиком ссылок) — и CI-скрипт линтит эту дисциплину. Две идеи выделяются:

Композер, знающий состояние

Одно поле ввода, чей глагол следует за состоянием выбранной сущности: у бегущей сессии оно рулит / дошлёт / прервёт; у запаркованной задачи — комментирует / возобновляет; у голой задачи — зачисляет в workflow. Владелец никогда не выбирает глагол — его выбирает состояние. Ровно то, что нужно утреннему UI gosleep.

Стриминг транскрипта replay-then-tail

Подписка = проиграть историю, затем хвостить живые события, дедуп по монотонному курсору строк. Во время живого хода «partial»-кадры (склейка ~40 мс) рисуют растущий пузырь, который очищается при коммите долговечной строки. Долговечные строки и косметические partial'ы чисто разделены — правильный контракт стриминга для любого дашборда.

2.6 Мобильный / удалённый доступ

Транспорт — сырой TCP JSON-RPC + токен, и это весь стек. Демон слушает 0.0.0.0:7077 по умолчанию; первый запрос TCP-соединения обязан быть meta.auth {token} (32 случайных байта hex, автоматически создаётся в ~/.autosk/daemon-token, права 0600). iOS-приложение (TestFlight) — тот же Tauri, собранный под iPhone как чисто удалённый компаньон: после подключения полный паритет — живые транскрипты, steer/abort посреди хода, парковка/резюм, CRUD задач, в компактной однопанельной вёрстке.

Три дыры = мобильная возможность gosleep

Нет TLS (токен ходит по сети открытым текстом; никаких рекомендаций про туннели), нет push-уведомлений (ноль кода APNs — телефон должен быть на переднем плане и подключён, иначе не увидит ничего) и нет релея (телефон достаёт демона только в одной LAN или через самодельный VPN). AutoSK доказывает: серверная сторона «рулить живым агентом с телефона» — это лёгкие 90%. Транспорт с расчётом на Tailscale + push-по-парковке обошли бы его одним прыжком.

2.7 Инженерия циклов — заявлено vs реализовано

Маркетинг скромный и честный: «настоящий конвейер, который можно наблюдать, рулить и которому можно доверять» — никаких «спите, пока оно работает», никакого планировщика, никакого само-исцеления. Код реализует три вложенных ограниченных цикла, и философия видна в каждом выходе: ограниченная автономия, парковаться рано, никогда не крутиться вхолостую.

3.2 Как запускаются агенты — краш-безопасная диспетчеризация

  • Warren никогда сам не спавнит процессы агентов. Он делегирует burrow через сокет в 3 шага: разрешить отрендеренное определение агента и заморозить его на строке запуска (runs.rendered_agent_json — воспроизводимость); подготовить рабочее пространство (seed-файлы кладутся одним атомарным раундтрипом, откат при сбое); диспетчеризовать запуск.
  • Строка до спавна: строка запуска создаётся до любого вызова burrow, с занулёнными runtime-id; id подставляются по мере успеха вызовов. Если оркестратор умрёт посреди спавна, реконсилер найдёт строки с null-id и приберёт — сбои переводят queued → cancelled с best-effort уничтожением.
  • Размещение до создания строки: воркер выбирается заранее, так что runs.worker_id ложится при создании; привязка burrow→воркер остаётся липкой для cancel/steer/reap.
  • Агенты — промпт-определения, а не код. Среди встроенных: claude-code, planner, pr-fixer, healer, надзиратель leveret — и два cron-патрульных агента: nightwatch (еженощно: сканировать репозиторий → выдать план исправлений, никогда не чинит сам; reap авто-диспетчеризует plan-run на каждый план) и bugwatch (2 раза в неделю: триаж багов → ≤3 консервативных фикс-плана). Планировщики планируют; исполнители исполняют — работающий цикл «владелец спит», на экономике API-ключа.
  • Дисциплина промпта воркера, которую стоит украсть (builtin claude-code): «Quality gates are terminal, not advisory. Ты НЕ закончил, пока гейт не выходит нулём… Не объявляй задачу завершённой с красным гейтом… Если действительно нечинимо — скажи это явно и оставь работу открытой, вместо того чтобы объявлять успех». 3.3 Состояние, персистентность, восстановление

Восстановление = переподключиться, а не перезапустить

На загрузке warren проходит таблицу запусков по строкам {queued, running} с живым runtime-id и заново подключает мост событийного стрима к каждой — фильтр resume-seq делает переподписку идемпотентной. Активные строки без runtime-id всплывают оператору как skipped — частичные спавны. Восстановление после рестарта — первоклассный путь, покрытый приёмочными тестами.

Re-wake из транскрипта

Когда якорный запуск разговора умер, warren спавнит свежий запуск, засеянный чисто из транскрипта в БД — переживает уничтожение старого рабочего пространства; цена в токенах растёт с длиной транскрипта (принятый v1-размен). Прямой ответ на исчерпание контекста: убить исчерпанного агента, засеять свежего из долговечного леджера — никогда не «оживлять» мёртвый контекст.

Двойная детекция терминальности

Поллер состояний опрашивает burrow параллельно событийному стриму — агенты, так и не выславшие терминальный конверт, всё равно доходят до терминального состояния в warren.

Reap — единственный терминальный путь

Любое окончание — чистое, отменённое, убитое watchdog'ом — идёт через один reap-конвейер: запушить частичную ветку, открыть PR, отзеркалить память/issue-состояние, уничтожить workspace, GC. Закоммиченная работа не теряется никогда, даже если убийца — watchdog.

  • Cron-триггеры: .warren/triggers.yaml на проект; внутренний тик планировщика диспетчеризует по тому же пути композиции, что и ручные запуски. maxCostUsd триггера перекрывает лимит уровня агента.

  • Лимиты стоимости применяются посреди запуска: событийный мост отменяет + рипает запуск, когда накопленная стоимость пересекает лимит. Кривые значения лимита fail OPEN — «опечатка в бюджете не должна молча отменять каждый запуск на $0».
  • Человеческие гейты с таймаутами: вопрос агента переводит запуск в paused; человек отвечает через API или истекает бюджет паузы (по умолчанию 30 минут) — тогда warren респавнит ход с ответом или с предупреждением о таймауте в промпте; респавненный агент перечитывает состояние с диска. Автономия никогда не блокируется на человеке навечно.
  • Координатор простоя: разговоры, простаивающие >20 минут, финализируются (ресурсы возвращаются) без закрытия самого разговора.

Источники: src/triggers/tick.ts, src/plan-runs/coordinator*.ts, src/runs/cost-cap.ts:1-31, src/runs/pause.ts:1-16, README.md:34-36.

3.7 Слабости — с кресла gosleep

БЛОКЕР  Экономика API-ключа

Пути через подписку нет вообще. Все паттерны переносимы; модель оплаты — нет. Собственная машинерия лимитов стоимости у warren существует потому что API-траты безграничны.

ТРЕНИЕ  Облачная форма

Контейнеры, Fly.io, bubblewrap, резидентный сервер — операционный след тяжелее, чем нужно laptop-first системе на скиллах. Семантика переносится на launchd + tmux; рантайм тащить не нужно.

РАЗМЕН  Кривая стоимости re-wake

Пересев свежей сессии из всего транскрипта БД растёт линейно с длиной разговора — признанный v1-размен. Компактные handoff'ы gosleep — более дешёвый эквивалент.

Объединяющий принцип (Warren, дословное правило дизайна)

Каждое решение о живости принимается из долговечного состояния (отметки событий в БД), никогда из убеждений в памяти — поэтому каждый детектор бесплатно переживает рестарт warren, и та же логика работает на пути восстановления. Для gosleep: heartbeat = mtime леджера/handoff-файлов и живость tmux — никогда скрейпинг содержимого панели, никогда то, что оркестратор «помнит».

5Headless-режим и вопрос подписки

Может ли gosleep работать на подписке Claude Pro/Max — легально, надёжно, всю ночь? Этот раздел объясняет, что такое claude -p на самом деле, восстанавливает хронологию политики Anthropic по датированным источникам и заканчивается матрицей подходов. Утверждения помечены как ФАКТ / СООБЩЕСТВО там, где доказательная база различается.

5.1 Что такое claude -p на самом деле

Обычно claude открывает чат в терминале и ждёт. claude -p "сделай X" запускает того же самого агента один раз, без интерфейса: выполняет задачу, печатает ответ, выходит. Это не отдельный продукт и не сырой вызов API — та же модель, те же инструменты, тот же контекст CLAUDE.md/скиллов/MCP, тот же логин. Меняются две вещи: (1) на промпты разрешений отвечать некому — инструменты нужно предодобрить через --allowedTools / --permission-mode, иначе запуск аварийно завершается; (2) вывод становится машиночитаемым — --output-format json (результат + session id + стоимость) или stream-json (живой поток событий). Agent SDK — тот же движок в виде библиотеки: он упаковывает и спавнит бинарник Claude Code и говорит с ним через stdio, — но его документация описывает только аутентификацию по API-ключу (эта разница важна ниже).

5.3 Что это значит для gosleep сегодня (2026-07-07)

Интерактивный tmux + Agent Teams — защищённая поверхность

Текущий подход gosleep остаётся на интерактивной квоте (5-часовое + недельные окна) — намного щедрее на доллар, чем кредиты по API-ставкам; явно не затронут ни одной волной ограничений; и это именно та поверхность, которую Anthropic раз за разом оставляла подписчикам, отрезая всё остальное.

claude -p — легально, поддерживается, ограничено бюджетом

Всё ещё работает на подписочном логине, но с ~06-15 берёт из программного пула по прейскуранту API. Активный ночной headless-флот на Max 20x (≈$200/мес кредита) может сжечь его за считанные дни. Использовать для ограниченного клея — генерация отчётов, проверки watchdog'а, CI — а не как основной двигатель.

Сторонние обвязки на OAuth — никогда

Заблокировано технически (2026-01-09), запрещено в ToS (02-19), коммерчески прекращено (04-04). Никогда не подавать подписочный OAuth-токен во что-либо, кроме Claude Code / claude.ai — включая Agent SDK.

Реалистичный риск — ужесточение, а не запрет

Anthropic только что построила систему тарификации headless — не тарифицируют то, что собираются убить. Митигируем: каждый автономный цикл деградирует до «ждать окна» (паттерн Ralph), плюс запасной путь конфигурации с ANTHROPIC_API_KEY (тот же CLI, одна env-переменная), по умолчанию ВЫКЛ.

Механизмы спавна ниже проверены по клонированным исходникам там, где это отмечено.

Первая партия (Anthropic) — санкционированный набор. Claude Code поставляет четыре мультиагентных примитива: сабагенты, скиллы, Agent Teams (~февраль 2026, экспериментальный флаг; лид спавнит тиммейтов с собственными контекстными окнами, обменом сообщениями и общим списком задач — поверхность gosleep) и workflows (research preview, июнь 2026). 6.1 Gastown + Beads (Steve Yegge) — gosleep в 10-кратном масштабе

Модель

Town содержит Rigs (по одному на репозиторий). У каждого рига есть Crew (рабочее место человека), Polecats (воркеры — постоянная идентичность, эфемерные сессии) и Hooks (хранилище на git worktree, переживающее крэши). The Mayor («Мэр») — инстанс Claude Code с полным контекстом воркспейса — координатор, с которым разговариваешь. Convoys группируют работу; конвои с меткой mountain получают автономную детекцию застоя и умный пропуск для запусков масштаба эпиков. Всё рабочее состояние живёт в Beads — git-нативном трекере issue от Yegge (~24k★): «память агента» — структурированные данные в git, а не история разговора.

Вердикт для gosleep

Спавн (проверен в исходниках): tmux-сессии с интерактивным claude (internal/polecat/session_manager.go), включая детекцию «зомби-сессий — tmux жив, а Claude мёртв». Совместим с подпиской по построению. Заявка: «4–10 агентов превращаются в хаос → комфортно масштабируйтесь до 20–30». Соответствие 1:1 — Mayor≈оркестратор, polecats≈воркеры, Beads≈Jira/GH+handoff'ы, hooks≈worktree. Чего нет у gosleep и есть у gastown: детекция зомби-сессий, почтовые handoff'ы между агентами, постоянная идентичность воркеров, детекция застоя конвоев. Кодовая база на Go — тащить тяжело, но идеи переносятся дёшево.

6.2 Ralph (frankbria/ralph-claude-code) — двигатель ночного цикла

Техника «Ralph Wiggum» Джеффри Хантли (июль 2025): бесконечный shell-цикл, перезапускающий агента с одним и тем же файлом промпта, файловая система как память — знаменит многомесячными запусками. Это самая ухоженная реализация (bash, v0.11.5, 784 теста), и буквально именная проблема GoSleep — то, что решает её закалка:

Двухусловный exit gate

Для выхода нужно ≥2 эвристических индикатора завершения И явный EXIT_SIGNAL: true в структурированном статус-блоке — защита и от преждевременного выхода (документ со словом «done»), и от бесконечных циклов.

Circuit breaker

CLOSED→HALF_OPEN→OPEN при: 3 цикла без прогресса, 5 циклов одной и той же ошибки, падение вывода >70%, 2 цикла отказов в разрешениях; cooldown с автовосстановлением для запусков без присмотра.

Автоожидание квоты

4-слойная детекция лимитов (таймаут-страж → структурный rate_limit_event → фильтрованный текст → исчерпание Extra-Usage); режим без присмотра ждёт сброса окна вместо смерти. Самый релевантный gosleep паттерн во всей экосистеме.

Детекция вопросов и защита файлов

Ловит момент, когда Claude спрашивает вместо того, чтобы действовать (в headless человека нет), и подмешивает корректирующее указание в следующий цикл; гранулярные allowlist'ы + проверка целостности на каждом цикле не дают агенту удалить собственные управляющие файлы.

Механика цикла: собрать контекст (номер цикла, оставшиеся задачи fix_plan.md, состояние breaker'а, сводка прошлого цикла) → вызвать claude -p --output-format json с --allowedTools и --resume сессии → разобрать JSON → продолжить/выйти. Плюс: rate limiter (100 вызовов/ч), резервные git-ветки + откат, tmux-дашборд мониторинга, очередь из GitHub-issue. Стратегическое чтение (ADR 0001): мейнтейнер ставит на то, что headless уходит на API-кредиты, отказывается от хака с управлением TUI как враждебного ToS и идёт в провайдеро-агностичность. Детали, которые стоит украсть: только Claude и Gemini поддерживают безгоночные предназначенные id сессий (--session-id при создании); «неподдерживаемые фичи деградируют с залогированным предупреждением, никогда — молчаливым сбоем».

Источники: .research-cache/ralph-claude-code README, CLAUDE.md, ADR 0001; ghuntley.com/loop; The Register 2026-01-27.

6.3 Claude Squad (smtg-ai/claude-squad) — минимальная рубка флота

Один TUI (cs, ~8k★, ставится brew) со списком N инстансов; каждый = git worktree + tmux-сессия; создать/поставить на паузу/возобновить/подключиться; ревью диффов перед применением; опциональный фоновый «yolo»-режим с автоприёмом. Спавн (проверен в исходниках): tmux new-session -d -s claudesquad_<name> -c <worktree> claude — чистый интерактивный CLI в tmux, подписочная квота, ноль поверхности ToS. Ни координации агентов между собой, ни планировщика — рубка флота, а не оркестратор. Значение для gosleep: независимый зрелый проект сошёлся на точно таком же паттерне спавна; конкретные заимствования — изоляция worktree на инстанс и UX паузы/резюма.

8Что берёт gosleep — объединённый ранжированный план

Дедуплицировано по всем трём исследованиям. Уровень 1 = делать сейчас, по рычагу; уровень 2 = следующие, дешёвые или наполовину готовые; затем явный список «не брать». Метки источников: ASK AutoSK · W/O Warren/Overstory · ECO отчёт по экосистеме.

Уровень 1 — шесть ходов, меняющих суть gosleep

  1. Heartbeat-файл + внешний механический watchdog с бюджетом рестартов и эскалацией человеку Ц высУ средР низW/O

    Каждый пульс оркестратора дописывает {ts, context%, флот} в фиксированный файл (запись — ПЕРВОЕ действие пульса). launchd-агент каждые 2–5 минут проверяет: сессия существует / heartbeat свежий / context% под потолком; мёртв → респавн по протоколу холодного старта (переподключиться, не респавнить воркеров); застой → один nudge, потом kill по явному id; бюджет 3-за-60-мин, потом стоп и эскалация. Семантика супервизора и watchdog'а Warren, пересаженная на tmux. Убирает «оркестратор умер в 3 часа ночи, флот простоял до утра» — самую большую дыру.

  2. Park-to-human как единственный сток отказов, с пояснительной запиской Ц высУ низР низASK

    Каждый отказ — крэш, нет handoff'а, лимит, kill watchdog'ом, структурный дрейф — сходится в ОДНО запаркованное состояние с машинно-написанным объяснением, образуя утреннюю очередь владельца. У gosleep есть BLOCKED_ON_HUMAN; это обобщает его до универсального стока с аудируемым полем причины.

  3. Персистентные, сбрасываемые человеком бюджеты циклов — полный словарь Ц высУ низР низASKECO

    Три уровня AutoSK (поправки хода ×3 → лимиты визитов шага → парковка), слитые с порогами breaker'а Ralph (без прогресса ×3, та же ошибка ×5, коллапс вывода, отказ разрешений ×2) и двухусловным exit gate. Счётчики живут в леджере/файлах задач, не в памяти — владелец может «помиловать» запаркованную задачу из любого редактора, а утреннее состояние аудируемо.

  4. Автоожидание квоты, выращенное до планирования флота с учётом окон Ц высУ средР низECOASK

    Детектировать исчерпание лимитов подписки (4-слойная детекция Ralph), чисто усыпить флот и автоматически возобновиться по сбросу окна — вместо «AutoSK запарковал всё в час ночи». Этого не делает никто в ландшафте; это именная функция gosleep.

  5. Push-уведомления по парковке (ntfy / Telegram / APNs) Ц высУ низР низASK

    В момент, когда работа паркуется на человека — или watchdog эскалирует, — телефон владельца знает. Ни один инструмент обзора этого не имеет; это и есть разница между «работает без присмотра» и «на этом можно спокойно спать».

  6. Восстановление = переподключение + сверка, никогда слепой респавн (закалить холодный старт) Ц высУ низР низW/O

    Паттерн recover.ts Warren: пройти долговечное состояние, переподключиться к живым воркерам, показать частичные спавны; re-wake = свежий оркестратор, засеянный из леджера, никогда не «оживление» мёртвого контекста. В скилле уже почти закодировано — сделать это промптом респавна для watchdog'а и покрыть приёмочным тестом.

Стратегия в один абзац

Двигатель оставить ровно там, где он есть — интерактивные Agent Teams на интерактивной квоте подписки, поверхности, которую Anthropic продолжает защищать. Обернуть его надзором уровня Warren (heartbeat + глупый внешний watchdog + бюджет рестартов), дисциплиной отказов уровня AutoSK (park-to-human с причинами, персистентные бюджеты) и закалкой циклов уровня Ralph (breaker, exit gate, автоожидание квоты). Затем выпустить две функции, которых нет ни у кого — push-по-парковке и резюм с учётом окон, — и gosleep по построению станет самой безопасной вещью в этом ландшафте, на которой можно спать.
