Проектный дайджест: как превратить GoSleep из системы, где документация пишется по конвенции или по просьбе, в систему, где она рождается сама собой — где флот агентов работает всю ночь, буферизует собственные вопросы и встречает владельца утром одним экраном, на котором видно всё.

Одно предложение, шесть подвижных частей

Каждый артефакт, который производит система доставки, лежит где-то на шкале детерминизма его генерации. Референс-проект (tasty-lunch) с жестокой ясностью доказал оба конца этой шкалы: нарративный слой, поддерживаемый конвенциями скиллов, масштабировался до 197 файлов без единого сбоя — а единственный артефакт, который требовал регенерации, рукотворный wiki-хаб статуса, сгнил за месяц. Лаборатория — это машина, которая связывает всю шкалу так, что ничто не гниёт и ничему не нужна человеческая рука в 3 часа ночи.

▲ Ключевая инверсия

Сегодня AskUserQuestion — основной интерфейс для вопроса, и ночью он просто блокирует панель, пока кто-нибудь не проснётся. Лаборатория переворачивает это: первичной становится долговечная запись вопроса (она переживает сессии, кормит дашборд, дайджест и пуш), а живой prompt поднимается, только когда владелец действительно на месте. Нет владельца → в очередь, взять обратимый дефолт, продолжать работать, показать всё утром.

01 · Проблема

Документация сегодня: по конвенции или по просьбе. Цель: сама собой.

У GoSleep уже сильная база — каждая задача оставляет бумажный след по правилу, а не по одолжению. Но ничто не записывает события по мере того как они происходят, у вопросов к владельцу нет дома, а дашборды, которые связали бы это воедино, не обновляются сами. Урок о том, что строить — и чего строить нельзя никогда — приходит из референс-проекта.

Урок tasty-lunch: конвенции масштабируются, рукотворные хабы гниют

tasty-lunch — та же линия скиллов, что у GoSleep: один владелец-одиночка + AI-оркестратор, 523 коммита за ~месяц, 828 документов на диске1. Прочтение всего дерева документации сортирует каждый артефакт в чистый вердикт — и этот вердикт и есть техзадание для Лаборатории.

✓ Что масштабировалось — по конвенции

197 файлов dev_history. 94+ handoff, пронумерованных 01→94, каждый с машиночитаемым telemetry-футером. 19 lessons-learned, каждый ссылается на реальный инцидент и закрывается правилом, унесённым в следующий цикл. Cycle-промпты жёстко зашивают «invoke /handoff» — эпоха «владелец просит handoff» уже закончилась. Единообразие 197 файлов и есть доказательство, что принуждение конвенциями работает в масштабе.

✗ Что сгнило — построили руками и бросили

wiki-хаб статуса построили руками один раз и больше не регенерировали. Он до сих пор гласит «Phase 1 in progress, 1 of 9 epics done» — при том что доставка дошла до Phase 23. Ни генератора, ни CI-проверки — поэтому он умер за месяц. Отдельно: 81% дерева reports/ так и не закоммитили (целый набор из 155 файлов не приземлился) — черновики без политики.

⚠ Единственное правило, вокруг которого построен весь дайджест

Всё, что нужно регенерировать, чтобы оно оставалось правдой, сгниёт — если только его не регенерирует скрипт. 197 append-only нарративных файлов выжили, потому что их написание — часть «готово». Единственный артефакт, требовавший регенерации, умер в тот момент, когда человек перестал править его руками. → Дашборд Лаборатории обязан быть сгенерирован скриптом из данных, никогда — рукотворным HTML.

Восемь пробелов, которые Лаборатория обязана закрыть

1 · Нет машиночитаемого слоя

Всё — проза в Markdown. У LIVE-STATUS есть грамматика, но нет схемы. Нет ни events.jsonl, ни status.json — дашборду пришлось бы регэкспить Markdown-файл.

2 · Нет таймлайна / ленты событий

Восстановить «что было ночью» = прочесть STATE + N handoff-ов + git log + Jira. Ничто не пишет события по мере наступления в одно место с таймстампами.

3 · Нет агрегированного «утреннего вида»

Секция At-a-glance в STATE — ближайшее, но она перезаписывается (нет истории), никуда не ссылается и мешает инфу владельцу с самоинструкциями оркестратора.

4 · У вопросов нет дома пробел №1

Блокер становится синхронным AskUserQuestion (умирает с сессией) или похороненным абзацем в handoff. Ничто не ставит вопросы в очередь, не типизирует их между воркерами. Ночью AskUserQuestion просто блокирует панель.

5 · Отчёты не обновляются сами

У docs/report/ есть генераторы, но нет триггера, связывающего их с событиями доставки. Приземлённая задача не обновляет никакой дашборд.

6 · Артефакты не сшиты кросс-индексом

Ничто не связывает «GSL-38 → коммит f12092e → dev_history → находка ревью → handoff 11 → Jira/GH». У каждой директории — в лучшем случае свой README.

7 · Телеметрия воркеров — самоотчёт-проза

Счётчики токенов приходят внутри SendMessage; ничто не валидирует и не агрегирует их дальше одной строки-итога.

8 · Вообще нет пути пуша

Запаркованный вопрос в 01:00 обнаружится в 09:00 — только если владелец откроет терминал. (У autosk тот же пробел.2)

02 · Лаборатория

Три яруса убывающего детерминизма

Доказательства из tasty-lunch сортируют каждый артефакт по тому, как он обязан производиться. Эта сортировка и есть архитектура: детерминированный пол событий, который ничего не стоит, существующий конвенционный нарратив посередине и ограниченная задача-синтезатор сверху, которая регенерирует всё производное. Wiki сгнил, потому что имел середину без пола и без крыши.

ЯрусКто производитДетерминизмСтоимостьЧто генерирует
Я1 · События Хуки Claude Code (.claude/settings.json, async:true) Механический — срабатывает независимо от модели 0 токенов, ~0 задержки Таймлайн: жизненный цикл сессий/воркеров, активность инструментов, коммиты, переходы Jira, сбои
Я2 · Нарратив Агенты по конвенции (существующие скиллы) Поведенческий — принуждается брифами + эвалами Уже оплачен (часть доставки) Handoffs, dev_history, reviews, RCA — человеческая история
Я3 · Синтез chronicler — claude -p glue или дешёвый tier Триггер по скрипту, контент с помощью модели Малый, бюджетируемый (--max-budget-usd) Регенерация дашборда, индексы, дайджест, кросс-ссылки, проверки свежести

Ярус 1 — детерминированный слой событий

Взять конверт из собственного черновика репозитория event-schema.md: {ts, run_id, seq, actor, type, data} плюс session_id/agent_id из входа хука. Его открытый caveat — «проверить возможности хуков на этапе сборки» — теперь снят: текущий каталог хуков покрывает каждый предложенный им тип события.3

Тип событияКонкретный хук (проверено 2026-07-07)
agent.spawned / terminatedSubagentStart / SubagentStop (несут agent_type, agent_id); SessionStart/End для панелей
agent.idleTeammateIdle — срабатывает, когда teammate уходит в idle (слепое пятно пульса, теперь бесплатно)

вопросы / праваNotification, PermissionRequest, PermissionDenied
доска задачTaskCreated / TaskCompleted

Почему Я1 важнее всего

Живость выводится из артефактов, а не из самоотчёта. Зависший агент не может доложить, что он завис, — но его поток событий просто останавливается. Тот же поток, что кормит дашборд, — лучший вход для пульса, чем tmux capture-pane. Два производителя дополняют хуки: явные lab-emit однострочники для семантических событий, которые хуки не выведут (cycle.started, question.posed, decision.made), и poll-fill — chronicler сверяет gh pr list / Jira JQL / git log для всего, что локальные хуки упустили (PR, смерженный из веба).

Правила, унаследованные из существующей дисциплины: атомарная запись (temp+rename в той же директории) для каждого не-append файла; append-only JSONL никогда не переписывается (правки — новые записи с supersedes:<seq>); ORCHESTRATION-STATE.md остаётся авторитетом — status.json производный, и при конфликте побеждают STATE + живой git.

Ярус 3 — дашборд «Лаборатория», и почему он статический

Статический HTML, регенерируемый из данных docs/lab/ — без сервера в v1. Это соответствует проверенному паттерну build-*.py, работает из file://, переживает выключенную машину, коммитится (значит читается с GitHub на телефоне) и не может сгнить, как wiki — потому что его никто не правит руками. Триггеры регенерации: (a) chronicler на каждой границе цикла; (b) debounce-хук PostToolUse на записи в docs/lab/; (c) по требованию. Живое управление — не задача этого дашборда; это Remote Control / терминал (§05).

chronicler — НЕ четвёртый живой агент

Это ограниченная задача по расписанию — headless one-shot со строгими --allowedTools + бюджетными кэпами. Держа его вне ростера teammate-ов, мы сохраняем бюджет spawn-cap-3, и падение chronicler-а никогда не застопорит доставку: слой данных просто устаревает до следующего тика, а дашборд показывает собственную несвежесть (штамп generated-at + макс. возраст события на каждой странице). Это встроенная сигнализация против гниения wiki.

Информационная архитектура из 7 экранов

1 · Overview

Утренний экран. Дайджест + полоса runway + сводка вопросов. Стартовая по умолчанию.

2 · Timeline

Лента событий, новейшие сверху, фильтр по актору / типу / серьёзности; маркеры инцидентов.

3 · Tasks

Доска по ключу Jira: статус, ссылки GH issue/PR, SHA коммитов, ссылка dev_history на задачу.

4 · Questions

Очередь §03: открытые (по типам), отвеченные (кто/когда), авто-разрешённые (с применённым дефолтом).

5 · Fleet

Карточки агентов: состояние, модель, старт/конец, токены, возраст последнего события.

6 · Cost

Ряды телеметрии: токены по циклам, накопление vs потолок, разбивка по моделям, события окна квоты.

7 · Library — сгенерированный кросс-индекс (убивает пробел №6)

Handoffs (нумерованные), dev_history (по задачам), reviews, reports, research, RCA — каждая строка с датой, затронутыми ключами задач и ссылками. Это индекс, сшивающий «GSL-38 → коммит → dev_history → ревью → handoff → Jira/GH», сгенерированный, никогда не поддерживаемый руками.

03 · Буфер вопросов

Буферизуй-и-продолжай: паттерн автономии, позволяющий владельцу спать

Сообщество описывает три уровня зрелости ночного поведения4: (a) парк на любом вопросе (autosk), (b) пауза с бюджетом и авто-разрешение, (c) буферизуй-и-продолжай — залогировать вопрос, взять обратимый дефолт, продолжать работать, показать всё утром. (c) назван «идеалом для GoSleep; наименее реализован в публичном коде». tasty-lunch уже испытал примитивную версию (OWNER-QUESTIONS.md / OWNER-DECISIONS). Здесь — полный дизайн.

Четыре типа, четыре поведения

ТипОпределениеНочное поведениеПуш?

CLARIFY Двусмысленность с очевидно-разумным прочтением Продолжить с дефолтом немедленно; записать как «отвечено дефолтом», чтобы владелец мог наложить вето задним числом Нет — только дайджест

Манифест решений — «решай сам по манифесту владельца»

docs/lab/decisions/manifest.md — суверенитет владельца, единственный ручной файл в docs/lab/. Агенты ЧИТАЮТ его каждый цикл, ПРЕДЛАГАЮТ правки как diff в дайджесте и никогда не правят молча. Он даёт политике, которая сегодня разбросана по «Standing rules» в STATE, memory-файлам и директивам в чате, единый дом, читаемый тулингом и версионируемый владельцем. Его ярусы автономии зеркалят authority/denylist из orchestrating-скилла — новой политики он не изобретает.

# Decision manifest — <owner> — vN (updated YYYY-MM-DD)
## 1. Always autonomous (никогда не спрашивать, всегда логировать)
- мержить зелёные PR на delivery-ветках; двигать фазы; обратимая работа в репо
- восстанавливать транзиентные ошибки воркера одним continue-nudge (валидировано 2026-07-07)
## 2. Decide-by-default (запись DECISION, применить дефолт на дедлайне)
- дедлайны: ночь → 10:00 утра; день → +2ч
- merge strategy → regular merge; модельная политика → Fable 5 / Opus-mechanical; N=2 эвала
## 3. Always ask, never default (= denylist дословно)
- force-push/rewrite истории; удаление веток/тегов/релизов; prod-деплой; ротация секретов;
  разрушительные миграции БД; внешние коммуникации; удаление облачных ресурсов; трата сверх потолка
## 4. Escalation & channels
- тихие часы 00:00-08:30: пуш ТОЛЬКО BLOCKER; всё прочее — в дайджест 06:30
- порядок каналов: пуш Claude-app → Telegram → (утром) дайджест
## 5. Budget & runway
- потолок токенов на фазу: N; на 80% → FYI; на 100% → BUDGET_EXCEEDED = BLOCKER
## 6. Standing preferences (стиль, язык, строгость ревью…)

Learning loop — вопросов-за-ночь → 0

Каждый ответ (живой или из очереди) добавляется в decisions/log.jsonl с полным контекстом. Периодически chronicler майнит его: одна и та же форма вопроса, отвеченная одинаково ≥2–3×, становится кандидатом в манифест в дайджесте — «Вы выбирали ‘regular merge’ 3× — повысить до §2 decide-by-default?» Владелец одобряет правкой манифеста (или ответом «да»). Это напрямую сокращает будущий объём вопросов — настоящую метрику автономии.

Доставка с учётом присутствия

Синхронный AskUserQuestion поднимается, только когда владелец присутствует — официальный маркер CLAUDE_CLIENT_PRESENCE_FILE (Remote Control) или просто «владелец писал за последние N минут». Нет → в очередь + пуш по типу. Есть → спросить живьём, но всё равно залогировать ответ в очередь — learning loop нуждается в нём в любом случае.

Утренний дайджест — deliverable, определяющий «GoSleep сработал»

Генерируется во время пробуждения из манифеста (scheduled task / cron / Routine) и по требованию; пишется в digest/YYYY-MM-DD-morning.md, рендерится на экране Overview, опционально пушится «дайджест готов». Секции, в порядке приоритета владельца:

1 · Ждёт тебя

Открытые BLOCKER, затем DECISION с их дедлайнами.

2 · Решено за тебя

Каждое авто-разрешение с процитированным правилом манифеста (дисциплина provenance).

3 · Что отгружено

Задачи / PR / коммиты со ссылками.

4 · Инциденты

Что сломалось, что восстановилось, ссылки на RCA.

5 · Стоимость и runway

Токены vs потолок, события квоты.

6 · Кандидаты в манифест

Предложения learning loop + план на завтра.

Дайджест так же важен, как сама работа

Непроверяемая ночь — провальная ночь, даже если все PR смержились. Всё в дайджесте ссылается в дашборд / Library — provenance это дисциплина (она прямой потомок PRD-тегов OWNER-RATIFIED / OWNER-ACQUIESCED-DEFAULT из tasty-lunch).

05 · Мобильный доступ

Официальный Remote Control против DIY-пути autosk

Самая ценная мобильная фича для системы «владелец спит» — пуш на запаркованный вопрос. autosk доказывает, что управление со стороны демона — лёгкие 90%, но оставляет ровно три пробела, которые GoSleep не должен унаследовать: нет TLS, нет relay, нет пуша. Официальный Remote Control (запущен 2026-02-24) закрывает все три на подписке. Строй поверх него, не переизобретай.
