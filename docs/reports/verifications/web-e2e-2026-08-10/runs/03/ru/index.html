Known-degraded state observed and worked around

The /actions/questions/answer and /actions/questions/defer endpoints spawn tools/lab/lab-emit.sh answer|defer --re <qid>, which reads LAB_DIR/questions/queue.jsonl and errors with no record with id … when the qid was seeded via SQL only. This is the environment artifact the mission brief called out. The workaround (used here for the interactive write tests to pass): seed each qid into BOTH the DB and queue.jsonl using lab-emit's field schema (id, type, question, status, qhash). With the JSONL fixture in place, the answer and defer flows succeed end-to-end — 0 console errors, DB rows flip as expected.

Raw API GET without Bearer returns 401 — this is correct auth behavior

curl http://127.0.0.1:7343/questions (no Authorization: Bearer …, no Accept: text/html browser hint) returns 401 as designed — the Bearer-gated JSON path is unchanged. The SPA-navigation guard (GSL-310) selectively returns the SPA shell only for browser-shaped Accept: text/html+ preference; XHR + SDK calls with Accept: application/json continue to require a Bearer. Not a defect — an intentional two-lane split.
