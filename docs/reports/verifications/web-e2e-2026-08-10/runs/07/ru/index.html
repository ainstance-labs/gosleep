2 GSL-319 MINOR Пайплайн наблюдения PR (FIX-C) functionality

`last_pr_url` заполняется только когда сессия проводит хук `tool-observed-feed.sh` — в bypass-режиме в свежем клоне без этого хука PR не отражается

UI-поверхности FIX-C (карточка 'Latest PR' на Overview + чип PR во Fleet) отрисовывают реальную кликабельную ссылку, как только agent_sessions.last_pr_url заполнено. Заполнение идёт через POST /internal/agents/tool-observed, который вызывается только из tools/hooks/tool-observed-feed.sh, а тот — только когда сессия сама подписала его в .claude/settings.json как PreToolUse-хук. В клоне run-07 $HOME/e2e-workspaces/todo-run07/.claude/settings.json подписаны ТОЛЬКО шимы AskUserQuestion и PermissionRequest (как в брифе). Итог: реальный gh pr create, открывший PR #7, сам НЕ заполнил last_pr_url — пришлось руками curl -X POST /internal/agents/tool-observed с наблюдённым URL, чтобы панель ожила для FIX-C-скриншота. UI FIX-C работает; источник данных FIX-C не срабатывает у сессии, где tool-observed-feed.sh не подключён. Варианты: пассивный сканер, который читает транскрипты на предмет PR-URL, или явная рекомендация обязательно подключать tool-observed-feed.sh рядом с двумя другими шимами.

4 MINOR Empty-state карточки Latest PR design

Overview полностью прячет карточку 'Latest PR', когда ни одна сессия ещё не касалась PR — нет empty-state

По явному дизайну (комментарий коммита GSL-319) карточка 'Latest PR' скрыта, пока во fleet нет ни одного наблюдённого PR-URL. Идея — 'не шуметь на несущих сессиях'. В run 07 это значило: базовый скрин S1 не показал карточку вообще — ничем не отличается 'фича есть, но простаивает' от 'фичу удалили'. Возможен ненавязчивый empty-state ('PR ещё не открывали — карточка появится, когда агент выполнит gh pr create.'), чтобы владелец, скользя по панели, знал о существовании поверхности. Не дефект против спеки; UX-предложение.
