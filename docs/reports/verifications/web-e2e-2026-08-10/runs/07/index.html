1 GSL-321 MAJOR Fleet Model column (FIX-B) functionality

Boot-window race: global-settings fallback fabricates a model for freshly spawned sessions

FIX-B (GSL-321) is only asymptotically correct. The transcript reader works — a direct resolveTranscriptModel('95df013c-…') returns claude-sonnet-5 for the dev-agent session, matching every one of its 77 type=assistant transcript lines. But at spawn time no assistant turn has landed yet, so the resolver returns null and the cache falls to the settings hierarchy, which for this machine hits ~/.claude/settings.json and returns claude-fable-5[1m]. The run-07 dev-agent (launched with --model sonnet) therefore appeared as claude-fable-5[1m] in Fleet for the first several seconds — exactly the 'wrong-but-confident' behaviour GSL-321 was written to eliminate. Once the first assistant message landed, Fleet converged to claude-sonnet-5. FIX RECOMMENDATION: when resolveTranscriptModel returns null for a session whose transcript file exists (i.e. the session HAS spawned but no assistant turn yet), return null all the way and let Fleet render 'unknown', instead of falling through to the settings hierarchy. Alternatively: gate the settings-hierarchy fallback on 'no transcript file exists at all', so a session with a still-empty transcript is honestly 'unknown'.

2 GSL-319 MINOR Panel PR-observation pipeline (FIX-C) functionality

`last_pr_url` is populated only when a hook wires `tool-observed-feed.sh` — bypass-mode agents in fresh clones ship a PR without it firing

FIX-C's UI surfaces (Overview 'Latest PR' card + Fleet PR chip) render a real, clickable link once agent_sessions.last_pr_url is populated. The population path relies on POST /internal/agents/tool-observed, which is only called from tools/hooks/tool-observed-feed.sh, which is only invoked when a session's .claude/settings.json wires it as a PreToolUse hook. The run-07 clone at $HOME/e2e-workspaces/todo-run07/.claude/settings.json wires ONLY the AskUserQuestion and PermissionRequest shims (per the brief). Consequence: the dev-agent's real gh pr create opening PR #7 did NOT populate last_pr_url on its own — we had to curl -X POST /internal/agents/tool-observed by hand with the observed URL to bring the panel to life for the FIX-C screenshot. FIX-C's UI works; FIX-C's data source does not fire on a session that doesn't already wire the tool-observed hook. Consider: either a passive scanner that reads transcripts for PR URLs, or documented guidance to bundle tool-observed-feed.sh alongside the two shims we DO recommend for every supervised clone.

3 MINOR Fleet Model rendering design

Model column shows the raw internal ID (`claude-sonnet-5`, `claude-fable-5[1m]`) instead of the friendly label the TUI uses (`Sonnet 5`)

Claude Code's TUI already knows how to render claude-sonnet-5 → Sonnet 5 and claude-fable-5[1m] → Fable 5 (1m). The Fleet panel shows the raw model ID from the transcript verbatim, which is greppable but not owner-friendly at a glance. Low-effort cosmetic mapping in Fleet.tsx: map the known short-name family to the same label the TUI shows, keep the raw ID in a tooltip. Not a regression — the column is new — but worth capturing before it becomes 'the way it's always been'.

4 MINOR Overview 'Latest PR' empty state design

Overview hides the 'Latest PR' card entirely when no session has touched a PR — no empty state affordance

By explicit design (per the commit comment on GSL-319), the 'Latest PR' card is hidden when the fleet has no observed PR URL. The intent is 'stay quiet on non-shipping sessions'. In run 07, that meant the S1 baseline shot showed no card at all — nothing to distinguish 'the feature is present but idle' from 'the feature was removed'. Consider a low-key empty state (No PR opened yet — the card will appear once an agent runs \gh pr create\.) so an owner scanning the panel understands the surface exists. Not a defect against the shipped spec; a UX suggestion.
