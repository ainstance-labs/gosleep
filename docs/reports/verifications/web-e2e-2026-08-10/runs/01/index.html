2 · Findings (severity, root cause, evidence)

Найденные дефекты по убыванию тяжести. Первый — блокер основного действия; чинить перед началом владельческого тестирования.

#1

Answer dialog crashes on the first keystroke — owner cannot answer any BLOCKER/DECISION from the web

MAJOR

apps/web/src/screens/Questions.tsx:651–655

onChange={(e) =>
  setAnswerDialog((prev) =>
    prev === null ? prev : { ...prev, value: e.currentTarget.value },
  )
}

Root cause. React 19 is free to invoke the state-updater function outside the synchronous event window. By the time the updater reads e.currentTarget.value, the SyntheticEvent has been recycled and e.currentTarget is null → TypeError: Cannot read properties of null (reading 'value'). React Router catches the throw and replaces the whole panel with Something went wrong.

Fix. Read the string synchronously before setState:

onChange={(e) => {
  const v = e.currentTarget.value;
  setAnswerDialog(prev => prev === null ? prev : { ...prev, value: v });
}}

Impact. Reproducible in automation. Under real keyboard typing it will bite intermittently now and often as soon as React 19 flushes the updater async — which it can any time. The Answer button is on every open BLOCKER/DECISION card. Whichever question the owner tries to answer first is the one that blanks the whole route.

Evidence: § scenario 19 · § 20 · § 21 (crash)

#2

Chrome logs 5,087 ERR_INSUFFICIENT_RESOURCES during a normal walk-through

MAJOR

Client polling / SSE lifecycle (cleanup on route unmount)

Root cause (not fully proven from the client alone). Recent resource entries: 250 total, 242 with transferSize=0 responseStatus=0. Only /status and /timeline polls are affected — /status fired 123×, /timeline 121× in about ten minutes. SSE /events reconnect churn on top of react-query polling is the most likely driver; React StrictMode double-mount in the built SPA would compound it.

Fix. Instrument react-query staleTime/refetchInterval; confirm EventSource.close() runs on route unmount; verify StrictMode is off in the production build.

Impact. A long-lived tab (the owner leaves the panel open all day) will hit Chrome's per-origin socket ceiling and silently stop refreshing. On mobile Safari the same class of error surfaces as blank cards.

Evidence: console.error ERR_INSUFFICIENT_RESOURCES ×5087; per-endpoint request counts above.

#4

Refreshing any non-Overview URL returns 401, not the SPA

MAJOR

apps/core/src/serve.ts (SPA fallback is mounted after every collision-name API route)

Root cause. The server-side /fleet /timeline /questions /tasks /cost routes are Bearer-gated JSON endpoints. A hard reload of any of those client-side URLs hits the API first, gets 401 with body unauthorized, and the SPA never loads. Only /overview happens to not collide with an API name.

Fix. Give SPA routes a namespace (/panel/*) OR move API to /api/*, OR detect Accept: text/html in each API route and fall through to the SPA index.

Impact. Every browser bookmark and every refresh of a non-Overview page breaks the panel. The owner learns "don't reload". The phone-dashboard tunnel makes this worse.

Evidence: reproducible via URL bar → http://127.0.0.1:7333/fleet returns 401 unauthorized.
