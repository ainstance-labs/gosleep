1 GSL-QA04 MAJOR SSE кросс-табная согласованность functionality

Решения по разрешениям не рассылаются между вкладками — вторая вкладка показывает устаревший статус до ручного refresh

Обработчик /actions/permissions/decide пишет только в SQLite-таблицу questions (и будит приостановленный CLI-hook через SessionAdapter.deliverAnswer). Он никогда не пишет в JSONL-лог событий, поэтому tail-индексер и SSE-broadcaster не видят смену состояния. Так как useQuestions в apps/web/src/data/queries.ts не имеет refetchInterval, вторая вкладка на /questions продолжает рендерить строку как open — с активными кнопками Allow/Deny — после того, как в другой вкладке нажали Allow. Воспроизведение (прогон 04): открыть /questions во вкладках A и B, POST свежий permission через /internal/permissions/post (вкладка B видит его появление — путь insert рассылается), нажать Allow в A (в БД строка становится answered/allow, applied_by=owner), вкладка B в течение 6+ секунд рендерит permission как open; обновляется только после полной перезагрузки.

2 GSL-QA04 MAJOR Адаптивная вёрстка design

SPA переполняется по горизонтали на узких viewport (320px = 114px скролла)

Root-grid grid-cols-[240px_1fr] рендерит фиксированный 240px sidebar и никогда не коллапсирует. Замер при 320×640: scrollWidth = 424, clientWidth = 310 — 114px горизонтальный скролл. Контент рядом с sidebar сжат до 80px, карточки перекрывают sidebar, для доступа к кнопкам нужен горизонтальный свайп. Панель управления живёт на 127.0.0.1 и владелец заходит с телефона в дежурном режиме — телефонный вид сломан. Решение: свернуть sidebar в hamburger под md breakpoint, либо явно отказать под 640px с сообщением «откройте на десктопе».

Shippedapps/web/src/main.tsx + router.tsx (root grid is unconditional 240px+1fr)
3 GSL-QA04 MINOR Клиентская защита от дублей действий functionality

Random Idempotency-Key на клик + client `isPending` race позволяют 5 быстрым кликам отправить 5 запросов

newIdempotencyKey() в apps/web/src/data/queries.ts генерит свежий crypto.randomUUID() на каждый вызов, поэтому серверный replay-кэш server_intents.intent_id не может слить double-click. Единственная защита клиента — disabled={isPending}, а isPending переключается через React-state update, который асинхронный. Когда 5 кликов приходят в одном JS-микротаске, все 5 стреляют до re-render. Проверено: 5 синхронных JS-кликов на Allow отправили 5 POST — сервер записал 1 ok и 4 fail (409, корректно — SQL-гвард WHERE status='open' удержал). Состояние осталось правильным, но ledger заполняется дублями. Fix: производить Idempotency-Key из (qid, decision, session-nonce).

Shippedapps/web/src/data/queries.ts:158-165 (newIdempotencyKey) and the ActionRow buttons
4 GSL-QA04 MINOR UX ошибок design

Подсказка 401 хардкодит порт 7331 даже когда SPA работает на другом порту

Когда SPA теряет Bearer, error-поверхность рендерит HTTP 401 from http://127.0.0.1:<port>/… и подсказку Check that gosleep-core is running on 127.0.0.1:7331 …. В прогоне 04 SPA идёт на 127.0.0.1:7344 — подсказка вводит в заблуждение. Тривиальный fix: подставить порт из runtime origin.

Shippedapps/web/src/components/QueryStatus.tsx:~50 (hint string)
5 GSL-QA04 MINOR Рендеринг вопросов design

`options` вопросов отображаются как raw JSON в `<pre>` вместо кликабельных вариантов

Для non-permission вопросов Questions карточка рендерит массив options как pretty-printed JSON внутри .mono <pre>, затем предлагает только free-text textarea в диалоге Answer. Permission-карточки корректно рендерят Allow/Deny кнопками. Для обычного AskUserQuestion владелец читает JSON (со скобками и отступами), потом вручную набирает ответ. Ничто не гарантирует, что ответ совпадёт с label варианта. Рендерить options как radio/toggle-кнопки (как CLI-native AskUserQuestion picker), либо убрать JSON-дамп и показать только labels.
