9 no-ticket MINOR Permission UX semantic functionality

NOTE — Claude Code shows the permission TUI dialog IN PARALLEL with the shim long-poll (not after timeout)

Contrary to a plausible mental model where the TUI is a "fallback after hook fails", empirical observation is that Claude Code renders the standard "This command requires approval / Do you want to proceed?" dialog IMMEDIATELY when the tool call fires, at the same time the PermissionRequest hook is running. Whoever answers first wins:

• Hook returns decision.behavior=allow first → TUI dialog dismisses silently, agent proceeds.
• User picks a TUI option first → hook's eventual answer is ignored (finding #7's orphan case is a manifestation: hook timed out and TUI is still the only path).

This is not necessarily a defect (the parallel design gives the operator a reliable local fallback if the hook is misconfigured), but it should be documented in the runbook because it changes what the panel means: a card appearing in the panel does NOT guarantee the operator is going to answer it there, and vice-versa. The Timeline's permission.posed event fires from the shim, so a card that lives 100% of its life in the TUI never leaves a Timeline trace.

Architecture notes

End-to-end shim topology exercised in this run

The pilot loop routes an agent's AskUserQuestion or PermissionRequest event through two shim scripts to a scratch core, and back through a WebSocket-fed React panel where the owner clicks a choice. The defer round-trip is the interesting shape: the shim's HTTP long-poll survives DB mutations that are NOT terminal (defer flips status to deferred, auto-reopen flips it back to open) and only wakes when status='answered' lands with a non-null answer_text.

Claude Code (dev-agent tmux %302)
  │ AskUserQuestion tool call
  ▼
PreToolUse[AskUserQuestion] hook  → tools/hooks/ask-user-question-hook.sh
  │ POST /internal/questions/post {questions:[...]}
  ▼
gosleep-core (127.0.0.1:7353, scratch DB)
  │ INSERT questions row, status='open'
  │ SSE broadcast question.posed
  ▼
Owner panel (Playwright / Chrome)
  │ button "Answer" → textarea "Green" → Send answer
  │ POST /actions/questions/answer {qid, answer_text:'Green'}
  ▼
gosleep-core
  │ UPDATE questions status='answered', answer_text
  │ sessionAdapter.deliverAnswer(qid, 'Green')
  │ questionNotifier.emit(mutation)
  ▼
ask-user-question-hook.sh (long-poll GET /internal/questions/:qid/answer-wait)
  │ 200 {answer_text:'Green'}
  │ stdout {hookSpecificOutput:{permissionDecision:'allow', updatedInput:{answers:{...:'Green'}}}}
  ▼
Claude Code injects the answer  →  dev-agent proceeds with 'Green'

DEFER inserts BETWEEN the panel Send and the wait wake:
  Owner clicks Defer  →  POST /actions/questions/defer {qid, defer_until:'+60s'}
  UPDATE questions status='deferred'   [wait ignores; !terminal, !=answered]
  60s pass…
  defer-reopen worker (10s interval)  →  UPDATE status='open' at defer_until≤now
  [wait STILL held — 'open' is not terminal either]
  Owner answers  →  status='answered'  →  wait wakes, shim returns answer
