1 GSL-370-followup-a11y MINOR Кнопка варианта на карточке — имя для скринридера design

Accessible name кнопки варианта склеивает ярлык + описание + pros + cons

Внешний QuestionOptions рендерит каждый вариант как голую <button> без aria-label; accessible name кнопки собирается как её textContent. Для варианта вроде Blue / «Cool and neutral» / +accessible / +brand-aligned / −overused VoiceOver проговаривает всю строку одной репликой; ведущая нумерация («1.») тоже читается.

Сценарий падения. Пользователь скринридера, слышащий «1. Blue Cool and neutral plus accessible plus brand-aligned minus overused, кнопка», должен разобрать всю нагрузку, прежде чем решить кликнуть. На вопросе с 8 вариантами это 8 длинных реплик.

Рекомендация (после мержа, не блокер). Добавить aria-label={opt.label} на внешнюю кнопку варианта (и на внутридиалоговую Button). Остальные метаданные по-прежнему видны внутри кнопки визуально, а первичное имя для скринридера станет только ярлыком; описание / pros / cons остаются доступными через вложенные лендмарки и видимый текст.

2 GSL-370-followup-stale-options MINOR Answer-диалог — жизненный цикл снапшота options architecture

Answer-диалог держит захваченный снапшот options, а не живую строку

Когда владелец кликает вариант на внешней карточке, диалог открывается с options: normalizeOptions(question.options), положенным в AnswerDialogState. То же на :769 для клика по «Answer». Если строка вопроса потом мутирует (например, SSE-рефреш заменит payload options пока диалог открыт), внутридиалоговый ряд вариантов продолжит рендерить устаревший снапшот.

Сценарий падения. Пути записи options сегодня нет в UI, поэтому в проде это почти невозможно; это — запах жизненного цикла, а не живой баг. Занесено на будущее, чтобы фича, позволяющая options мутировать (например, агент переспрашивает вопрос на месте), не влетела молча в устаревший диалог.

Рекомендация (после мержа, не блокер). Либо (а) читать живую строку из кэша useQuery внутри диалога по qid и ре-нормализовать на каждый рендер, либо (б) оставить снапшот и задокументировать инвариант «options заморожены на моменте открытия» в комментарии над AnswerDialogState.options.
