Findings (0 CRITICAL · 0 MAJOR · 3 MINOR)

1 MINOR S5 — panel Deny dialog reason via CDP fill functionality

Deny dialog reason typed via WebDriver-style `fill` didn't reach the row (`applied=None`); direct API POST with the same reason lands correctly and reaches the model

When the S5 DENY leg was first driven through the panel Deny dialog via Chrome DevTools MCP's fill(uid, value), the row (p-20260815-222823-f4ce985d) transitioned to status='answered' with answer_text='deny' and applied_by='owner' — but the applied column stayed None. So no reason string was persisted to the row, and nothing was propagated to the model via the shim's permissionDecisionReason path.

The subsequent test with the SAME payload sent as a direct POST /actions/permissions/decide { updated_message: "…" } against a fresh row worked end-to-end: applied was populated on the row, the shim relayed the string as decision.reason, and the exact reason text landed in the dev-agent's on-disk transcript.

Most likely cause: React controlled-input event-dispatch quirk under WebDriver-style value assignment — the input's value attribute is set but React's onChange handler doesn't observe the change, so denyDialog.reason in component state stays empty, so the submit sends updated_message: null. This is a testing-tooling artifact, not a product bug, but it means the CDP-driven leg of the DENY panel path is UNCONFIRMED for this run. A real human click through the same dialog is expected to work — retest with either a real mouse+keyboard trace or a native input-event dispatch would close this.

Shippedapps/web/src/screens/Questions.tsx (denyDialog · reason field · submitDecide)
2 MINOR S4 — panel Answer dialog is free-text-only design

The panel's Answer dialog doesn't expose per-option variant clicks; a "variant" answer is proven only by typing an option label

When a question row on the Questions screen has options (an AskUserQuestion variant-type call), the panel renders each option's label + description as a static-text list, and clicking "Answer" opens a dialog whose ONLY input is a single free-text textbox. There is no per-option click-to-answer control. The S4a "variant answer" was therefore executed by typing the option label ("Rows list") verbatim into the free-text box.

Functionally this is fine — the agent receives an answer that matches the option label — but the UI presents variant-typed and free-text-typed rows as identical from the owner's perspective. Consider adding a per-option "pick" button for variant-typed rows so the owner can answer with one click and provenance is unambiguous.

Shippedapps/web/src/screens/Questions.tsx (Answer dialog)
3 MINOR S4c — Defer dialog has no short-timer preset design

Shortest Defer preset is 30 minutes; short-loop verifications must use Custom ISO

The Defer dialog offers presets "No timer", "30 minutes", "2 hours", "Tomorrow 10:00", "Next Monday 10:00", and "Custom ISO". For the S4c DEFER round-trip we needed a very short auto-reopen window (~45 s) to observe the transition live within the same session, which meant hand-computing a Custom ISO timestamp. Not blocking — Custom ISO works — but a "30 seconds" or "1 minute" preset would remove the arithmetic step for both this kind of live verification and any real-life "hold this thought for a minute" cadence.
