Находки (0 CRITICAL · 0 MAJOR · 3 MINOR)

1 MINOR S5 — панельный Deny-reason через CDP fill functionality

Reason, введённый в Deny-диалог через WebDriver-style `fill`, не дошёл до строки (`applied=None`); прямой API POST с тем же reason ложится корректно и доходит до модели

Когда DENY-нога S5 первым делом была прогнана через панельный Deny-диалог с помощью Chrome DevTools MCP fill(uid, value), строка (p-20260815-222823-f4ce985d) перешла в status='answered' с answer_text='deny' и applied_by='owner' — но колонка applied осталась None. То есть reason на строку не записался, и через shim'овский permissionDecisionReason-путь до модели ничего не ушло.

Последующий тест с тем же payload'ом, но отправленным как прямой POST /actions/permissions/decide { updated_message: "…" } на свежую строку, отработал end-to-end: applied заполнилось на строке, shim пробросил строку как decision.reason, и точный текст reason'а лёг в on-disk-транскрипт dev-agent'а.

Наиболее вероятная причина: quirk с React controlled-input под WebDriver-style присваиванием value — value-атрибут инпута выставляется, но React'овский onChange не срабатывает, из-за чего denyDialog.reason в state'е компонента остаётся пустым, и submit шлёт updated_message: null. Это артефакт тестового инструмента, а не баг продукта — но означает, что CDP-нога панельного DENY-пути в этом прогоне НЕ ПОДТВЕРЖДЕНА. Реальный клик рукой через тот же диалог должен работать; retest либо реальным mouse+keyboard, либо через native input-event dispatch закроет вопрос.

2 MINOR S4 — панельный Answer-диалог только free-text design

Панельный Answer-диалог не даёт кликнуть per-option; variant-ответ доказывается только вводом метки опции

Когда строка на Questions имеет опции (variant-типовый AskUserQuestion), панель рендерит метку и описание каждой опции как static-text, а клик "Answer" открывает диалог, у которого единственный ввод — свободный текстовый box. Per-option "picked" контрола нет. S4a "variant-ответ" был поэтому исполнен через ввод метки опции ("Rows list") дословно в free-text.

Функционально это работает — агент получает ответ, совпадающий с меткой опции — но UI-но variant-typed и free-text-typed строки выглядят одинаково с точки зрения владельца. Стоит добавить per-option кнопку "выбрать" для variant-typed строк, чтобы владелец отвечал в один клик, а провенанс был однозначным.

В кодеapps/web/src/screens/Questions.tsx (Answer dialog)
3 MINOR S4c — Defer-диалог без коротких пресетов design

Самый короткий Defer-пресет — 30 минут; коротким live-верификациям приходится использовать Custom ISO

Defer-диалог предлагает пресеты "No timer", "30 minutes", "2 hours", "Tomorrow 10:00", "Next Monday 10:00", "Custom ISO". Для DEFER-round-trip'а S4c был нужен очень короткий auto-reopen (~45 сек), чтобы увидеть переход вживую в той же сессии — пришлось руками считать Custom ISO. Не блокер — Custom ISO работает — но пресет "30 seconds" или "1 minute" убрал бы арифметику как для такого live-check'а, так и для реального "подожди минутку" ритма.

Архитектурные заметки

Где стоит плагинная эра после этого прогона

Вердикт: BATTLE-READY. Плагинная эра — рабочая поверхность как минимум для трёх текущих бандлов. Полный owner-loop — вопрос, permission (обе ветки), defer-round-trip, live-панель, наблюдение PR, вызов скилла — работает end-to-end, при этом агент загружен ТОЛЬКО из disk-only plugin-dir'ов, а глобальный ~/.claude владельца по контенту не тронут.

  • Загрузка плагинов через --plugin-dir работает чисто для всех трёх бандлов; скиллы всплывают под namespace'ом своего бандла и вызываются в бою (S1 + S6).
  • Веб-control-plane (вершина ветки b4560d5, включая свежезамерженный PR #307 со Skills-экраном) гонит все семь owner-экранов вживую от SSE; Questions ведёт AskUserQuestion и permission-строки в одной очереди.
  • Interaction-loop, который лежит в харнессе — PreToolUse{AskUserQuestion} + PermissionRequest{.*} hooks, guarded на GOSLEEP_WEB_QUESTIONS=1, wired на /internal/questions/post и /internal/permissions/post — доходит от панели обратно до модели на каждой отработанной ноге.
  • Глобальная безопасность конфига держится: три --plugin-dir бандла НЕ попадают в ~/.claude/plugins/installed_plugins.json; единственный diff на диске — штатный per-session тик lastUpdated у двух существующих плагин-бухгалтерских файлов.

Три MINOR-находки — уровня «полировка». Finding #1 — почти наверняка quirk тестового инструмента (та же reason-строка дошла до модели, когда отправлена напрямую POST'ом); findings #2 и #3 — маленькие owner-facing удобства (per-option variant-клик, короткий defer-пресет). Ни одна из них не блокирует принятие плагин-бандлов как основной delivery-поверхности.

Честная классификация. S1, S2, S3+S7, S4a/b/c, S5-ALLOW, S6, S8, S9 — это LIVE-AGENT доказательства, то есть транскрипт, терминал и состояние панели реального Sonnet dev-agent'а, а не синтетика. У S5-DENY был API-layer confirmation step (прямой POST) из-за quirk'а из finding #1, и reason дошёл до модели через тот же shim-путь, каким пошёл бы и клик из панели.
