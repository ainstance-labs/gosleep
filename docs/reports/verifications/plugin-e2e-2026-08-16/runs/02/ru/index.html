Адъюдикация MINOR-находок из прогона 01

Живая перепроверка трёх MINOR-находок на том же стеке. Каждый вердикт опирается на состояние БД и вывод shim.

A1 СНЯТО minor #1 прогона 01 — reason при Deny через CDP fill артефакт автоматизации

Причина, введённая настоящими нажатиями клавиш (CDP Input.dispatchKeyEvent), попадает в applied и доходит до модели — продуктового бага нет

Проверка. Новая заявка на разрешение (p-20260815-225949-8e49b837), клик Deny, ввод строки RUN02-KEYSTROKES-DENY-REASON-adjudicating-minor-1 в поле причины через тулу type_text (реальные нажатия, а не fill(uid,value)), клик Deny.

Строка в БД после. status=answered · answer_text=deny · applied="RUN02-KEYSTROKES-DENY-REASON-adjudicating-minor-1" · applied_by=owner — строка причины сохранилась.

Вывод shim. {"hookSpecificOutput":{…,"decision":{"behavior":"deny","reason":"RUN02-KEYSTROKES-DENY-REASON-adjudicating-minor-1"}}} — точная схема Claude Code, полный цикл «сервер → shim → модель» замкнулся.

Вердикт. Артефакт Chrome DevTools MCP: fill(uid,value) напрямую записывает .value без диспатча input-событий, поэтому контролируемый ввод React их не видит. Настоящие клавиши (то, что делает реальный человек) работают до конца. Тикет-дефект не нужен.

A2 ПОДТВЕРЖДЕНО minor #2 прогона 01 — клик по варианту в диалоге ответа design

В диалоге ответа действительно только свободный ввод; лейблы вариантов — статический текст без клика

Проверка. Открыт вопрос-вариант q-2026-08-15-001 (2 опции: «Grouping panel» / «Total-row footer»), нажат Answer, обследован DOM диалога.

Содержимое диалога. Одна <textarea> плюс кнопки Cancel и Send answer. Больше ничего.

DOM-проба. hasRadio=false, hasSelect=false. Опции живут вне диалога — в самой строке вопроса, как <li> с hasClick=false. Они информационные, а не действенные.

Вердикт. Не тестовый артефакт — реальному человеку тоже приходится дословно перепечатывать лейбл варианта, чтобы ответить. Мелкий UX-пробел остаётся; маленький тикет «per-option pick button» всё ещё имеет смысл. Не блокирует.

A3 ПОДТВЕРЖДЕНО minor #3 прогона 01 — короткий пресет Defer design

Custom ISO снова замкнулся сквозь всё дерево; минимальный пресет — по-прежнему 30 минут

Проверка. Ask-question shim (q-2026-08-15-002), defer через POST /actions/questions/defer с defer_until = now + 30 с (Custom ISO), ожидание автопереоткрытия, ответ «Left» через API. Общее время удержания ≈73 с.

Тайминг. open → deferred (defer_until t+30с) → авто-reopen на t≈36с → answered. Long-poll шима вернул 200 с hookSpecificOutput.updatedInput.answers = {…: "Left"}. Механика Custom ISO жива и корректна.

Вердикт. Механика в порядке; минимальный пресет — 30 минут. Для «подержи 30 секунд» приходится руками считать ISO. Остаётся мелким пробелом качества жизни.

1 MINOR T6 — клик по варианту в диалоге ответа (без изменений с прогона 01) design

Диалог ответа действительно только free-text для вопросов-вариантов — нет ни радио, ни select, ни кнопок «выбрать вариант»

Живой обход DOM подтвердил: у диалога только textarea + Cancel/Send answer. Лейблы вариантов — статический текст. Владелец обязан дословно перепечатать метку варианта.

Цена оставить как есть. Функциональности не мешает — модель получает ответ, совпадающий с меткой варианта, — но панель не отличает ответ на variant-типовый вопрос от ответа на free-text. Небольшой тикет добавить per-option pick button закроет эту двусмысленность.
