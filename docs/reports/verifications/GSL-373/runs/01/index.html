1 GSL-373 MAJOR /fleet attribution functionality

LIKE-prefix false attribution — heuristic now default, bug now default

The heuristic JOIN in /fleet matches panes by SQL LIKE a.cwd_project_root || '%'. Without a trailing path separator, the pattern matches any pane whose pane_current_path STARTS WITH the cwd string — including unrelated sibling directories. Two projects /repo/foo and /repo/foobar/… collide: LIKE '/repo/foo' || '%' matches /repo/foobar/x.

GSL-359 swapped primacy to make the heuristic the PRIMARY attribution path (previously pidtree was primary and this join only ran as fallback). So a pre-existing correctness bug is now the default — every misattributed row shows up with attribution='heuristic' and a wrong tmux_pane_ref.

Live-verified. Two sessions were seeded in a fake HOME: native at /…/fake-repo and observed-only at /…/fake-repo-sibling. A tmux pane was inserted with pane_current_path=/…/fake-repo-sibling/subdir. /fleet attributed the SAME pane to BOTH sessions — the sibling correctly, and the native session wrongly — with attribution='heuristic' in both cases (evidence file 05-fleet-with-sibling-pane.json).

Fix candidate. Change the JOIN condition to LIKE a.cwd_project_root || '/%' OR add an equality alternate pane_current_path = a.cwd_project_root OR pane_current_path LIKE a.cwd_project_root || '/%'. Small, low-risk, restores the intent ("pane cwd is under session cwd").

4 GSL-373 MINOR chunked rotation invariants functionality

Theoretical starvation: `coldRotationComplete` never flips under sustained cold-list growth

In sessionsCollectorTick, the wrap condition is coldCursor >= cold.length. If the cold list grows by ≥ coldChunkSize() items per tick (e.g. an owner drops 50+ historical transcripts into ~/.claude/projects every 5 s), the cursor advances by chunkSize but cold.length grows just as fast, so the wrap never fires. coldRotationComplete stays false forever, holdFirstSweep stays true forever, and every emitted event is tagged backfill=true indefinitely — the backfill filter on the panel would silently hide live events.

Requires a pathological input (500+ new cold transcripts/second); not observed under normal owner workflows. Test coverage does not exercise a growing cold list — the existing test only checks a static 3-item list. Fix: capture initialColdSize on the first tick and wrap when coldCursor >= initialColdSize, OR flip coldRotationComplete=true once the cursor advances by ≥ initial cold count, whichever comes first.
