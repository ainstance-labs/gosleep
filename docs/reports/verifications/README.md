# Verification runs — стандарт приёмочных отчётов

Как устроен верификационный ран: итеративная приёмка сданного эпика в виде самодостаточного
HTML-дашборда. Введено owner-мандатом 2026-07-23 («скриншоты в ветке» недопустимы),
подтверждено практикой первого рана. Эталонный пример: [`GSL-138/runs/01/`](GSL-138/runs/01/index.html).
По этому README следующий ран собирается без чтения переписки.

## Путь и нумерация

```
docs/reports/verifications/<EPIC-KEY>/runs/NN/
```

`<EPIC-KEY>` — ключ приёмочного эпика (например `GSL-138`), `NN` — номер рана с ведущим нулём
(`01`, `02`, …). Раны **итеративны**: новый ран не переписывает предыдущий, а ложится рядом.
Ран 01 остаётся историческим срезом — по паре соседних ранов видно, что закрылось между ними.

Цикл: **run N → разбор владельцем → фикс-волна (эпик с тикетами) → run N+1.** Открытые находки
рана — вход фикс-волны; итог фикс-волны — вход следующего рана. Находка, не закрытая к run N+1,
обязана снова оказаться в его пунктах со статусом.

## Структура рана

```
runs/NN/
  index.html        дашборд, английский — основной документ рана
  ru/index.html     русская версия того же дашборда
  assets/           styles.css, lightbox.js, скриншоты — всё локально
  design/
    index.html      визуальный обзор дизайн-системы (билингвальный)
    pages/          снапшот проверяемых страниц на момент рана
    assets/, ru/    его собственные ресурсы
```

- **HTML-дашборд EN+RU.** Основной `index.html` — английский; русская версия — `ru/index.html`.
  Не Markdown и не PDF — именно дашборд (рендер — скилл `agentic-report-creator`: светлая и
  тёмная темы, лайтбокс с клавиатурной навигацией).
- **`design/` обязательна.** Снапшот проверяемых страниц (`design/pages/`) плюс визуальный
  обзор дизайн-системы (`design/index.html`: палитры обеих тем живыми свотчами, шкалы
  типографики и отступов, компоненты живым HTML). Исходные страницы изменятся следующей же
  фикс-волной — ран остаётся самодостаточным свидетельством того, что именно принималось.
- **Самодостаточность file://.** Отчёт открывается офлайн двойным кликом: никаких CDN, внешних
  шрифтов и сетевых запросов; CSS и JS лежат рядом в `assets/`. Дубликаты листов внутри рана —
  осознанная цена самодостаточности (вес репозитория проигрывает воспроизводимости).

## Пункты отчёта

- **Нумерованные пункты с Jira-чипами.** Каждая находка — целочисленный пункт; рядом чип с
  ключом заведённого тикета. **Пункт без ключа — не находка**: нечего чинить — нечего и
  нумеровать. Статус каждого пункта — английские константы: LANDED / PARTIAL / NOT-LANDED,
  severity CRITICAL / MAJOR / MINOR (термины не переводятся и в русской версии).
- **Секция «на что обратить внимание»** — обязательна: где смотреть (страницы, темы, ширины)
  и честный список спорных решений рана — того, что верификатор принял сам и что владелец
  может захотеть переиграть.
- Секция гейтов: таблица до/после (smoke, tsc, chronicler, hooks) + команды воспроизведения.

## Скриншоты

**fullPage-«полотна» запрещены.** Только компактные viewport-кадры: **1280×800** и **390×844**,
обе темы (light и dark) для каждой проверяемой страницы. Длинные простыни на всю высоту
документа не принимаются: их нельзя прочитать в лайтбоксе, и они прячут дефекты за масштабом.
Перед затвором проверяется computed background обеих тем (обе стороны переключения:
prefers-color-scheme и `:root[data-theme]`). Именование — `<страница>-<ширина>-<тема>.png`.

Ассеты рана живут **внутри рана** и не дублируются в `docs/dev_history/assets/` (конвенция
GSL-142, см. `docs/dev_history/README.md`). Поток копий односторонний: ран может скопировать
листы к себе ради самодостаточности; из рана наружу ничего не расходится.

## Эталон верификации — три слоя

Ран сверяет сданное с тремя источниками нормы, в этом порядке:

1. **Спека** — дизайн-спека эпика (для UI-редизайна: `docs/design/ui-redesign-spec.md`,
   GSL-112). Числа и токены спеки — первичный эталон; расхождение с ней — находка.
2. **Одобренный снапшот** — `design/pages/` последнего рана, принятого владельцем. Регресс
   против принятого состояния — находка, даже если спека молчит.
3. **Индустриальные нормы** — WCAG-контраст, консистентность токенов, паттерны
   developer-tools-эталонов проекта (Mastra Studio, Supabase). Слой применяется там, где
   молчат первые два.

Конфликт слоёв решается в порядке номеров: спека бьёт снапшот, снапшот бьёт индустриальную
норму; сам конфликт — материал для секции «на что обратить внимание».

## Независимость верификатора

Верификатор читает сданный код и design source — **не** предыдущие отчёты, payload'ы и тикеты
(свежие глаза, без якорения; скилл `verifier-skeptic`). Проверка «доехали ли прошлые фиксы» —
отдельная регрессионная работа поверх пунктов предыдущего рана, не «свежие глаза».
