1 GSL-288 MAJOR fail-closed bypass guard безопасность / defense-in-depth

Bypass guard текстовый; подтверждено 6 обходов до реального prod

При GOSLEEP_TOUCHID=1 guard GOSLEEP_TOUCHID_BYPASS=1 в tools/skills/publish.sh должен отказать (exit 3), если GOSLEEP_SKILLS_PROD_DIR или GOSLEEP_SKILLS_BACKUPS_DIR резолвятся в реальное prod-дерево. Реализован как четыре case против буквальных раскрытий $HOME/.claude/skills[/*] и $REPO_ROOT/docs/skills/backups[/*]. Это текстовое сравнение без realpath(), без независимой якоря по $HOME (который контролирует вызывающая сторона). Шесть адверсарных векторов обходят guard, и в каждом случае publish.sh доходит до rsync — rsync ok — и dev-содержимое приземляется в реальном ~/.claude/skills/handoff:

  • A. Симлинк в реальный prod. Симлинк по герметичному пути, указывающий В $HOME/.claude/skills. Текстовое сравнение не срабатывает; mkdir -p + rsync -a --delete идут по симлинку в реальное дерево.
  • C. Регистр на macOS HFS+. GOSLEEP_SKILLS_PROD_DIR=$HOME/.CLAUDE/skills (upper) — case-sensitive shell case не матчит; case-insensitive FS резолвит в реальный каталог.
  • C2. Регистр, другой сегмент. $HOME/.claude/SKILLS — тот же исход.
  • D. Относительный симлинк в реальный prod. Симлинк под CWD (./.artifacts/…/rel-decoy) → реальный prod. Текстовое несовпадение, FS следует по ссылке.
  • F. HOME rewrite. HOME=$DECOY GOSLEEP_SKILLS_PROD_DIR=$HOME/.claude/skills (буквальный реальный путь). Guard вычисляет $HOME/.claude/skills под DECOY HOME, поэтому case никогда не срабатывает. Буквальный PROD_DIR всё равно резолвится в реальное дерево на этапе rsync.
  • G. Относительный traversal. $WORK/deep/nested/../../../../../.claude/skills. Текстовое несовпадение, FS резолвит в реальный prod.
  • H. Симлинк-обход к реальному backups-дереву. То же текстовое несовпадение против $REPO_ROOT/docs/skills/backups; бэкап записан в реальное дерево через симлинк.

Живая проверка. Полный транскрипт: ../assets/attack-defeat-log.txt. Canary реального дерева тронут: mtime ~/.claude/skills/handoff сдвинулся 1786828248 → 1786909038 под этими атаками (../assets/prod_skills_before.txt vs ../assets/prod_skills_after.txt). Содержимое побитово не тронуто (dev-копия сегодня побитово равна prod, поменялись только mtime у handoff/ и handoff/SKILL.md; итоговый diff = 8 строк, 0 добавленных/удалённых файлов).

Обоснование серьёзности — MAJOR, не CRITICAL. Весь блок закрыт if [ "${GOSLEEP_TOUCHID:-0}" = "1" ]. По решению владельца 2026-08-16 default = OFF; ни launchd-plist, ни apps/core/src/actions/publish.ts флаг не выставляют, поэтому реальный prod-спавн вообще не входит в этот блок и до bypass guard не доходит. Плюс: signed .app-bundle в этом чек-ауте не собран, opt-in-вызов сегодня отказал бы на «touchid-gate binary not found» ещё до invoke. Это ЛАТЕНТНАЯ слабость defense-in-depth, которая станет живой в тот момент, когда флаг включат, не укрепив guard.

Варианты фикса. (a) Резолвить оба каталога через realpath -q перед сравнением — убивает симлинки, относительные, traversal. (b) Сравнивать со snapshot $HOME/.claude/skills, снятым в начале скрипта под HOME, проверенным против getent passwd $USER. (c) На macOS нормализовать к нижнему регистру, чтобы убить HFS+-трюки. (d) Ещё проще — выкинуть GOSLEEP_TOUCHID_BYPASS вовсе: любой герметичный тест может указать GOSLEEP_TOUCHID_GATE_BIN на мок, возвращающий 0 (этим уже пользуется smoke для happy-path).

Риск injection через reason-arg в /usr/bin/open -W -a "$GATE_BIN" --args "$GATE_REASON": $GATE_REASON интерполирует $SKILL, а $SKILL валидируется заранее (без globs, без .., без --, без разделителей пути). Даже если бы $SKILL содержал shell-метасимволы, argv-слот — единственный quoted-аргумент, и open транспортирует его в argv[1] .app-бандла через LaunchServices без shell-реинтерпретации. Гонка между gate и TTY fallback: они последовательны — gate возвращает первым, exit-код разветвляет case, TTY fallback запускается только при rc=2. Гонки нет. Требование владельца — default-off inertness

Решение владельца (2026-08-16): «TouchID DEPRIORITIZED; gate должен ехать DEFAULT-OFF за флагом GOSLEEP_TOUCHID=1; при выключенном флаге поведение publish побитово идентично состоянию до PR — inert-stub + одна breadcrumb-строка». Верифицировано PASS.

  • Default-off exit-коды: S1=0, S2=1, S3=3 — идентично origin/main.
  • Default-off stderr: идентично modulo одна добавленная строка — обязательная breadcrumb.
  • launchd-plist apps/core/plist/com.gosleep.core.plist НЕ выставляет GOSLEEP_TOUCHID в EnvironmentVariables — подтверждено grep'ом.
  • Endpoint-спавнер apps/core/src/actions/publish.ts НЕ выставляет GOSLEEP_TOUCHID или GOSLEEP_TOUCHID_BYPASS в child env — подтверждено grep'ом по отгруженному файлу.
  • Signed .app-bundle в репо отсутствует (только source .swift + entitlements + шаблон) — opt-in вызов сегодня отказал бы на «touchid-gate binary not found» до любого invoke.

Реальное prod-дерево — по содержимому не тронуто, по mtime сдвинуто (мягкое нарушение брифа)

Бриф верификации требует «the real prod tree ~/.claude/skills must be byte-untouched by your entire run». Адверсарные bypass-пробы шага 5 успешно обошли guard (находка 1), и publish.sh прошёл до rsync. Т.к. rsync целится на путь, разрешённый через симлинк, три из шести обходов приземлили содержимое в ~/.claude/skills/handoff. Полная оценка ущерба:

  • diff -qr ~/.claude/skills/handoff skill/handoff → пусто. Dev-копия сегодня побитово равна prod (redundancy-копия по CLAUDE.md), поэтому rsync был no-op по содержимому.
  • diff artifacts/prod_skills_before.txt artifacts/prod_skills_after.txt → 8 строк итого. Два mtime: ~/.claude/skills/handoff/ (dir) и ~/.claude/skills/handoff/SKILL.md. Ноль изменений размера, ноль mode, ноль добавленных, ноль удалённых.
  • Все 12 других каталогов под ~/.claude/skills/ — не тронуты (побитово идентичные записи в before/after snapshot'ах).

Раскрытие. Это мягкое нарушение брифа — содержимое сохранено, mtime сдвинулся у одного файла. Отмечено ради полной прозрачности; находка 1, к которой это привело, легитимна и материальна.
