1 GSL-288 MAJOR fail-closed bypass guard security / defense-in-depth

Bypass guard is text-only; 6 defeats verified end-to-end against real prod paths

Under GOSLEEP_TOUCHID=1, the GOSLEEP_TOUCHID_BYPASS=1 guard in tools/skills/publish.sh is supposed to refuse (exit 3) whenever GOSLEEP_SKILLS_PROD_DIR or GOSLEEP_SKILLS_BACKUPS_DIR resolve into the real production tree. The guard is implemented as four case statements against the literal expansions of $HOME/.claude/skills[/*] and $REPO_ROOT/docs/skills/backups[/*]. That is a textual match with no realpath() normalization and no anchoring separate from the caller-controlled $HOME. Six adversarial vectors bypass the guard, and in each case publish.sh proceeds through the rsync — rsync ok — landing dev content in the real ~/.claude/skills/handoff tree:

  • A. Symlink into real prod. A symlink at a hermetic path pointing INTO $HOME/.claude/skills. Textual match fails; mkdir -p + rsync -a --delete follow the link into the real tree.
  • C. Case trick on macOS HFS+. GOSLEEP_SKILLS_PROD_DIR=$HOME/.CLAUDE/skills (uppercase) — case-sensitive shell case matches nothing; the case-insensitive filesystem resolves it to the real dir.
  • C2. Case trick, other segment. $HOME/.claude/SKILLS — same outcome.
  • D. Relative-path symlink to real prod. A symlink under CWD (e.g. ./.artifacts/…/rel-decoy) → real prod. Textual mismatch, filesystem follows.
  • F. HOME rewrite. HOME=$DECOY GOSLEEP_SKILLS_PROD_DIR=$HOME/.claude/skills (literal real path). The guard evaluates $HOME/.claude/skills under the DECOY HOME, so the case never fires. The literal PROD_DIR still resolves to the real tree at rsync time.
  • G. Relative traversal. $WORK/deep/nested/../../../../../.claude/skills. Textual mismatch, filesystem resolves to real prod.
  • H. Backups symlink to real backups tree. Same textual mismatch against $REPO_ROOT/docs/skills/backups; backup written to the real tree via the symlink.

Severity rationale — MAJOR, not CRITICAL. The entire block is guarded by if [ "${GOSLEEP_TOUCHID:-0}" = "1" ]. Under the owner ruling of 2026-08-16 the default is OFF; neither the launchd plist nor apps/core/src/actions/publish.ts sets the flag, so a real production spawn skips this block entirely and never reaches the bypass guard. On top of that, the .app bundle is not built in this checkout, so an opt-in call today would refuse with "touchid-gate binary not found" before invoking anything. This is a LATENT defense-in-depth weakness that becomes live the moment the flag flips ON without hardening the guard.

Fix candidates. (a) Resolve both dirs with realpath -q before comparison — kills symlinks, relatives, traversal. (b) Compare against a snapshot of $HOME/.claude/skills captured at script start under a locked $HOME that is verified equal to getent passwd $USER's home. (c) On macOS, normalize to lowercase before comparison to defeat HFS+ case tricks. (d) Simpler still: drop GOSLEEP_TOUCHID_BYPASS altogether — every hermetic test can point GOSLEEP_TOUCHID_GATE_BIN at a mock that returns 0, which the smoke already uses for the happy-path.
