1 GSL-156 MAJOR Self-health cards (Overview) design NOT-LANDED

Unscoped .unknown cascade paints whole self-health cards in status magenta

The rule .unknown{color:var(--unk);cursor:help} is not scoped to an element, while the unknown class is carried by whole containers: class="card sh-m unknown" (selfhealth.tsx meterClass). Inside the Freshness card the heading .sh-h, the value <b id="sh-data-age"> and the .sh-row text have no colour of their own and inherit magenta, and the entire card gets cursor:help.

Measured live (index.html, both themes): heading «Freshness — two ages, not one» = rgb(142,77,157) (--unk); the value «8h 17m» — a READ value, not a missing one — is also magenta. This breaks the redesign's rule 2 («colour is earned by judgement only; prose is neutral») and theme.ts's own .sh-m comment: «The state lives on the LEFT EDGE of the card, not in the ink of its prose». GSL-146 closed the sibling cascade (label rules swallowing span.unknown) but left the container ink and cursor untouched. .clock.unknown survives only because every child happens to be repainted by its own rule.

2 GSL-157 MAJOR Freshness meter (Overview) functionality NOT-LANDED

Freshness meter encodes grade=dead as the unknown state

selfhealth.tsx:47 projects the data grade with a ternary that has no dead branch: fresh → ok, stale → gaps, anything else → unknown. On the committed build (data age 8h 17m > the 3h dead threshold) the page shows a red DEAD banner at the top — and two blocks below it the Freshness card wears card sh-m unknown, the magenta «cannot read the reading» state.

The reading IS read: 8h 17m is known, the dead verdict is computed. «dead» and «unknown» are the project's central semantic axis (spec 4.3, the GSL-109 lesson; the Unknown component's whole docstring), and the card mis-encodes a known-bad state as an unreadable one — in the reassuring direction. METER_CLASS has no dead entry at all; meterClass emits dead only for the handoff alarm, so the red .sh-m.dead treatment is unreachable for Freshness.

4 GSL-159 MINOR Runway (Overview) design NOT-LANDED

runway-bind badge in the clear state is half-painted: ok ink over a neutral shell

At r.bound === "clear" the runway renders <span class="runway-bind ok">nothing is going to stop the night</span>. .runway-bind sets the neutral triple (soft bg, neutral border, neutral ink); span.ok (specificity 0,1,1) overrides only the colour. Result: green text on a neutral shell — a hybrid that matches neither the badge shape of spec 7.1 (one role = one bg/ink/border triple) nor 8.1 («the badge beside the value carries the grade»). theme.ts itself defines span.ok for «inline spans inside a sentence», explicitly not for badges.

LATENT: the committed bundle is bound=unknown, so the state is not visible today; the screenshot shows the same shell in its current neutral state. clear is the target good state of the whole dashboard and is reachable any healthy night.
