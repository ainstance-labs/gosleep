2 GSL-228 MINOR Tier-2 floor: секреты correctness

Tier-2 secrets: фраза `leak the token` не ловится

В шаблоне secrets глаголы rotate, share, publish, commit, expose разрешают опциональный the, а leak(ed) — нет. Итог: leak the token, leak my token, leak this token принимаются как DECISION и получают дефолт-таймер 2h. Воспроизведено: question --type DECISION --question 'leak the token' --default no --reversibility high → q-…. Правка: симметричный \bleak(?:ed)?\s+(?:the\s+)?…. Комментарий кода (стр. 111) говорит «false positive — сужай, не расширяй»; здесь обратный случай (false NEGATIVE), правка = расширение.

3 GSL-228 MINOR Tier-2 floor: секреты correctness

Tier-2 `rotate` обходится, если между `the` и «ключом» есть квалификатор

Шаблон \brotate\s+(?:the\s+)?(секрет|токен|api-ключ|key)\b требует, чтобы секрет-слово шло сразу после rotate или rotate the — без слов между. Естественные фразы rotate the AWS key, rotate the master key, rotate our api key, rotate my token НЕ ловятся. Проверено: rotate the AWS key принят как DECISION. Существующий тест rotate the api key проходит только потому, что api key совпадает с ветвью api[- ]?key. Правка: разрешить 1–2 слова между ((?:\S+\s+){0,2}) или расширить группу квалификаторов.

4 GSL-228 MINOR Tier-2 floor: внешние коммуникации correctness

`post on social media`, `tweet the launch`, `email the team` обходят external-comms

Шаблон external_comms требует связки глагол+существительное из фиксированного списка. Естественные внешние коммуникации post on social media, tweet about the launch, email the team about status принимаются, потому что social, media, team, launch не входят в якорный список. Заявление «money/comms/secrets/destructive → BLOCKER by code» на практике мягче, чем звучит. Предложение: добавить team, channel, social media, slack, twitter/x, linkedin или ввести двухступенчатую проверку (глагол один → CLARIFY; глагол+сильное существительное → BLOCKER).

5 GSL-229 MINOR Схлопывание qshape correctness

qshape false-merge: `not` — стоп-слово, `merge PR` ≡ `NOT merge PR`

Список QSHAPE_STOPWORDS содержит not, а токены ≤2 символов отбрасываются (→ PR теряется). Прямой тест: qshape('should we merge PR') == qshape('should we NOT merge PR') (обе фразы сводятся к merg). Также bump to v2 ≡ bump to v3. Цикл candidates группирует по (qshape, decision.lower); при N≥3 такие пары «одинаковых форм с противоположными решениями» «слипнутся» в один манифест-кандидат. Влияние ограничено: candidates — ADVISORY (комментарий строка 362 — манифест правится владельцем), автоматическая установка правила невозможна. Но семантический риск реален — отрицание не filler-слово. Правка: убрать not из стоп-слов или инвертировать знак токена (ˆmerg), чтобы противоположности не сливались.

6 GSL-227 MINOR Валидация rule correctness

`delegation:` принимает будущие даты, кривые даты и неизвестные origins

Правило --rule delegation:<origin> <date> принимается, если после префикса есть что-то похожее на дату — allowlist origins и валидность/прошлое даты не проверяются. Воспроизведено: delegation:owner 2099-12-31 → OK, delegation:owner 20260816 → OK (кривая дата), delegation:noname 2026-08-16 → OK (неизвестный origin), delegation: owner 2026-08-16 → OK (пробел после :). Гарантия provenance для автономных решений ослаблена. Правка: ^delegation:(owner|orchestrator)\s+\d{4}-\d{2}-\d{2}$ плюс проверка «дата в прошлом или сегодня».

7 GSL-230 MINOR Подкоманда park design

`park` принимает прошедший `--wake-at` — reopener сразу же откроет запись

Команда park --re <id> --wake-at 2020-01-01T00:00:00Z проходит и пишет deferred-патч с defer_until=2020-01-01T00:00:00Z. Любой reopener сверяет defer_until <= now и сразу же откроет запись на следующем тике — смысл «парковки» теряется. Стоит отклонять wake-at <= now + <мин-окно> (минуты/часы). Кривые / без-Z / не-UTC даты отклоняются корректно — здесь всё хорошо.
