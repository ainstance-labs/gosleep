GSL-375 корректность purge

Разбор purgeMissingTranscripts в apps/core/src/observed/sessions.ts. Тесты test/observed.sessions.test.ts — 14 / 14 pass (82 expects). Ручной аудит на row-resurrection race:

  • Нативные строки неприкосновенны — SELECT ... WHERE observed_only = 1; нативные строки (observed_only=0) вообще не посещаются.
  • Бюджет соблюдается — PURGE_BUDGET_PER_TICK = 32; mass-delete-тест за 2 тика вычищает 35 строк ровно как 32+3.
  • Belt-and-braces re-check — даже если tick-снапшот кандидатов говорит «нет», перед DELETE прогоняется existsSync по ~/.claude/projects/*/<sid>.jsonl; тест vanish-mid-rotation это доказывает (растёт skipped_still_exists).
  • session_ended срабатывает ровно один раз — эмитится ДО DELETE; если writer observed-events отверг append, DELETE пропускается (continue) — silent-purge исключён. Следующий тик уже не увидит строку, повторного эмита нет.
  • Boot-race закрыт — purge выполняется только когда coldRotationComplete === true, boot backfill (пока cold-кандидаты довыгружаются по чанкам) не может false-purge'нуть строку до fold'а её транскрипта.
  • Row-resurrection race при нормальной работе отсутствует — цикл tick на коллектор последовательный (один interval); vanish, замеченный на tick N+1, вычищается purge'ом того же N+1.

Заметки по архитектуре — взгляд верификатора

Слоёная защита в GSL-385 — realpath + инод-идентичность + case-fold + пере-якорение HOME/repo

Fail-closed-проверка guard'а делает ЧЕТЫРЕ пересекающихся сравнения на каждую bypass-поверхность: (a) равенство текста lowercased-физических путей, (b) префиксный матч по lowercased-физическим путям, (c) обход по инодам от override'а вверх до якоря, (d) HOME/REPO_ROOT перечитываются из OS-authoritative источников (dscl на Darwin, getent на Linux). Срабатывание ЛЮБОГО из этих слоёв — bypass отклонён.

Повторная adversarial-атака (6 старых + 6 новых классов выше) показывает: сегодня на macOS обходных путей через этот стек нет. Остаточная поверхность атаки — сами anchor-override переменные окружения, что закрывается «Находкой 1» как defense-in-depth-рекомендация.

GSL-386 shim peek — дешёвая защита от будущего silent-miss

До GSL-386 peek был head -c 4096 | sed -n -E 's/.*"session_id":"([^"]+)".*/\1/p'. Существовало ДВЕ поверхности silent-failure: (1) Claude Code раздувает преамбулу и sid уходит за 4 KiB (silent miss → opted-in-сессия падает в TUI), (2) жадный квантификатор sed'а ловит ПОСЛЕДНЕЕ вхождение в окне peek (сегодня безопасно, потому что "session_id" внутри tool_input-строк JSON-эскейпится в \"session_id\", но это одно изменение препроцессинга от silent-corruption).

Пара «64 KiB cap + awk match()+exit» стоит ~+0-10% wall-clock против жадного sed-пайплайна (по бенчу автора) — гораздо меньше, чем стоит fallback в TUI, и на порядок меньше ~4× стоимости альтернативы grep|sed|head. Хорошо оформленное upfront-исправление.

GSL-375 purge — bounded, gated, идемпотентный

Purge посещает максимум PURGE_BUDGET_PER_TICK = 32 строк за тик, только observed-only-строки, только после coldRotationComplete = true. Перед каждым DELETE идут (1) проверка членства в candidate-set, (2) re-check existsSync по ~/.claude/projects/*/<sid>.jsonl, (3) успешный appendObservedEvent({kind:"session_ended"}). Если что-то из этого отказывает — DELETE пропускается. Row-resurrection race ограничен лагом в один тик, который коллектор естественно обрабатывает на следующем проходе. Аккуратно и дёшево.
