Layered defense on GSL-385 — realpath + inode-identity + case-fold + HOME/repo re-anchor

The guard's fail-closed check runs FOUR overlapping comparisons per bypass surface: (a) text equality on lowercased physical paths, (b) prefix match on lowercased physical paths, (c) inode walk from the override up to the anchor, and (d) HOME/REPO_ROOT re-derived from OS-authoritative sources (dscl on Darwin, getent on Linux). Adversarial re-testing (6 old + 6 new defeats above) shows no path around this stack on macOS today. The residual attack surface is the anchor-override env-vars themselves — covered by Finding 1 as a defense-in-depth suggestion.

GSL-386 shim peek — cheap protection against a future silent-miss

The pre-GSL-386 peek used head -c 4096 | sed -n -E 's/.*"session_id":"([^"]+)".*/\1/p'. Two silent-failure surfaces existed: (1) Claude Code preamble growth pushing the sid past 4 KiB (silent miss → opted-in session falls back to TUI), and (2) sed's greedy quantifier matching the LAST occurrence in the peek window (would misfire only if an unescaped "session_id":"..." appears inside tool_input — today safe, but one preprocessing change away from silent corruption).

The 64 KiB cap + awk match()+exit pair costs ~+0-10% wall-clock vs the greedy-sed pipeline (per implementer's bench) — much less than a fallback to the TUI would cost, and dramatically less than the ~4× cost of a grep|sed|head alternative. Well-shaped preemptive fix.

GSL-375 purge — bounded, gated, idempotent

The purge visits at most PURGE_BUDGET_PER_TICK = 32 rows per tick, only observed-only rows, only after coldRotationComplete = true. Every DELETE is preceded by (1) a candidate-set membership check, (2) an existsSync re-check against ~/.claude/projects/*/<sid>.jsonl, and (3) a successful appendObservedEvent({kind:"session_ended"}). If any of those refuses, the DELETE is skipped. The row-resurrection race is bounded to one tick's lag, which the collector handles naturally on the next pass. Well-scoped and cheap.
