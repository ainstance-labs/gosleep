6 · Findings

Critical (0)

None. The safety invariant holds architecturally and empirically.

Medium (1)

M1 — publish.sh half-published state when DB unmigrated. MEDIUM

If publish.sh runs against a GOSLEEP_DB_PATH that does not yet have the skills table (fresh clone, corrupted DB, migration skipped), the sequence is:

  1. verify-local passes
  2. backup written
  3. rsync completes → ~/.claude/skills/<name>/ is updated in production
  4. CHANGELOG.jsonl append succeeds → orphaned "published" row lives in JSONL
  5. fold-to-DB fails with no such table: skills → publish.sh exits rc=1

Net effect: filesystem + JSONL are ahead of the DB; the endpoint returns 500 to the caller; the CLI operator sees "publish.sh FAILED to append CHANGELOG row — the rsync ALREADY LANDED" (which is truthful about the rsync but misleading about the JSONL, which did append). Reproduced in the hermetic sandbox (see live-proof #8, first attempt). In production the launchd-managed core migrates the DB at boot, so this is a theoretical concern; still worth a runbook note that publish.sh in isolation requires a migrated DB, and worth guarding record-publish.ts to skip the fold gracefully (or run migrations) when the table is missing.

Minor (3)

m1 — publish.sh has no idempotency at the CLI layer. MINOR

Re-invoking with the same --intent-id appends another row every time. This is by design — the endpoint (withTimeline) is where Idempotency-Key is enforced. Confirmed empirically: 3rd sandbox publish appended a 3rd row despite reusing intent_id. A future runbook note should warn direct-CLI operators not to re-run manually; the T10 test-guard's intent_id correlation logic could also duplicate-detect at end-of-run.

m2 — Skills.tsx submitPublish is defined but only referenced from a hidden span. MINOR

Lines 68-89 define submitPublish and call the mutation. Lines 182-185 keep it alive with a hidden <span>{typeof submitPublish}</span> so tsc doesn't strip it. When TouchID lifts, the wire-up is not a one-line disabled={false} flip — the Publish button also needs onClick={() => submitPublish(row)}. Worth naming in GSL-266's acceptance so an implementer does not miss it and ship a still-non-functional button.

m3 — Content edits (GSL-186, GSL-189) landed on safe copies as required. RESOLVED / RE-CONFIRMED
