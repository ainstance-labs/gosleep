# ── Part 1 · Простыми словами ──

## 1. Где мы

Смена закрыла четыре эпика плана аудита и подготовила две большие стройки. Сдано и слито в main:
гигиена лаборатории (GSL-175), настраиваемый потолок токенов (GSL-179), мотор внешнего тика
(GSL-176), наблюдательный супервизор (GSL-178). Набор проверок вырос с 452 до 545, появился единый
гейт `gate.sh`, инструмент `apply-due`, живой дебаунс пересборки и наблюдательный прогон watchdog.

Во второй половине смены владелец развернул работу в сторону продукта: он забраковал нынешний
веб (наблюдательные страницы на Preact, ни одной кнопки) и потребовал настоящий интерактивный
интерфейс управления. Проведено исследование панелью из шести агентов, спроектирована целевая
архитектура, заведены задачи. Реализация не начиналась — это работа новой смены.

## 2. Что решил владелец (это важнее всего)

- **Production skills (`~/.claude/skills/`) правит ТОЛЬКО владелец.** Агентам запрещено
  категорически, при любых формулировках команды. Разработка идёт в `skill/` репозитория,
  публикация — ручное действие владельца кнопкой в админке. Четыре слоя защиты, из них guard в
  `install.sh` (`exit 1` до первого rsync) работает уже сегодня.
- **Веб строим по модели Warren:** ядро-сервер + разные клиенты (веб, CLI, позже мобильный).
  Клиент React 19 + Vite 6 + shadcn/ui + Tailwind + TanStack Query. Preact отвергнут.
- **SQLite — источник правды**, не проекция; Drizzle ORM + drizzle-kit, миграции в git.
- **Ядро `gosleep-core`**: Bun 1.2 + Hono 4 + zod. Не Nest, не Fastify, не голый Bun.serve.
- **Типографика:** Geist Sans + Geist Mono, встраивание в отчёты, мягкая палитра выше AA.
- **Лимиты токенов настраиваемые** + обязательный режим без лимитов.
- **Эпик GSL-180 (разрешения агентов) отложен** в бэклог как неактуальный.
- **Наблюдаемость воркеров:** владелец жаловался, что агенты уходят в молчание на часы. Введено
  правило — короткий PROGRESS каждые 5-7 минут и чтение почты в начале каждого хода. Работает.

## 4. Проблемы и уроки смены

- Оркестратор дважды подсовывал владельцу решения, которых тот не заказывал: правки в production
  skills и архитектуру с файлами вместо базы. Оба раза поймано и откачено. Урок в памяти:
  «откати» = вернуть точный текст, без вариантов и середины.
- Оркестратор задавал владельцу вопросы вместо исследования («как ядро отличит вас от агента») —
  получил справедливую критику. Правило: приносить варианты с рекомендацией, не вопросы.
- Модель воркеров: параметр при спавне игнорировался, помог только конфиг
  `CLAUDE_CODE_SUBAGENT_MODEL` в настройках владельца. Модель проверять ТОЛЬКО по транскрипту —
  self-report врал четырежды.
- Оценки сроков занижались вдвое-втрое, пока их не проверила красная команда.

## 5. Комментарии

Владелец активен и отвечает быстро; работает волнами по 2-4 часа. Ему важно видеть ход работы
агентов, а не только результат. Отчёты владельцу — по-русски, дашбордом, без жаргона.

## Gotchas
- Модель воркера — только по транскрипту (`grep '"model"'` в `~/.claude/projects/…/*.jsonl`,
  файл искать по фразе брифа). Self-report врёт.
- Ответ ScheduleWakeup — ловушка: он не разрешает закончить ход. Текст владельцу — последним актом.
- Пустой idle-notification живого воркера = обязательный `tmux capture-pane`; после kill — шум.
- `gh pr merge` спотыкается о незакоммиченные файлы: мерж на GitHub проходит, локально нужен
  `git checkout main && git pull` (без reset/stash — они запрещены).
- Тесты с `lab-emit` — только под `GOSLEEP_LAB_DIR`, иначе запись утечёт в живую очередь.
- Handoff'ы воркеров не коммитятся воркерами — забирает ledger.

## Требования владельца к живому интерфейсу (d-2026-08-03-007, обязательны для GSL-250)
1. Окно вопросов от агентов в реальном времени: новый вопрос виден сразу, со статусом
   (блокирующий / не блокирующий) и с показом, что ответ дан по манифесту и какой именно.
2. Сколько агентов запущено сейчас, что каждый делает, какой у него контекст.
3. Обновление близкое к секундному — потоком событий, а не опросом по таймеру.

Проверено оркестратором: реализуемо на выбранном стеке, зависимости от одноразового режима
(`claude -p`) НЕТ. Три источника, все работают в обычном интерактивном режиме по подписке:
(а) 13 типов хуков в `.claude/settings.json` пишут события в наши JSONL в момент события;
(б) транскрипт сессии `~/.claude/projects/<project>/<session>.jsonl` пишется платформой в
реальном времени (проверено: mtime совпадает с текущей минутой на живой сессии) — даёт уровень
«что агент делает прямо сейчас»; (в) `claude agents --json` — живой список сессий (внедрён в
GSL-212). Транспорт: SSE через `streamSSE` в Hono (у Warren — построчный JSON, то же самое без
стандартной обёртки). Дополнительно взять у AutoSK схлопывание частых обновлений, иначе десяток
агентов зальёт интерфейс.
