Проект gosleep существует ради ОДНОЙ большой цели: построить самую сильную автономную систему оркестрации AI-агентов, чтобы владелец мог «идти спать» (GoSleep), а система продолжала доставлять работу сама — принимая решения за него по манифесту, буферизуя вопросы, авто-генерируя всю документацию и показывая всё в веб-лаборатории с мобильным доступом.

## 4. Твоя ПЕРВАЯ задача — глобальный аудит

Проведи холистический аудит всей системы оркестрации против исходного промпта — «мощной системой архитекторов и экспертов» (многоагентная панель). Цель: понять, где мы РЕАЛЬНО против мандата, что устарело, что недоделано, и составить приоритизированный план улучшений.

**Возможные измерения аудита** (уточни сам, это стартовый список):
1. **Свежесть research**: autosk/warren/overstory могли эволюционировать с 2026-07-10 — перечитать заново (репозитории + autosk.app). Что нового переняли конкуренты?
2. **Проблема супервизии**: watchdog (GSL-53) достаточен? Нужен ли LLM-координатор уровнем выше, и можно ли его сделать БЕЗ `claude -p` (или с ним по подписке)?
3. **Подписка vs `claude -p`**: наша адаптация прочна? Что сломается, если Anthropic запретит `-p`?
4. **Зрелость автономности**: буфер вопросов + манифест + learning loop реально работают end-to-end без человека ночью? KPI промпта — «вопросов-за-ночь → 0 для повторяющихся форм».
5. **Полнота Лаборатории**: handoff/dev_history/reports правда авто-генерируются, или человек всё ещё пишет «создай handoff»? (Промпт хочет ПОЛНУЮ автоматизацию.)
6. **UI/UX**: индикаторы автономности, окно вопросов по типам, статусы задач — реализованы и хороши? Сверить с autonomy-lab-ui отчётом.
7. **Loop engineering**: используем ли новейшие паттерны?
8. **Mobile**: удалённая оркестрация с телефона реально работает?

**Ограничения (HARD, не нарушать даже ради «мощной панели»):**
- ⛔ **NO Workflow tool** (standing rule владельца) — многоагентность только через tmux-teammates.
- **Fleet cap 3** — одновременно максимум 3 воркера. «Мощную панель экспертов» реализуй ПОСЛЕДОВАТЕЛЬНЫМИ волнами по ≤3 (например: волна 1 — 3 доменных аудитора → волна 2 — ещё 3 → синтез-агент), НЕ массовым спавном. Если считаешь, что аудит требует снятия Workflow-бана — это DECISION к владельцу с дефолтом «последовательные волны», не решай молча в пользу Workflow.
- **Модели по сложности** (owner 2026-07-23): архитектура/экспертный анализ/дизайн → **Fable 5** (model: fable); механика (setup/finalize/регрессия) → **Opus 4.8** (model: opus). Модель каждого воркера сверять по транскрипту (по фразе брифа, не по mtime).
